### 0.6 编译器自身源码的编码规范

Serica 编译器用它自己写，所以这些规范就是「Serica 代码怎么写」的范本。

| 项 | 规定 |
|---|---|
| 文件行数 | ≤ 400 行（后端可到 600，需决策记录） |
| 函数行数 | ≤ 60 行 |
| 函数参数 | ≤ 5 个，超过用记录打包 |
| 嵌套 | ≤ 2 层容器段 |
| 命名 | 汉字语义名，不用缩写：`词法分析` 而非 `lex`；`符号表` 而非 `symtab` |
| 禁止 | 全局可变状态；跨篇访问超过 2 层；单个 `规则：` 段超过 30 句 |
| 必须 | 每个公开函数有 `例：` 段，至少 1 正例 1 反例 |
| 注释 | 只写「为什么」，不写「做什么」；`（…）` 内一句一义 |
| 导入 | 显式列出，禁止通配 |

### 0.7 本手册的权威性

- 规格冲突时，**第 1 章 > 第 2–5 章 > 第 6–12 章**
- 实现与规格冲突时，**以规格为准**，实现方报 `DRIFT`，不擅自改规格
- 规格变更必须走决策记录（12.3 模板），人签字后才生效
- 模型不得自行解释词表外写法；表外即报错

## 1. 语言规格（地基）

### 1.1 五条设计原则

1. **一符一职，一词一义**：符号与词各只有一个职责，无同义词、无兼职。
2. **段是唯一块结构**：冒号开段，容器段以 `段结束。` 收；无花括号、不依赖缩进。
3. **零空格、顶格**：词边界由虚词与全角标点决定；空行只分段，不入语法。
4. **双层同语言**：文章层面向应用，系统层面向内核。共享类型系统、IR、后端，**不是两门语言**。
5. **嵌套 ≤ 3 层容器段**：超过必须抽函数。这是可读性上限，不是能力上限。

### 1.2 符号表（13 类，封版）

| # | 符号 | 唯一职责 | 例 |
|---|---|---|---|
| 1 | `《》` | 篇名；跨篇访问前缀 | `《内核》`、`《数学》的平方【3】` |
| 2 | `：` | 段标签终止；构造/调用的字段分隔 | `规则：`、`学生【姓名：「张三」】` |
| 3 | `。` | 句终，一行一句 | `总分记为0。` |
| 4 | `；` | 条件句两分支分界 | `…；否则，…。` |
| 5 | `，` | 条件引导；分支内多句分隔 | `如果甲大于1，…` |
| 6 | `、` | 并列项列举 | `输入：甲、乙。` |
| 7 | `「」` | 文本字面量；内部符号按字面处理 | `「优秀」` |
| 8 | `『』` | 含 `」` 的文本，用于转义 | `『他说「好」』` |
| 9 | `【】` | 调用、构造、内置操作 | `求积【甲、乙】`、`列表【1、2】` |
| 10 | `（）` | 注释，不参与求值 | `（此处说明。）` |
| 11 | `〈〉` | 类型标注、类型参数、容量参数 | `甲〈整数〉`、`通用〈甲型〉`、`管道〈10〉` |
| 12 | `．` | 小数点（全角，别于句号） | `3．14` |
| 13 | `0-9` | 数字字面量、索引 | `270`、`第1项` |

#### 1.2.1 半角规则

- 只允许 `0-9` 与数字内部的小数点 `.`。其余半角字符（`, : ; ( ) [ ] { } " ' ! ? = + - * / < > & | # @ $ % ^ ~ \`）一律判错。
- `3.14` 与 `3．14` 等价，格式化器统一输出 `3．14`。
- 半角空格判错。缩进（行首空白）判错。

#### 1.2.2 符号冲突与转义

| 场景 | 规则 |
|---|---|
| 文本内需要 `」` | 用 `『…』` 包裹，内部 `「」` 成为字面字符 |
| 文本内需要 `』` | `『』` 无法表达。用字符拼接：`「他说」连接文本化【字符【12303】】`（`12303` 是 `』` 的 Unicode 标量值，见 1.8.1.1） |
| 注释内需要 `）` | 不允许。注释里不写右括号，用两句注释 |
| 注释内需要 `。` | 允许，注释内句号只是文字 |
| 汇编段内任意字符 | 允许。汇编段内容原样输出，不做词法检查（见 1.16.4） |

> **`（）` 为什么不能兼职表达式括号**：注释与分组同符号会让「这是注释还是表达式」无法在词法层判定。Serica 用「复合表达式必须拆句」（1.9.6）替代括号，代价是写不出 `（甲加上乙）乘以丙`，收益是零歧义、零符号膨胀。

### 1.3 词表（封版，115 条目 / 112 词形 + 1 收束标记）

>
> 逐组相加：28 + 15 + 6 + 16 + 6 + 8 + 4 + 3 + 7 + 12 + 10 = **115 条目**。

#### 1.3.12 词表硬约束

1. **标识符不得等于词表词**，也不得包含词表词作为连续子串。因为分词器会在任意位置优先匹配词表词，`记为值` 必然被切成 `记为` + `值`。
2. **标识符不得等于内置名**（1.21），也不得包含内置名作为连续子串。
3. **内置名可以含词表词**——这是唯一被允许的「词表词出现在更长的名字里」的场合，因为内置名在词法层优先匹配（1.4.1 第 5.a 步）。`文本化`、`随机整数`、`读取文本` 都属此类。
4. **文本字面量内部不受约束**：`「如果记为等于」` 合法。
5. **注释内部不受约束**：`（这里说如果等于也可以。）` 合法。
6. **篇名不受约束**：`《如果》` 合法，但引用时要写 `《如果》的甲`，不产生歧义（`《》` 是硬边界）。

### 1.4 词法规则

#### 1.4.1 分词算法（模型必须照此实现）

单遍扫描，从左到右，每个位置执行：

```
1. 若是空白（半角空格/Tab）→ 报错「出现空格」。
2. 若是换行 → 输出「换行」token（仅用于行号统计与诊断，不参与语法）。
3. 若是全角标点 → 输出对应符号 token。
4. 若是 ASCII 数字 → 累积连续数字与至多一个小数点 → 数字 token。
5. 否则（汉字或 `_`）→ 进入标识符/词匹配，两级优先：
   a. 先在「内置名表」里取最长命中（≤8 汉字）。命中 → 输出内置名 token，前移。
   b. 再在「词表」里取最长命中。命中 → 输出词 token，前移词长。
   c. 都未命中 → 把当前一个汉字并入标识符缓冲，位置前移 1。
   d. 标识符缓冲非空且下一步命中内置名或词表词 → 先输出标识符 token，再处理。
6. 文件结束 → 输出标识符缓冲（若非空）→ EOF。
```

**为什么需要第 5.a 步（内置名表优先）**：

标准库与内置操作里有若干名字天然含有词表词——`文本化` 含 `文本`、`读取文本` 含 `文本`、`转换整数` 含 `整数`、`随机整数` 含 `整数`。如果只查词表，这些名字会被切成 `文本`+`化`，标准库直接不可用。

解法不是给它们改名（那会让标准库名字变得别扭），而是**把内置名与标准库导出名放进一张独立的、优先于词表的表**：

| 性质 | 词表（1.3） | 内置名表（本表） |
|---|---|---|
| 数量 | 115 条目，封版 | 开放，随标准库增长 |
| 解析优先级 | 低 | **高**（第 5.a 步） |
| 用户能否用作标识符 | 不能 | 不能 |
| 是否算「语言的词」 | 是 | 否，属标准库范畴 |
| 变更约束 | 人签字 | 标准库版本变更即可 |

内置名表的完整内容：

```
文本化 读取文本 写入文本 读取参数 写入错误
转换整数 转换小数 转换文本 转换字符
随机整数 当前时间 休眠
寻找子串 替换子串 比较文本
排序列表 寻找列表
位模式 十六进制 二进制
断言 终止
绝对值 最大值 最小值 平方根 幂 取整
```
规则：

1. 内置名表由编译器在启动时从标准库的 `导出：` 段自动收集，外加固定的 10 个语言内置（`转换`、`截取`、`追加`、`删除`、`插入`、`文本化`、`申请内存`、`释放内存`、`复制内存`、`比较内存`）。
2. 最长匹配优先：`读取文本` 优先于 `读取`；`文本化` 整词命中，不会被切成 `文本`+`化`。
3. **内置名不可被用户重定义**（报 `E3001`），也不可作标识符（报 `E3006`）。
4. **内置名不进 115 词表**。词表管语法骨架，内置名管标准库。这条分界保证「标准库可以长，语言不会膨胀」。
5. 若内置名与词表词**完全同形**（如 `截取` 既是词表词又是内置函数），词表优先——因为 1.3 已封版。这类同形名在标准库里只作词表词的「语法糖身份」使用，调它时写 `【】` 形式。

> **这条规则的必要性**：v3.0 漏了它，导致 `文本化【值】` 在词法层就断了。这是「标准库用中文命名」与「词表封版」两条原则的必然摩擦点，必须显式裁决，不能靠取名运气。

**最长匹配优先级**：`不大于` 优先于 `大于`；`不等于` 优先于 `等于`；`项数` 优先于 `项`；`字数` 优先于 `字`；`参数为`/`结果为`/`对齐为`/`类型为`/`记为` 各自整体匹配。

**词表最长词**：`停止循环`（4 字）、`跳过本次`（4 字）、`申请内存`（4 字）、`内存屏障`（4 字）、`按位异或`（4 字）。所以 8 字窗口足够，实际取 4 即可，留余量取 6。

#### 1.4.2 标识符规则

- 首字符：汉字，或 `_`。
- 后续：汉字、`_`、ASCII 数字。
- 长度：1..32 个字符。
- 不得含 ASCII 字母（`甲a` 判错）。
- 不得等于或包含词表词（1.3.12），也不得等于内置名（1.4.1）。
- 同一篇内不得重复定义（不同段也不行）。
- 大小写无关（因为无字母）。

#### 1.4.3 数字字面量

| 形式 | 例 | 说明 |
|---|---|---|
| 十进制整数 | `42` | 默认 `整数` |
| 负数 | `负7` | `负` 是词，`7` 是数字，语法层组合 |
| 小数 | `3．14`、`3.14` | 归一为 `3．14` |
| 十六进制 | `十六进制【FF】` | 内置操作，不引入 `0x` 前缀（半角 `x` 禁止） |
| 二进制 | `二进制【1010】` | 同上 |

> 为什么不用 `0x`：`x` 是半角字母，与「禁半角」冲突。`十六进制【FF】` 里 `FF` 是文本，需写 `十六进制【「FF」】`。为避免这层嵌套，十六进制字面量规定为 `十六进制【255】` 形式——参数是十进制数，语义是「把这个十进制数当十六进制位模式解读」。这很反直觉，所以**实际写法是 `位模式【「FF」】`**，`位模式` 作为内置操作接受文本参数。

简化决定：**不提供十六进制/二进制字面量**。需要时用十进制或 `位模式【「FF」】`（`位模式` 是内置函数，不是字面量语法）。这一条写进 1.3 词表外，属标准库函数而非语法。

#### 1.4.4 文本字面量

```
「你好，世界。」
『他说「好」。』
```

- `「」` 内不得出现 `」`。
- `『』` 内不得出现 `』`。
- 文本可跨行？**不允许**。跨行文本必须用 `连接` 拼接。
- 文本内允许 `。，、；：（）【】〈〉．` 等全角符号，按字面处理。

#### 1.4.5 注释

```
（这是一句注释。）
（注释里可以写如果等于记为，不影响分词。）
```

- `（）` 内不得出现 `）`。
- 注释可跨行（因为 `）` 是终止符，换行不终止）。
- 注释不参与语法，但**参与行号统计**。
- 注释可出现在任何两个 token 之间，包括段标签后、句号前。

#### 1.4.6 汇编段

```
汇编：
mov x0, #1
svc #0x80
汇编结束。
```

- `汇编：` 之后到 `汇编结束。` 之间的**全部字节**原样保留，包括半角、空格、换行。
- 汇编段内**不能写注释**。想写说明就写在 `汇编：` 之前，用普通 `（…）` 注释。
- 终止标记固定为 `汇编结束。`。它**不是词表词**，是汇编段的固定收束标记，只在汇编段内被识别。
- 汇编段内不得再出现 `汇编结束。`（会提前终止）。
- 汇编段内不得嵌套汇编段。
- 汇编段只在 `系统：` 内合法（语义规则 16、17）。
- 汇编段内**不做**全角检查、空格检查、词表检查；内容交给后端按目标平台校验指令名与寄存器名。

### 1.5 语法：段与句

#### 1.5.1 段的三类

| 类 | 成员 | 段体内容 | 终止方式 |
|---|---|---|---|
| 声明段 | 导入、常数、类型、记录、枚举、联合、输入、设定、导出、锁、线程、通道 | 声明句 | 遇下一个段标签或文件结束 |
| 容器段 | 函数、通用、规则、循环、匹配、尝试、并行、系统、汇编 | 句子 + 子段 | **必须 `段结束。`** |
| 叶子段 | 例、输出 | 句子 | 遇下一个段标签或文件结束 |

**这条规则是 v3.0 最重要的修复**。v2.0 只说「遇下一标签终止」，导致 `规则：` 内的 `循环：` 无法判断是嵌套还是同级。现在：容器段一律显式 `段结束。`，解析器用栈配对，无歧义。

#### 1.5.2 嵌套规则

- 容器段可嵌套容器段，深度 ≤ 3（含最外层）。
- 容器段内可含声明段？**不允许**。声明段只能出现在顶层。
- 叶子段内不得含任何段。
- `匹配：` 内只允许 `情形`/`其他` 子段，不允许其他段标签。
- `尝试：` 内只允许 `出错：`/`收尾：` 子段。
- `汇编：` 内不得含任何段。

#### 1.5.3 段序（顶层）

```
《篇名》
→ 导入 → 常数 → 类型 → 记录/枚举/联合
→ 输入 → 设定 → 导出 → 锁/线程/通道
→ 函数/通用
→ 规则/循环/匹配/尝试/并行/系统
→ 例 → 输出
```

同类段必须连续。中间夹别的段后再开同类段判错。

#### 1.5.4 一个完整骨架

```
《示例》

导入：《数学》。

常数：上限〈整数〉记为100。

记录：点。
横〈整数〉。
纵〈整数〉。

输入：甲〈整数〉。
设定：结果〈整数〉。

导出：平方。

函数：平方，参数为值〈整数〉，结果为整数。
返回值乘以值。
段结束。

规则：
结果记为平方【甲】。
循环：只要结果大于上限。
结果记为结果减去1。
段结束。
段结束。

例：甲记为3。结果记为9。

输出：结果。
```

注意：`规则：` 内的 `循环：` 有独立的 `段结束。`，`规则：` 自己还有一个。

#### 1.5.5 空行与缩进

- 空行：只作视觉分段，不影响语义。段与段之间建议空一行。
- 缩进：**判错**。所有行必须顶格。
- 行尾空白：判错。
- 文件末尾必须有一个换行。

### 1.6 句式全集（16 种）

| # | 句式 | 模板 | 允许位置 |
|---|---|---|---|
| 1 | 赋值 | `<名>记为<项>。` | 任意句子位置 |
| 2 | 带类型赋值 | `<名>〈类型〉记为<项>。` | 设定段、函数体首现 |
| 3 | 条件 | `如果<条件>，<句>；否则，<句>。` | 任意句子位置 |
| 4 | 条件多句 | `如果<条件>，<句>，<句>；否则，<句>，<句>。` | 同上 |
| 5 | 跳出 | `如果<条件>，停止循环。` / `跳过本次。` | 循环段内 |
| 6 | 返回 | `返回<项>。` | 函数/通用段内 |
| 7 | 抛出 | `抛出<文本项>。` | 任意 |
| 8 | 函数定义 | `函数：<名>，参数为<名>〈类型〉、…，结果为<类型>。` | 顶层 |
| 9 | 泛型定义 | `通用〈甲型〉：<名>，参数为<名>〈甲型〉、…，结果为<类型>。` | 顶层 |
| 10 | 列表字面量 | `列表【<项>、<项>】` | 表达式位置 |
| 11 | 下标读写 | `<数组>的第<项>项` / `<数组>的第<项>项记为<项>。` | 表达式/句子 |
| 12 | 匹配 | `匹配：<项>。` + `情形<值或成员>：` + `其他：` + `段结束。` | 容器段 |
| 13 | 构造 | `<记录名>【<字段>：<项>、…】` / `<标签类型名>【<成员>：<项>】` | 表达式位置 |
| 14 | 调用 | `<名>【<项>、…】` | 表达式位置 |
| 15 | 注释 | `（任意文字。）` | 任意位置 |
| 16 | 收束 | `段结束。` / `汇编结束。` | 容器段末尾 |

> **句式数恒为 16**：定长数组的 `数组〈整数〉【1、2、3】` 归句式 13（构造，类型自带元素类型故不写字段名）；`数组〈整数〉〈3〉` 与 `管道〈10〉` 归句式 8/9 的类型参数位。新增能力一律塞进已有句式，不扩句式表——这是词表与句式双封版的纪律。

#### 1.6.1 条件句的分支内容

`如果` 后只能跟**一条或多条简单句**，用 `，` 分隔。简单句指句式 1、2、5、6、7。

- **不允许**分支内再写条件句。要嵌套判断就抽函数。
- **不允许**分支内写 `循环：` 等容器段。
- 分支内多句用 `，` 分隔，最后一句以 `。` 收。

```
如果甲大于0，结果记为1，标记记为真；否则，结果记为0，标记记为假。
```

#### 1.6.2 条件表达式

`<条件>` 的语法：

```
<条件> := <项> <比较词> <项>
        | <条件> 并且 <条件>
        | <条件> 或者 <条件>
        | 不是 <条件>
        | <真假项>
```

- `并且`/`或者` **不得混用**，混用判错，必须拆成两个条件句。
- 优先级：`不是` > 比较 > `并且`/`或者`（同级左结合）。
- 比较词两端类型必须相同（文本比文本、整数比整数），否则判错。

#### 1.6.3 匹配段

```
匹配：等级。
情形「优秀」：
评语记为「保持」。
情形「合格」：
评语记为「再练」。
其他：
评语记为「加油」。
段结束。
```

- `情形` 后的值是字面量（整数、文本、真假、枚举成员），**或联合/可选/成败的成员名**（1.8.2.2）。
- 每个 `情形` 段体至少一句。
- `其他：` 一般必须存在（穷尽性检查）。若枚举已列全，可写 `其他：` 后跟 `段结束。`，段体为空——但**必须写 `其他：`**，保持结构统一。
- **唯一的例外**：被匹配的类型是 `联合`/`可选`/`成败`，且全部成员都已列出时，可省略 `其他：`。因为穷尽性在编译期可证，省一行不损失安全性。
- `匹配` 的项类型与 `情形` 值类型必须一致。带标签的值匹配成员名，不带标签的值匹配字面量，两者不混用。
- 分支内读被匹配值的成员（`甲的姓名`）是安全的；读**未激活**的成员在带标签类型上会插入运行时检查，命中即抛 `「联合成员不匹配」`。

#### 1.6.4 尝试段

```
尝试：
结果记为危险操作【输入】。
出错：
日志记为「失败：」连接错误。
收尾：
清理【资源】。
段结束。
```

- `出错：` 必须存在。
- `收尾：` 可选。
- `出错：` 段内自动可用变量 `错误`（类型 `文本`），由运行时填入。
- `收尾：` 段内不得 `返回`（否则跳过收尾后的清理）。

#### 1.6.5 并行段

```
并行：
令牌一记为计算一【数据】。
令牌二记为计算二【数据】。
段结束。
```

- 段体内每条必须是**赋值句**（句式 1），左侧名的类型必须与右侧返回类型一致。返回 `空` 的函数要赋给 `空` 类型的名。
- 左侧名必须已在 `设定：` 声明（或用句式 2 就地标注 `名〈类型〉记为…`）。
- `段结束。` 处自动等待全部线程完成（隐式 join），结果已写入左侧名。
- 段内不得写 `循环：`、`匹配：` 等容器段，不得写 `返回`、`抛出`。
- 段内不得读写段外可变量（编译期检查，报 `E5002`）。可以读 `常数：` 与参数。
- 段内不得嵌套 `并行：`。
- 段数上限 16，超过报 `E2006`（防止误写创建上千线程）。

#### 1.6.6 例段（编译期断言）

`例：` 段体内只允许**赋值句**（句式 1、2）。判定期望值的规则不需要任何新词：

> **出现在 `输出：` 段的名字，其在 `例：` 中的赋值就是期望值；其余名字是输入。**

```
例：甲记为考生【姓名：「张三」、三科：列表【95、95、95】】。等级记为「合格」。评语记为「等级：合格」。
```

上例中 `甲` 不在 `输出：` 段 → 输入；`等级`、`评语` 在 `输出：` 段 → 期望值。

判定期序：

1. 把非输出名的赋值写入输入环境。
2. 执行 `规则：` 段。
3. 比对每个输出名的实际值与例中赋的值。
4. 任一不符 → 编译期报错，打印期望与实际。

约束：

- 例段的赋值顺序不影响语义（先收集全部输入，再执行规则）。
- 例段中的项必须是**编译期可求值**的（字面量、构造、列表字面量、纯函数调用）。含 `读取文本` 等 IO 的例段判错。
- 一个例段只跑一次。多个例段逐个跑。
- 可选 `（…）` 注释说明该例的意图。

反例：

| 写法 | 问题 |
|---|---|
| `例：输入甲记为1。` | `输入` 是段标签，不是例段内的词 |
| `例：甲为1。` | `为` 不在词表 |
| `例：甲记为读取文本【】。` | 例段不许 IO |
| `例：甲记为1。` 但 `输出：` 是 `乙` | 未断言任何输出名，例段无效 |

### 1.7 表达式与求值

#### 1.7.1 项（表达式）的语法

```
<项> := <字面量>
      | <名>
      | <项> 的 <字段名>                    （字段读；也是标签取值）
      | <项> 的 第 <项> 项                  （索引读）
      | <项> 的 项数 | <项> 的字数          （长度）
      | <名> 【 <项> 、… 】                 （调用）
      | <记录名> 【 <字段> ： <项> 、… 】    （构造）
      | <标签类型名> 【 <成员> ： <项> 】     （联合/可选/成败构造）
      | <标签类型名> 【 <无载荷成员> 】       （无载荷成员构造）
      | 数组 〈 <类型> 〉 【 <项> 、… 】      （定长数组字面量）
      | 数组 〈 <类型> 〉 〈 <常量> 〉        （定长数组定量声明）
      | 字符 【 「<单字符>」 】 | 字符 【 <常量> 】  （字符字面量）
      | 列表 【 <项> 、… 】                 （列表字面量）
      | <项> <二元运算符> <项>
      | 不是 <项> | 取反 <项> | 负 <数字>
      | 《篇名》 的 <名>                    （跨篇）
```

#### 1.7.2 二元运算符与优先级

| 级 | 运算符 | 结合 |
|---|---|---|
| 1（高） | `乘以`、`除以`、`取余`、`按位与` | 左 |
| 2 | `加上`、`减去`、`按位或`、`按位异或` | 左 |
| 3 | `左移`、`右移` | 左 |
| 4 | `等于`、`不等于`、`大于`、`小于`、`不大于`、`不小于` | 非结合 |
| 5 | `并且`、`或者` | 左（不得混用） |

#### 1.7.3 无括号规则

**不提供表达式括号**。需要改变结合顺序时，拆成多个赋值句：

```
（想要（甲加上乙）乘以丙，写成两行。）
临时记为甲加上乙。
结果记为临时乘以丙。
```

理由：`（）` 已专用于注释，再引入 `〔〕` 会让符号表膨胀且用户要记第四种括号。拆句的代价是多一行，收益是零歧义、可读性更好（每一步有名字）。

#### 1.7.4 求值顺序

- 二元运算：左操作数先求值，再右操作数。
- 函数调用：参数从左到右求值，然后进入函数。
- 短路：`并且` 左假即返回假，`或者` 左真即返回真。
- 赋值：右侧先求值，再写左侧。

#### 1.7.5 内置操作（`【】` 形式，属标准库而非语法）

**前缀式（`【】` 调用）**：

| 操作 | 语义 |
|---|---|
| `转换〈T〉【值】` | 类型转换，必须显式 |
| `截取【文本、起点、终点】` | 取子串，索引从 1，终点不含 |
| `追加【列表、值】` | 原地追加 |
| `删除【列表、序号】` | 删除第 n 项 |
| `插入【列表、序号、值】` | 在第 n 项前插入 |
| `文本化【值】` | 任意值转文本，用于输出 |
| `申请内存【字节数】` | 仅系统层 |
| `释放内存【指针】` | 仅系统层 |
| `复制内存【目标、源、字节数】` | 仅系统层 |
| `比较内存【甲、乙、字节数】` | 仅系统层 |

**中缀式（二元运算符写法）**：

| 写法 | 等价于 |
|---|---|
| `甲连接乙` | `连接【甲、乙】` |
| `甲的项数` | `项数【甲】` |
| `甲的字数` | `字数【甲】` |

中缀式是语法糖，降级时统一转成 `【】` 形式。两者不可混用：不能写 `连接甲、乙`，也不能写 `项数【甲】的字数`（无意义）。

#### 1.7.6 十六进制与二进制

不提供 `0x`/`0b` 字面量（含半角字母）。改用标准库函数：

```
掩码记为十六进制【「FF」】。
标志记为二进制【「1010」】。
```

- 参数是 `文本`，只允许 `0-9`、`A-F`、`a-f`（十六进制）或 `0-1`（二进制）。
- 返回值是 `整数`。
- 文本含非法字符 → 编译期报错（因为例段在编译期求值）；运行期调用则抛 `「数字格式错误」`。
- 结果超出 `整数` 范围 → 抛 `「整数溢出」`。

#### 1.7.7 运算符与内置函数的分界

判断标准：**能被用户用现有词重写出来的，就不给内置函数；重写不出来的（需要访问硬件或运行时），才给内置函数。**

| 内置（不可重写） | 非内置（标准库用语言写） |
|---|---|
| `转换` | `文本化` 的整数分支（可手写数字转字符） |
| `截取`/`连接`/`字数`（文本是运行时表示） | `排序`（用循环写） |
| `追加`/`删除`/`插入`（列表是运行时表示） | `最大值`（用条件写） |
| `申请内存`/`释放内存`（需系统调用） | `绝对值`（用条件写） |
| `原子加`/`原子换`（需硬件指令） | `查找`（用循环写） |
| `发送`/`接收`（需运行时调度） | `随机整数`（用线性同余写） |

这条分界保证标准库大部分是 Serica 自己写的——这是「自研」的实际体现。

### 1.8 类型系统

#### 1.8.1 标量

| 类型 | 宽度 | 字面量 | 说明 |
|---|---|---|---|
| `整数` | i64 | `42`、`负7` | 默认整数 |
| `整数8/16/32/128` | 对应宽度 | `42` | 显式标注才用 |
| `正整数` | u64 | `42` | 不接受 `负` |
| `正整数8/16/32/64` | 对应 | `42` | |
| `小数` | f64 | `3．14` | IEEE-754 |
| `小数32` | f32 | `3．14` | |
| `真假` | 1 字节 | `真`、`假` | 存储占 1 字节，非 1 bit |
| `字符` | u32 | `字符【「中」】`、`字符【20013】` | Unicode 标量值，见 1.8.1.1 |
| `文本` | UTF-8 引用 | `「你好」` | 不可变，ARC 管理 |
| `空` | 0 字节 | `空` | void |

##### 1.8.1.1 字符字面量（零半角）

`字符` 有两种构造形式，都在 `【】` 内，**不含任何半角字母**：

| 形式 | 例 | 用途 |
|---|---|---|
| 单字符文本 | `字符【「中」】` | 日常写法。`【】` 内必须恰好 1 个 Unicode 标量值 |
| 十进制标量值 | `字符【20013】` | 打不出来的字符：`字符【12303】` 是 `』`、`字符【10】` 是换行 |

```
换行符记为字符【10】。
左书名号记为字符【「《」】。
```

规则：

- `字符【「…」】` 内长度 ≠ 1 → 报 `E4008「字符字面量必须恰好一个字符」`。
- `字符【20013】` 的数必须在 `0..1114111` 且不是代理对区（`55296..57343`）→ 否则报 `E4009「字符标量值越界」`。
- `字符` 与 `整数` 互转：`转换〈整数〉【字符】` 得标量值，`转换〈字符〉【20013】` 反向；`转换〈字符〉【文本】` 要求文本长度恰为 1。
- **废除旧写法 `字〈4E2D〉`**：`4E2D` 含半角字母 `E`，违反 1.2.1；且 `字` 单字会与 `字数` 抢最长匹配。全书统一为 `字符【…】`。

#### 1.8.2 复合

| 类型 | 写法 | 值语义 | 内存 |
|---|---|---|---|
| 定长数组 | `数组〈整数〉` | 值类型 | 栈，编译期定长（1.8.2.1） |
| 动态列表 | `列表〈整数〉` | 引用类型 | 堆，ARC |
| 指针 | `指针〈整数〉` | 值类型 | 仅系统层 |
| 函数 | `函数〈整数、文本〉` | 值类型 | 函数指针 |
| 联合 | `联合：数值。` | 值类型 | 最大成员 + 标签（1.8.2.2） |
| 可选 | `可选〈整数〉` | 值类型 | 标签 + 值（1.8.2.2） |
| 成败 | `成败〈整数、文本〉` | 值类型 | 标签 + 值或错误（1.8.2.2） |
| 弱引用 | `弱引用〈学生〉` | 引用类型 | 不增计数 |
| 易变 | `易变〈整数〉` | 值类型 | 禁止优化读写 |

#### 1.8.2.1 定长数组（长度写在哪里）

定长数组只有两种构造，都不含新词：

| 形式 | 例 | 长度 | 初值 |
|---|---|---|---|
| 字面量 | `数组〈整数〉【1、2、3】` | 元素个数 = 3 | 逐项给出 |
| 定量声明 | `数组〈整数〉〈3〉` | 3 | 全零（`零值`） |

```
设定：分数〈数组〈整数〉〉、缓冲〈数组〈字符〉〉。
分数记为数组〈整数〉【90、85、77】。
缓冲记为数组〈字符〉〈16〉。
分数的第2项记为95。
长度的数记为分数的项数。
```

- `〈〉` 是**类型参数/容量参数位**（与 `管道〈10〉` 同一用法），`【】` 是**值位**。两者形状不同，不会混。
- `零值` 填充分：整数类 `0`、小数 `0`、真假 `假`、字符 `0`、指针 `空指针`、记录递归零值。
- **不允许空数组**：`数组〈整数〉【】` 判错 `E4010「定长数组必须有长度」`。要可变长用 `列表`。
- **不允许运行期定长**：`数组〈整数〉〈项数〉` 中 `项数` 必须是编译期常量，否则报 `E4011「定长数组长度必须是编译期常量」`。运行期要多少用 `列表`。
- 下标从 1，越界时：索引是字面量 → 编译期报 `E5009`；索引是变量 → 运行时抛 `「数组越界」`。
- 数组是**值类型**：作为参数传入时整体复制（16 个整数 = 128 字节的 memcpy，由优化 pass 消除明显拷贝）。要共享用 `指针〈数组〈T〉〉`（仅系统层）。

#### 1.8.2.2 标签取值：联合、可选、成败

三者是同一机制的三种封装，**构造与判别写法完全一致**，不引入新词，不占用词表。

**构造**：与记录构造同形（`类型名【成员名：值】`），但**恰好一个成员**；无载荷成员省略 `：值`。

**判别**：`匹配：` + `情形<成员名>：`（1.6.3 已有形状，成员名属标识符，不是词表词）。

**取值**：`<值>的<成员名>`（1.3.8 的 `的`，与记录字段读同一写法）。

**联合**：

```
联合：数值。
大值〈整数〉。
小值〈小数〉。

甲记为数值【大值：5】。
匹配：甲。
情形大值：
结果记为文本化【甲的大值】。
情形小值：
结果记为文本化【甲的小值】。
段结束。
```

> 成员名必须是**不含词表词**的标识符（1.3.12）。所以不能写 `整数部分`——`整数` 是词表词，分词器会先切出 `整数`，剩下 `部分` 成了孤儿。用 `大值`/`小值` 这类双字名。

**本小节不提供「判断某成员是否激活」的运算符**：判别一律走 `匹配`。理由：加一个 `是` 或 `属于` 就扩词表，而 `匹配` 已经能表达全部情形，且强制穷尽更安全。

**可选**：两个内置成员 `有值`、`无值`。`无值` 无载荷。

```
设定：甲〈可选〈整数〉〉、结果〈整数〉。
甲记为可选【有值：7】。
匹配：甲。
情形有值：
结果记为甲的值。
情形无值：
结果记为0。
段结束。
```

```
甲记为可选【无值】。
```

> `可选` 的载荷成员名是 `值`，故取值写 `甲的值`。`值` 不是词表词（词表里是 `零值`、`取值`），可作成员名。

**成败**：两个内置成员 `成功`（载荷为第一个类型参数）、`失败`（载荷为第二个类型参数）。

```
函数：除法，参数为被除数〈整数〉、除数〈整数〉，结果为成败〈整数、文本〉。
如果除数等于0，返回成败【失败：「除数为0」】；否则，返回成败【成功：被除数除以除数】。
段结束。

规则：
调用结果记为成败【成功：10】。
匹配：调用结果。
情形成功：
商记为调用结果的成功。
情形失败：
商记为0。
段结束。
段结束。
```

> 名字里不能有 `尝试`（段标签词），所以用 `调用结果` 而非 `尝试结果`。`被除数`/`除数` 都不含词表词（词表里是 `除以`），可放心用。

**为什么要 `成败` 而不全用异常**：异常适合「我这一层处理不了」，`成败` 适合「调用方必须当场决定怎么办」。两者共用同一运行时（`成败` 是普通值，零额外开销），标准库两套都给，由调用方选。**注意：`成败` 不是异常，`失败` 不会自动展开栈**。

**编译器检查**：

1. 构造时成员名必须是该类型声明的成员，否则 `E4012「成员名不属于该类型」`。
2. 构造时恰好一个成员，多写或漏写报 `E4013「带标签类型必须恰好一个成员」`。
3. 载荷类型必须与成员声明一致，否则 `E4014「成员载荷类型不符」`。
4. `匹配` 已列全部成员时可省 `其他：`——这是**唯一**允许省略 `其他：` 的场合（穷尽性在编译期可证）；列不全必须补 `其他：`，否则 `E2008「匹配段缺少「其他：」」`。
5. 读未激活成员的值 → 运行时抛 `「联合成员不匹配」`。`匹配` 分支内读该分支成员是安全的，编译器据此插入最小检查（可被优化 pass 消除）。

**不占词表**：`有值`、`无值`、`成功`、`失败` 是**内置成员名**，地位等同记录字段名与枚举成员名，属标识符空间，不计入 115 条目。但它们**不能被用户当标识符**（1.9.6 第 2 条）——否则 `匹配` 里无法区分成员与普通名。这条写死，防止后续把它们当成语法词扩表。

#### 1.8.3 用户定义类型

**记录**（结构体，值类型，栈分配）：

```
记录：学生。
姓名〈文本〉。
年龄〈整数〉。
成绩〈列表〈小数〉〉。
```

构造：`学生【姓名：「张三」、年龄：18、成绩：列表【90．5】】`。

**记录的传参语义（写死，不留想象空间）**：

- 记录按**值**传递：整个记录被复制。
- 复制是**浅复制**：标量字段复制值，引用字段（文本、列表）复制指针并 `retain`。
- 因此：函数内改**标量字段**不影响调用方；改**列表字段的内容**（`追加`）会影响调用方，因为共享同一块堆内存。
- 要改标量字段并让调用方看到，只有两条路：
  1. 把该字段改成 `列表〈T〉` 并改第 1 项（丑，不推荐）；
  2. 在 `系统：` 段传 `指针〈记录〉`，手动解引用写（内核与运行时用）。

示例说明：

```
记录：账户。
余额〈整数〉。
流水〈列表〈整数〉〉。

函数：存钱，参数为账〈账户〉、额〈整数〉，结果为空。
账的余额记为账的余额加上额。
追加【账的流水、额】。
段结束。
```

调用后：调用方的 `余额` **不变**（标量字段是副本），但 `流水` **多了额**（列表共享）。这个不对称必须写进文档，否则用户会踩坑。

**要正确实现「存钱」，写法是把余额也变成引用语义，或者用返回值**：

```
函数：存钱，参数为账〈账户〉、额〈整数〉，结果为账户。
账的余额记为账的余额加上额。
追加【账的流水、额】。
返回账。
段结束。

（调用：当前记为存钱【当前、100】。）
```

**枚举**（值类型，底层整数）：

```
枚举：颜色。
红。
绿。
蓝。
```

使用：`颜色记为红。`；匹配：`情形红：`。

**联合**（值类型，带标签）：成员名必须是**不含词表词**的标识符。

```
联合：数值。
大值〈整数〉。
小值〈小数〉。
```

构造、判别、取值三者见 **1.8.2.2**（联合/可选/成败共用同一套写法）。`可选`、`成败` 的构造与解包也在那一节，本小节不重复。

**类型别名**：

```
类型：标识〈正整数〉。
```

#### 1.8.4 类型标注

写在名字后的 `〈〉` 内，可省略（省略按赋值推断）：

```
设定：甲〈整数〉、乙〈文本〉、丙〈列表〈整数〉〉。
输入：语文〈整数〉、姓名〈文本〉。
```

- 函数参数与返回值**必须**标注。
- 记录字段**必须**标注。
- 局部变量可省略，首次 `记为` 时推断。
- 推断失败（如 `甲记为空`）判错，必须标注。

#### 1.8.5 类型规则

1. **不隐式窄化**：`整数` 赋给 `整数32` 必须 `转换〈整数32〉【值】`。
2. **隐式拓宽允许**：`整数32` 可赋给 `整数`，`整数` 可赋给 `小数`。
3. **整数与小数混合运算**：整数提升为小数，结果为小数。
4. **文本与整数不隐式互转**：必须 `文本化【值】` 或 `转换〈整数〉【文本】`。
5. **泛型单态化**：每个具体类型生成一份代码，零运行时开销。
6. **类型推断限于函数体内**：跨函数边界必须可判定，即参数与返回必须标注。
7. **循环引用的记录**：必须用 `弱引用` 打断，否则 ARC 泄漏（1.13.3）。

#### 1.8.6 转换

```
甲记为转换〈整数32〉【乙】。
文本记为文本化【甲】。
整数记为转换〈整数〉【「42」】。
```

- 整数 ↔ 小数：截断（向零）。
- 文本 → 整数：解析失败抛异常。
- 整数 → 文本：十进制。
- 指针 ↔ 整数：仅系统层。

### 1.9 名字与作用域

#### 1.9.1 作用域层级

| 层 | 内容 | 可见范围 |
|---|---|---|
| 篇级 | 常数、类型、记录、枚举、联合、函数、通用、规则、导出、锁、线程、通道 | 全篇 |
| 函数级 | 参数、函数体内 `记为` 的名字 | 函数体内 |
| 段级 | 无独立段级作用域 | — |

**没有块级作用域**。因为段不嵌套句子块，条件句分支里 `记为` 的名字属于所在函数/规则段。

#### 1.9.2 遮蔽

**禁止遮蔽**。函数参数不得与篇级名同名；函数体内 `记为` 不得与参数同名。

理由：遮蔽是 C/Java 里最常见的 bug 来源，中文名本来就长，遮蔽收益为零。

#### 1.9.3 跨篇访问

```
导入：《数学》。

规则：
结果记为《数学》的平方【3】。
段结束。
```

- `导入：` 后可跟多个篇名，用 `、` 分隔。
- 跨篇访问必须写 `《篇名》的` 前缀，不允许省略。
- 被访问的名字必须在对方 `导出：` 段列出。

#### 1.9.4 导出

```
导出：平方、取大。
```

- 默认全部私有。
- `导出：` 只能列篇级名字。
- 未导出的名字跨篇访问判错。

#### 1.9.5 前向引用（顺序无关）

**篇级名字在整个篇内可见，与出现顺序无关。**

```
函数：偶数，参数为数〈整数〉，结果为真假。
如果数等于0，返回真；否则，返回奇数【数减去1】。
段结束。

函数：奇数，参数为数〈整数〉，结果为真假。
如果数等于0，返回假；否则，返回偶数【数减去1】。
段结束。
```

`偶数` 在自己体内调用 `奇数`，而 `奇数` 定义在后面——合法。名字解析分两遍：先收集全篇篇级名字，再解析引用。

理由：

- 递归与互递归是基本能力，强制前置声明会逼出「伪辅助函数」这种绕路。
- 中文名较长，前置声明段会让文件头臃肿。

例外：**没有**。局部名（函数体内 `记为`）仍是「先定义后使用」，因为局部名的类型靠赋值推断，无法两遍收集。

#### 1.9.6 命名的可预测性规则

为了让「名字不撞词表词」可机械判断，标识符必须满足：

1. 不含任何词表词作为连续子串（1.3.12）。
2. 不得等于 `有值`、`无值`、`成功`、`失败`（内置成员名，见下方名单）。
3. 长度 ≥ 2 个汉字（单字名与词表词几乎必然冲突）。
4. 不用 `的`、`第`、`项` 开头（会被分词成结构访问）。
5. 不用数字开头（与数字字面量冲突）。

推荐的命名方式：**名词 + 名词**（`总分`、`页表位置`）、**形容词 + 名词**（`空闲块`、`最大项`）、**动词 + 名词**（`读位置` 不推荐，用 `当前位置`）。

不推荐：单字（`甲` 仅用于示例与极短作用域）、拼音（`zongfen`）、英文（判错）、带数字（`值1` 中含 `1` 合法但可读性差，示例里用 `令牌一`）。

**高频踩坑名单**（这些词看着像好名字，实为词表词，取名必撞）：

| 不能用作名字 | 因为它已是 | 换个说法 |
|---|---|---|
| `地址`、`取值`、`对齐` | 内存与硬件词（1.3.10） | `位置`、`起始`、`偏移` |
| `字符`、`整数`、`文本`、`列表`、`数组`、`函数`、`指针`、`空` | 类型词（1.3.2） | `本字`、`数目`、`原文`、`序列`、`表`、`过程`、`游标` |
| `项`、`项数`、`字数`、`第` | 结构访问与集合词（1.3.8/1.3.9） | `条目`、`长度`、`尺寸`、`序号` |
| `输出`、`输入`、`例`、`规则`、`系统` | 段标签（1.3.1） | `结果`、`来源`、`样例`、`流程`、`内核` |
| `成功`、`失败`、`有值`、`无值` | `成败`/`可选` 的**内置成员名**（1.8.2.2） | `是否通过`、`错误说明`、`找到`、`未找到` |

> 为什么内置成员名也进这份名单：`可选【有值：7】` 里的 `有值` 是**语法位置上的固定名**，若用户自己也起名叫 `有值`，`匹配` 时就无法区分「分支成员」与「普通名」。所以内置成员名与词表词同等对待——不能当标识符。这条列入 `E3006` 的检查范围。

### 1.10 内存模型

| 层 | 规则 |
|---|---|
| 文章层（默认） | **ARC**：编译器自动插入持有/释放；`弱引用` 打破循环 |
| 系统层（`系统：` 内） | **手动**：`申请内存`/`释放内存`；不插 ARC |
| 裸机目标 | 默认关闭 ARC，可用 `--启用自动内存` 打开 |

#### 1.10.1 值类型与引用类型

| 类型 | 类别 | 分配 |
|---|---|---|
| 整数/正整数/小数/真假/字符 | 值 | 栈或寄存器 |
| 定长数组 | 值 | 栈 |
| 记录 | 值 | 栈（含引用字段时，字段指向堆） |
| 指针 | 值 | 栈 |
| 可选/成败 | 值 | 栈 |
| 文本 | 引用 | 堆，ARC |
| 列表 | 引用 | 堆，ARC |

#### 1.10.2 ARC 插入规则

编译器在以下位置插入 `retain`/`release`：

1. 引用类型赋值给新名字 → 对新值 `retain`，对旧值 `release`。
2. 引用类型作为参数传入 → 调用方 `retain`，被调方函数末尾 `release`（或按调用约定转移）。
3. 引用类型作为返回值 → 转移所有权，不 `retain`。
4. 引用类型离开作用域 → `release`。
5. `弱引用` 赋值 → 不 `retain`，目标释放时置 `空指针`。

优化：编译器做引用计数消除（RCO），消除明显的临时 retain/release 对。

#### 1.10.3 循环引用

```
记录：节点。
值〈整数〉。
下一个〈可选〈弱引用〈节点〉〉〉。
```

- 环必须至少有一个 `弱引用` 边。
- `--检查泄漏` 运行时统计未释放块，退出时打印。
- `例：` 段可加 `（应无泄漏。）` 注释，CI 用 `--检查泄漏` 跑。

#### 1.10.4 系统层

- `申请内存【字节数】` 返回 `指针〈空〉`。
- `释放内存【指针】` 归还。
- 系统层内的指针不被 ARC 跟踪，编译器不做任何插入。
- 系统层函数返回指针时，所有权归调用方，必须显式 `释放内存`。

### 1.11 并发模型

#### 1.11.1 声明

```
锁：互斥。
线程：工作线程。
通道：管道〈10〉。
```

- `锁：<名>。` 声明互斥量。
- `线程：<名>。` 声明线程句柄（用于手动创建线程）。
- `通道：<名>〈容量〉。` 声明通道，`〈10〉` 是容量，大于 0。容量 0 表示同步通道（发送阻塞直到有人接收）。

#### 1.11.2 并行段（推荐写法）

```
并行：
甲记为计算一【数据】。
乙记为计算二【数据】。
段结束。
```

- 隐式创建线程，`段结束。` 处隐式 join。
- 无需声明 `线程：`。
- 适合「有 N 个独立计算，等全部完成」。

#### 1.11.3 手动线程

```
设定：结果一〈整数〉、结果二〈整数〉。

规则：
创建线程：工作线程、任务一。
创建线程：工作线程二、任务二。
等待线程：工作线程。
等待线程：工作线程二。
段结束。
```

- `创建线程：<线程名>、<函数名>。`
- `等待线程：<线程名>。`
- 手动线程不自动等待，必须显式 `等待线程`。

#### 1.11.4 锁

```
规则：
加锁：互斥。
计数记为计数加上1。
解锁：互斥。
段结束。
```

- `加锁：<锁名>。`、`解锁：<锁名>。`
- 编译器检查：加锁后所有路径必须解锁。有 `返回`/`抛出` 提前退出的，必须配 `尝试：…收尾：解锁：互斥。`。
- 同一线程重复加锁同一互斥量 → 运行时死锁，不做检查（文档说明）。

#### 1.11.5 原子

```
原子加：计数、1。
原子换：标志、真。
```

- 只用于 `整数`/`正整数`/`指针`。
- `原子加` 返回旧值（可忽略）。
- `原子换` 返回旧值。

#### 1.11.6 通道

```
规则：
发送：管道、42。
接收：管道、结果。
段结束。
```

- `发送：<通道>、<项>。` 容量满时阻塞。
- `接收：<通道>、<目标名>。` 通道空时阻塞，收到后写入目标名。
- 通道元素类型在首次使用时推断，全篇必须一致。
- 关闭通道不做（用哨兵值约定），写进 1.18 已知限制。

#### 1.11.7 共享可变状态规则

**编译期强制**：任何在 `设定：` 声明且被多个线程可能写入的名字，读写必须在 `加锁` 与 `解锁` 之间，或使用 `原子加`/`原子换`。否则报错：

```
文件:12:1 错误：共享可变状态「计数」未加锁
建议：用「加锁：互斥。」与「解锁：互斥。」包裹，或改用「原子加：计数、1。」
示例：加锁：互斥。计数记为计数加上1。解锁：互斥。
```

不可变数据（`常数：`、函数参数、`记为` 后从未再次赋值的局部名）不受此限制。

### 1.12 异常模型

#### 1.12.1 抛出

```
如果除数等于0，抛出「除数不能为零」。
```

- 抛出值是 `文本`。
- 未捕获的抛出 → 运行时打印文本 + 调用栈，退出码 1。

#### 1.12.2 捕获

```
尝试：
结果记为除【甲、乙】。
出错：
日志记为「计算失败：」连接错误。
结果记为0。
收尾：
输出：「结束」。
段结束。
```

- `错误` 是 `出错：` 段内自动绑定的名字，类型 `文本`，不需要声明。
- `出错：` 段执行完后，控制流继续到 `收尾：` 之后的第一句。
- 不能在 `出错：` 段内 `返回`（会跳过 `收尾`）。要提前返回，先 `收尾` 里做清理，再在外层返回。

#### 1.12.3 零成本实现

- 正常路径：无额外指令。
- 抛出：查当前函数的异常表，跳转到 landing pad。
- 异常表由编译器生成，存于产物的只读段。
- 裸机可用 `--无异常` 编译，此时 `抛出` 变成 `终止`，`尝试` 段被优化掉。

#### 1.12.4 运行时错误也可捕获

除零、越界、空指针解引用、通道死锁检测都会抛出文本，可被 `尝试` 捕获。文本固定：

| 错误 | 文本 |
|---|---|
| 除零 | `「整数除零」` |
| 下标越界 | `「下标越界」` + 实际值与范围 |
| 空指针 | `「空指针解引用」` |
| 断言失败 | 例段期望值不符时的文本 |
| 栈溢出 | `「栈溢出」` |

### 1.13 泛型

#### 1.13.1 定义

```
通用〈甲型〉：交换，参数为左〈甲型〉、右〈甲型〉，结果为空。
临时记为左。
左记为右。
右记为临时。
段结束。
```

#### 1.13.2 约束

```
通用〈甲型：可比较〉：取大，参数为前〈甲型〉、后〈甲型〉，结果为甲型。
如果前大于后，返回前；否则，返回后。
段结束。
```

- 约束词只有 4 个：`可比较`（支持 6 个比较词）、`可复制`（支持赋值传参）、`可排序`（支持 `<` 全序）、`可哈希`（可用于匹配）。
- 多个约束用 `、` 分隔：`通用〈甲型：可比较、可哈希〉`。
- 不满足约束的实例化在编译期报错。

#### 1.13.3 单态化

- 每个具体类型生成一份机器码。
- `交换【甲、乙】` 中甲是 `整数`、乙是 `整数` → 一份；甲是 `文本`、乙是 `文本` → 另一份。
- 同一个类型参数组合只生成一次（去重）。
- 不保留运行时类型信息（除 `--保留类型信息`）。
- 泛型递归实例化必须有限：编译器检测到实例化栈超过 16 层报错「泛型递归无终止」。

#### 1.13.4 泛型容器

```
通用〈甲型〉：取首，参数为列〈列表〈甲型〉〉，结果为甲型。
如果列的项数等于0，抛出「列表为空」。
返回列的第1项。
段结束。
```

### 1.14 系统层

`系统：` 段内额外允许：

| 能力 | 写法 | 说明 |
|---|---|---|
| 取地址 | `甲的地址` | 返回 `指针〈T〉` |
| 解引用读 | `指针的取值` | |
| 解引用写 | `指针的取值记为<项>。` | |
| 指针偏移 | `指针加上<字节数>` | 按字节，不改类型 |
| 申请内存 | `申请内存【字节数】` | 返回 `指针〈空〉` |
| 释放内存 | `释放内存【指针】` | |
| 内存复制 | `复制内存【目标、源、字节数】` | |
| 内存比较 | `比较内存【甲、乙、字节数】` | 返回整数 |
| 对齐 | `对齐为【2/4/8/16】` | 声明或强制对齐 |
| 易变访问 | `易变〈整数〉` | 禁止优化 |
| 端口读 | `端口读【端口号】` | x86 特有，其他平台报错 |
| 端口写 | `端口写【端口号、值】` | 同上 |
| 内存屏障 | `内存屏障。` | 全屏障 |
| 中断 | `中断【编号】记为<函数名>。` | 安装中断处理 |
| 内联 | `内联：<函数名>。` | 强制内联 |
| 汇编 | `汇编：` … `汇编结束。` | 原样输出 |

#### 1.14.1 中断与裸机

```
系统：
（安装页错误处理。）
中断【14】记为页错误处理。
汇编：
（本段原样输出。）
msr vbar_el1, x0
eret
汇编结束。
段结束。
```

#### 1.14.2 边界

- 系统层不是另一门语言：类型系统、IR、后端完全共用，区别只是「允许哪些构造」。
- 文章层写 `甲的地址` 报错：

```
文件:8:5 错误：文章层不允许取地址
建议：把这段移入「系统：」段，或改用「列表」等引用类型
示例：系统：
```

- `系统：` 不得出现在 `函数：` 之前（1.15-16）。

### 1.15 语义硬规则（28 条，冻结）

1. `除以` 向零截断；常量除零编译报错，运行时除零抛 `「整数除零」`。
2. 数组定长、索引从 **1** 起、越界抛异常；列表可变长、索引同样从 1。
3. `停止循环`/`跳过本次` 只在循环段合法。
4. 标识符不得等于或包含词表词。
5. 文本字面量内符号按字面处理。
6. 普通函数是纯的：不读篇级可变名、不写篇级名；共享状态必须显式传参，或用锁保护后经 `系统：` 段访问。
7. `并且`/`或者` 不混用；混用判错。
8. 输出按 `输出：` 段的声明顺序；语言不规定呈现格式。
9. `匹配` 必须穷尽，缺 `其他：` 判错。**唯一例外**：被匹配者类型为 `联合`/`可选`/`成败` 且成员已全部列出。
10. 类型不隐式窄化，必须 `转换〈T〉【值】`。
11. 泛型单态化，不向运行时保留类型信息（除 `--保留类型信息`）。
12. ARC 在文章层强制；系统层指针不跟踪。
13. 跨线程共享可变状态必须加锁或原子，否则编译报错。
14. `尝试` 必须配 `出错`；`收尾` 可选。
15. 裸机目标默认无标准库、无异常、无 ARC，需显式开启。
16. `系统：` 段不得出现在 `函数：` 之前。
17. `汇编：` 内容不做语法检查，只做长度与目标平台校验。
18. 同篇不得重复定义同名符号；跨篇用 `导入：` 后加 `《篇名》的` 前缀。
19. **容器段必须以 `段结束。` 终止**；缺少或多出都判错。
20. **禁止遮蔽**：内层名不得与外层同名。
21. **不允许块级作用域**：条件句分支内 `记为` 的名字属于所在函数/规则段。
22. **表达式无括号**：需要改变结合顺序时拆成多个赋值句。
23. **前向引用**：篇级名字在整个篇内可见，与出现顺序无关；递归与互递归不需前置声明。局部名仍须先定义后使用。
24. **记录按值传递**：浅复制；标量字段的修改不影响调用方，引用字段（文本、列表）的内容共享。要改标量字段须返回新记录，或系统层传指针。
25. **例段是编译期断言**：`例：` 段体内的赋值不生成运行代码；出现在 `输出：` 段的名的赋值是期望值，其余是输入。例段必须是编译期可求值的。
26. **定长数组的三种定长来源**：字面量（元素个数）、`〈常量〉`（编译期常量）、记录字段声明（随记录布局）。运行期值不得作长度，不能用 `数组` 表达动态长度。
27. **带标签类型必须恰好一个成员激活**：`联合`/`可选`/`成败` 构造时恰写一个成员；读未激活成员是运行时错误，不是未定义行为。`匹配` 的分支内读该分支成员免检查。
28. **字符字面量零半角**：只有 `字符【「单字符」】` 与 `字符【十进制标量值】` 两种形式；`字〈4E2D〉` 一类含半角字母的写法废除。`『』` 无法表达的字符（如 `』`）用后者。

### 1.16 完整样例：文章层

```
《成绩评定》

导入：《数学》。

常数：满分〈整数〉记为300。

记录：考生。
姓名〈文本〉。
三科〈列表〈整数〉〉。

输入：甲〈考生〉。
设定：等级〈文本〉、评语〈文本〉。

导出：评定。

函数：评定，参数为学生〈考生〉，结果为文本。
累计记为0。
位置记为0。
循环：只要位置小于学生的三科的项数。

累计记为累计加上学生的三科的第位置项。

匹配：累计。
情形300：
返回「满分」。
其他：

段结束。
段结束。

规则：
等级记为评定【甲】。
评语记为「等级：」连接等级。
段结束。

```

这份样例的正确性要点：

| 要点 | 体现 |
|---|---|
| 函数纯性 | `累计`、`位置` 是函数局部名，不是篇级 `设定`；函数不碰 `等级`/`评语` |
| 禁止遮蔽 | 局部名与篇级名全体不同名 |
| 容器段收束 | `循环`、`匹配`、`函数`、`规则` 各有自己的 `段结束。` |
| 嵌套深度 | 最深为 `函数`(1) → `循环`(2) 与 `函数`(1) → `匹配`(2)，都在 3 层限制内；`如果` 是句子不是容器段，不计层 |

| 例段绑定 | 例中 `等级`、`评语` 是 `输出：` 声明的名 → 期望值；`甲` 不在输出 → 输入 |
| 索引从 1 | `位置` 从 0 起自增，第一次进循环体即为 1，取 `第1项` |


### 1.17 完整样例：系统层

```
《内核入口》

输入：启动参数〈正整数〉。
设定：页表位置〈正整数〉。

系统：
（关中断、设栈、建立页表。）
汇编：
ldr x0, =栈顶
mov sp, x0
bl 主函数
汇编结束。
页表位置记为转换〈正整数〉【申请内存【4096】】。
如果页表位置等于0，抛出「内存不足」。
段结束。

函数：检查对齐，参数为起始〈正整数〉，结果为空。
如果起始取余4096不等于0，抛出「未对齐」。
段结束。

规则：
检查对齐【页表位置】。
段结束。

输出：页表位置。
```

这份样例的关键点：

| 要点 | 体现 |
|---|---|
| 指针不出系统层 | 篇级 `设定` 用 `正整数` 存地址；`申请内存` 的结果在系统段内立刻 `转换` 成整数 |
| 汇编段在系统段内 | 嵌套 2 层，未超限；汇编内容含半角与空格，**豁免**（1.4.6） |
| 汇编收束 | `汇编结束。` 只收汇编段，`段结束。` 收系统段 |
| 函数不碰硬件 | `检查对齐` 只做算术，可被文章层调用 |
| 零空格 | `如果起始取余4096不等于0` 全紧排 |
| 命名不含词表词 | `页表位置`、`起始` 而非 `页表地址`、`地址`——`地址` 是词表词（1.3.10），取名撞它会被分词器切开 |

> `汇编结束。` 不是词表词，是汇编段的固定收束标记（1.4.6）。`汇编：` 段内不做词法检查，所以 `ldr x0, =栈顶` 里的半角逗号合法。

### 1.18 已知限制（明示，非隐藏）

这些不是「暂时不支持」，是**设计上明确不做**，并且每一条都有替代方案。写在这里是为了不让模型自行发明语法。

## 2. 编译器架构（全自研）

### 2.1 七层流水线

```
源码（.serica）
 │
 ├─① 词法   全角定界 + 词表最长匹配 + 注释/文本/汇编特殊处理  → token 流
 ├─② 语法   段栈驱动递归下降 + 显式段结束配对              → AST
 ├─③ 名字   作用域建立、遮蔽检查、导入解析、导出检查        → 带符号的 AST
 ├─④ 类型   推断 + 标注校验 + 约束求解 + 转换合法性        → 类型标注 AST
 ├─⑤ 单态   泛型实例化                                   → 无泛型 AST
 ├─⑥ 降级   AST → IR（结构化 → 三地址码）                → IR 模块
 └─⑦ 后端   IR → 优化 → 机器码 → 目标格式                → 产物
```

每层都是**纯函数**：`输入 → 输出`，不共享可变状态。这样每一层都能单独跑测试，模型每张卡只改一层。

### 2.2 各层职责边界

| 层 | 只做 | 绝不做 |
|---|---|---|
| 词法 | 切 token、报半角/空格/缩进错误、处理 `「」『』（）汇编` | 判断语法结构 |
| 语法 | 建 AST、配对 `段结束`、检查段序、检查句式 | 判断名字是否存在 |
| 名字 | 建符号表、检查重复/遮蔽/导入/导出 | 判断类型 |
| 类型 | 推断、校验、约束求解、转换检查、ARC 标注 | 生成 IR |
| 单态 | 泛型实例化与去重 | 类型检查（已在④做过） |
| 降级 | AST → IR，插入 ARC/异常/并发指令 | 优化 |
| 后端 | 指令选择、寄存器分配、重定位、产物写出 | 任何语义判断 |

**这条边界表是模型最容易违反的地方**。任务卡若发现模型在词法层判断类型，直接判失败重发。

### 2.3 IR 设计

#### 2.3.1 形式

三地址码，SSA 形式，文本可打印：

```
函数 平方(值: 整数) -> 整数 {
  入口:
    %1 = mul 值, 值
    ret %1
}
```

- 每个值一个 `%n` 编号，全局唯一。
- 基本块以标签开头。
- 指令集固定 52 条（2.3.3），**不得增删**，需增必须走决策记录。

#### 2.3.2 类型标记

| 标记 | 类型 |
|---|---|
| `i8` `i16` `i32` `i64` `i128` | 有符号整数 |
| `u8` `u16` `u32` `u64` | 无符号整数 |
| `f32` `f64` | 浮点 |
| `bool` | 真假 |
| `ptr` | 指针（不区分元素类型） |
| `[]T` | 数组/列表的切片视图 |
| `T*` | 引用（ARC 对象） |
| `void` | 空 |

#### 2.3.3 指令集（52 条，八组）

| 组 | 指令 | 条数 |
|---|---|---|
| 常量 | `const.i` `const.f` `const.str` `const.null` | 4 |
| 变量 | `alloca` `load` `store` `addr` `gep` | 5 |
| 整数 | `add` `sub` `mul` `div` `rem` `and` `or` `xor` `shl` `shr` `not` `neg` | 12 |
| 浮点 | `fadd` `fsub` `fmul` `fdiv` `fneg` `fcmp` `f2i` `i2f` | 8 |
| 比较/控制 | `icmp` `br` `jmp` `switch` `phi` `select` | 6 |
| 函数 | `call` `tail` `ret` | 3 |
| 内存 | `malloc` `free` `memcpy` `memset` `retain` `release` | 6 |
| 并发 | `spawn` `join` `lock` `unlock` `atomic.add` `atomic.xchg` `chan.send` `chan.recv` | 8 |

合计 4+5+12+8+6+3+6+8 = **52**。

例外处理指令（`throw` `landingpad` `resume` `invoke`）单独成组，不计入 52：共 4 条，见 2.3.4。

#### 2.3.4 异常指令（4 条）

| 指令 | 语义 |
|---|---|
| `invoke f(args) to 正常块 unwind 异常块` | 调用并登记展开点 |
| `landingpad` | 异常落地，取得异常对象 |
| `throw %str` | 抛出 |
| `resume` | 重新抛出（未处理） |

#### 2.3.5 IR 不变式

1. SSA：每个 `%n` 只定义一次。
2. 每个基本块以终结指令（`br`/`jmp`/`switch`/`ret`/`throw`/`resume`）结尾。
3. `phi` 只在块首，且入边数等于前驱数。
4. 类型标注必须完整，无隐式转换。
5. `retain`/`release` 只作用于 `T*`。
6. `lock`/`unlock` 在同一函数内成对。
7. `spawn` 的目标必须是 `call` 指令的结果。

`serica ir 文件` 输出必须满足上述七条，CI 用 `tools/验证ir.serica` 检查。

### 2.4 优化 pass（9 个，顺序固定）

| 序 | pass | 作用 | 关掉的开关 |
|---|---|---|---|
| 1 | 常量折叠 | 编译期算尽常量表达式，含 `例：` 断言求值 | `--无折叠` |
| 2 | 死代码消除 | 删除无副作用且结果未用的指令 | `--无死码` |
| 3 | 常量传播 | 把已知常量替换到使用点 | 同上 |
| 4 | 内联 | 小于 40 条 IR 的函数强制内联；`内联：` 段强制 | `--无内联` |
| 5 | 循环不变量外提 | 循环体内不变的表达式提到循环前 | `--无循环优化` |
| 6 | 逃逸分析 | 未逃逸的 ARC 对象改为栈分配 | `--无逃逸` |
| 7 | 引用计数消除 | 删除相邻的 `retain`/`release` 对 | `--无逃逸` |
| 8 | 尾调用 | 尾位置的 `call` 转 `tail` | `--无尾调` |
| 9 | 窥孔 | 局部指令序列替换（如 `add 0` → 删除） | `--无窥孔` |

**顺序不可调**：折叠 → 死码 → 传播 → 内联 → 循环 → 逃逸 → RCO → 尾调 → 窥孔。每一步都依赖前一步的产出。

`-O0` 关闭全部 9 个（`例：` 求值仍执行，因为那是语义而非优化）；`-O1` 开 1–3、9；`-O2` 全开（默认）。

### 2.5 后端结构（十个后端共用一套框架）

```
IR 模块
 ├─ 指令选择       IR → 目标指令（表驱动，每目标一张表）
 ├─ 寄存器分配     线性扫描（贪心，溢出到栈）
 ├─ 栈帧布局       参数、局部、溢出槽、对齐
 ├─ 重定位与符号    目标格式的符号表
 ├─ 汇编输出或直出  先出汇编文本（便于调试），再由内置汇编器转机器码
 └─ 目标格式封装    Mach-O / PE / ELF / .wasm / 扁平二进制
```

**关键决定：后端先出汇编文本，再由自研汇编器转机器码。**

理由：

1. 调试容易——出错能看汇编。
2. 一个汇编器服务所有目标（同架构共享）。
3. 模型写后端时容易验证（对比 `as` 的输出）。

风险：汇编文本往返会丢失信息（如某些伪指令）。缓解：汇编器接受的是**受限子集**，不是完整 GAS 语法，见 2.5.2。

#### 2.5.1 各目标后端差异点

| 目标 | 架构 | 特有难点 |
|---|---|---|
| macOS | arm64/x86_64 | Mach-O 段结构、`__TEXT/__DATA`、ad-hoc 签名、系统调用号 |
| Linux | arm64/x86_64 | ELF 段、`PT_LOAD`、`syscall` 约定、动态链接器路径 |
| Windows | x86_64/arm64 | PE 头、导入表、`kernel32` 调用、SEH 展开表 |
| Web | wasm32 | 栈机器而非寄存器机，寄存器分配阶段要换成「虚拟栈」策略 |
| Android | arm64 | ELF `.so`、JNI 命名约定、`__android_log_print` |
| iOS | arm64 | Mach-O、位码可选、`UIApplicationMain` 桥、禁止 `fork` |
| 鸿蒙 | arm64 | ELF/HAP 打包、鸿蒙 NDK ABI |
| 裸机 ×3 | x86_64/arm64/riscv64 | 无操作系统：自写启动、页表、中断向量、串口输出 |

#### 2.5.2 受限汇编子集

自研汇编器只接受：

- 指令助记符 + 最多 4 个操作数
- 立即数（十进制或 `#0x…`）
- 寄存器名（按目标固定表）
- 标签与 `.` 开头的伪指令：`.section` `.globl` `.align` `.byte` `.word` `.quad` `.asciz` `.space`
- **不接受**：宏、条件汇编、`@` 修饰符之外的复杂表达式、多行续行符

超出子集报错，不做「尽力解析」。

### 2.6 自研清单（白名单与黑名单）

| 必须自研 | 允许外部 | 理由 |
|---|---|---|
| 词法/语法/名字/类型/单态 | 系统调用（`read`/`write`/`mmap` 等） | 无法自研 |
| IR 与 9 个优化 pass | 平台链接器（`ld`/`ld64`/`lld`） | 产物格式复杂，且链接器不是编译器 |
| 汇编器（受限子集） | 平台 SDK（NDK/iOS SDK/鸿蒙 SDK） | 系统 API 定义 |
| ARC 运行时 | 裸机引导 ROM（仅加载，不执行 Serica 代码） | 硬件启动 |
| 异常表展开 | 源语言解析器（**仅转换器**，见 8.3） | 转换器不是产品编译器 |
| 线程/锁/原子/通道运行时 | 种子 Go 工具链（自举后删除） | 临时 |
| 标准库（全部） | — | |
| 格式化、包管理、文档、语言服务 | — | |

**黑名单（出现即判失败）**：

- LLVM / Clang / GCC 作为后端
- 生成 `.c` 再调 `cc`
- 嵌入 CPython / V8 / Node / Lua / libgc
- 用 `cgo` 或 FFI 调用现成编译器
- 把 Serica 编译成 JavaScript 源码（Web 端必须出 wasm，不能出 JS）

> 最后一条要说清：Web 端产物是 `.wasm`，另配一份**手写的、固定的、不随源码变化的** JS 胶水（约 60 行，用于加载 wasm 与 DOM 绑定）。胶水是运行时的一部分，不是编译产物。

### 2.7 自举路径

```
阶段 0   seed/（Go，≤15000 行）编译 → s0
阶段 1   s0 编译 compiler/ → s1
阶段 2   s1 编译 compiler/ → s2
门禁     s1 与 s2 逐字节一致（sha256 相同）
阶段 3   用 s2 编译 std/ 与 tools/ → 全绿
之后     删除 seed/，仓库 grep "package main" 为空
```

#### 2.7.1 自举的三个陷阱

| 陷阱 | 表现 | 预防 |
|---|---|---|
| 种子和自研版语义不一致 | s1 能过、s2 不过 | 阶段 1 前必须让种子通过同一套 500 例一致性 |
| 浮点/整数边界差异 | 相同源码两端结果不同 | 一致性套件覆盖 `i64` 极值、`f64` NaN/Inf、`u64` 溢出 |
| 未定义行为的隐性依赖 | 种子跑对，自研版跑错 | `--严格` 模式禁止一切未定义行为，两版都用它 |

#### 2.7.2 种子语言：Go

种子上限 **15000 行**。选 Go 的四条理由：

1. **自举终点是删除**：种子唯一职责是产出 s0，之后 `s1 == s2` 就删。它不进产品，不值得为它的性能付不稳定代价。
2. **模型改得动**：`qwen3-coder-next` 对 Go 的生成准确率高于 Zig/Rust。种子里会堆大量表驱动代码与位运算，一次写对的比例直接决定进度。
3. **十年后还能编译**：Go 有明确的向后兼容承诺。Zig 至今未发 1.0，语法仍在改，两三年后种子可能编译不过，而种子要活到 M9。
4. **交叉编译够用**：种子只需产出**第一个**后端（macOS arm64）。十个目标是自举后用自研编译器写的；种子不需要扛十端。

Zig 的优势（交叉编译全端、体积小、零运行时）在本方案里都不进产品：用户拿到的是 Serica 自编的产物，没人看到 Go 二进制。

#### 2.7.3 种子的行数分配（预算表）

| 模块 | 预算行数 | 说明 |
|---|---|---|
| `lex` | 1200 | 词表匹配、文本/注释/汇编、诊断 |
| `parse` | 2600 | 段栈、16 句式、AST 定义 |
| `check` | 2800 | 符号表、类型推断、约束、转换 |
| `mono` | 800 | 单态化与去重 |
| `ir` | 1500 | IR 构建、打印、验证 |
| `interp` | 1800 | 解释执行（M3 用，M4 后可删） |
| `codegen`（macOS arm64） | 3000 | 指令选择、寄存器分配、Mach-O |
| `asm`（arm64 汇编器） | 1200 | 受限子集 |
| `main` + 驱动 | 600 | 命令行、错误汇总 |
| **合计** | **15500** | 超 15000 需置换：优先删 `interp` |

**置换优先级**（超预算时按顺序砍）：`interp` → 优化 pass（种子里只保留折叠与死码）→ `asm`（改用系统 `as`，需决策记录）。

### 2.8 零知识构建

`make ci-preflight` 必须在干净容器内通过：

- 不读环境变量做逻辑分支（`HOME`、`PATH` 除外）
- 不依赖本机已装的编译器（白名单：链接器、`as` 若已决策）
- 不依赖网络
- 输出路径不硬编码绝对路径
- 两次构建产物 sha256 一致

失败诊断：

```
文件:build/xxx 错误：构建读取了环境变量 SERICA_TMP
建议：改为命令行参数传入，或使用 --tmp 参数
示例：serica build 文件 -o 产物 --tmp /tmp/serica
```

### 2.9 编译器如何用 Serica 表达自身（M9 自举的落地依据）

编译器要用 Serica 写，就必须能用 Serica 表达「符号表、AST、IR」这些数据结构。这一节给出最小可行写法，M9-01 照此实现。

#### 2.9.1 AST 用枚举 + 记录

Serica 没有继承，用「枚举标签 + 联合」表达变体：

```
枚举：节点种类。
字面量节点。
名字节点。
调用节点。
二元节点。
条件节点。
循环节点。
返回节点。

记录：节点。
种类〈节点种类〉。
文本值〈文本〉。
整数值〈整数〉。
左边〈整数〉。
右边〈整数〉。
子节点〈列表〈整数〉〉。
```

- `节点` 是**扁平记录**，所有字段都有，按 `种类` 决定用哪几个。
- 子节点用**索引**而不是指针（`左边〈整数〉` 是节点列表的下标）。
- 整个 AST 是 `列表〈节点〉`，索引从 1。

为什么不用嵌套记录：Serica 的记录是值类型且不能自我引用（`记录：节点。子〈列表〈节点〉〉` 会无限递归）。扁平 + 索引是唯一可行方案，且缓存友好。

#### 2.9.2 符号表用「列表 + 线性查找」

```
记录：符号。
名字〈文本〉。
种类〈整数〉。
类型名〈文本〉。
作用域深度〈整数〉。

记录：符号表。
条目〈列表〈符号〉〉。
```

- 小作用域（函数级）线性查找足够，实测 < 50 项。
- 篇级符号超过 500 项时按「名字字数」分桶：`桶〈列表〈列表〈符号〉〉〉`，桶下标 = 名字字数。
- 不做哈希表语法（1.18-9）。

#### 2.9.3 IR 用「指令记录 + 文本打印」

```
枚举：指令种类。
常量指令。
加载指令。
存储指令。
加法指令。
…
跳转指令。
调用指令。
返回指令。

记录：指令。
种类〈指令种类〉。
结果号〈整数〉。
操作数一〈整数〉。
操作数二〈整数〉。
文本值〈文本〉。
```

- `serica ir` 就是把 `列表〈指令〉` 逐条打印成文本。
- 两轮自举比对的是**这个文本**（先比文本，再比产物字节）。文本相同而产物不同，说明后端有不确定性（未初始化内存、哈希序、时间戳），必须查。

#### 2.9.4 编译器的段结构

```
《词法》

导入：《诊断》。

导出：切分。

记录：词。
种类〈整数〉。
字面〈文本〉。
行〈整数〉。
列〈整数〉。

函数：切分，参数为源〈文本〉、诊断〈诊断器〉，结果为列表〈词〉。
词表记为《词法表》的加载【】。
结果记为列表【】。
位置记为1。
循环：只要位置不大于源的字数。
…
段结束。
返回结果。
段结束。
```

关键点：

- 编译器分篇，每篇一个阶段，篇间只经 `导出：` 交互。
- 诊断器作为参数传递（不写全局），符合函数纯性。
- 词表是另一篇的常数，`《词法表》的加载【】` 取回。
- 位置、列都从 1 起，与语言本身一致。

#### 2.9.5 自举的第一道坎

**种子编译器必须能编译上述写法的编译器代码。** 这意味着种子要先支持：

| 能力 | 为何必须先有 |
|---|---|
| 记录 + 列表 + 嵌套泛型 `列表〈列表〈符号〉〉` | 符号表分桶 |
| 枚举 + 匹配 | AST 与指令种类 |
| 字符串操作（截取/连接/字数/查找） | 词法与诊断 |
| 泛型（`列表〈T〉` 的取项、追加） | 全部容器 |
| 异常（词法错误） | 诊断 |
| 递归（AST 遍历） | 语法与类型检查 |
| `可选〈T〉` 的构造与 `匹配` 解包（1.8.2.2） | 词法器的「下一个词」，找不到就是 `无值`；类型检查的「推断类型」，推不出就是 `无值`。若没有 `可选`，这两处只能靠哨兵值，是 bug 温床 |
| `成败〈T、E〉` 的构造与 `匹配` 解包（1.8.2.2） | 解析与类型检查的错误**不该抛异常**——一个文件里十个错，编译器要一次全报，不是抛第一个就停 |
| `数组〈整数〉〈N〉` 定长数组 | 词法器的字符分类表（256 项查表）、IR 的定长寄存器映射表。用 `列表` 会引入不必要的堆分配与 ARC 开销 |

这六项就是 M1–M6 的全部内容——**没有它们，编译器写不出来**。所以 M9 不可能提前，也不该提前。

后两项（`可选`/`成败`/定长数组）不是「语法糖」而是**编译器的必需件**：错误必须能批量收集（`成败`），词法器的「没有下一个词」必须能表达（`可选`），字符分类必须零分配（`数组`）。这也反向证明了 v3.1 补齐的类型语法不是可选项。

## 3. 平台（七端 + 三裸机）

### 3.1 平台矩阵

| # | 目标 | 架构 | 产物格式 | 系统接口 | 优先级 |
|---|---|---|---|---|---|
| 1 | macOS | arm64 / x86_64 | Mach-O 可执行 | syscall + libSystem | **P0 首个** |
| 2 | Linux | x86_64 / arm64 | ELF 可执行 | `syscall` | P0 |
| 3 | Windows | x86_64 / arm64 | PE 可执行 | `kernel32` / NT | P1 |
| 4 | Web | wasm32 | `.wasm` | WASI + JS 胶水 | P1 |
| 5 | Android | arm64 | ELF `.so` | JNI + NDK | P2 |
| 6 | iOS | arm64 | Mach-O | iOS ABI + UIKit 桥 | P2 |
| 7 | 鸿蒙 | arm64 | ELF / HAP | 鸿蒙 NDK | P2 |
| 8 | 裸机 x86_64 | x86_64 | 扁平二进制 / ELF | 直接硬件 | P3 |
| 9 | 裸机 arm64 | arm64 | 扁平二进制 | 直接硬件 | P3 |
| 10 | 裸机 riscv64 | riscv64 | 扁平二进制 | 直接硬件 | P3 |

后端开发顺序**严格按优先级**，一次一端。**不允许并行开两个后端**——寄存器分配与 ABI 的 bug 会互相污染。

### 3.2 ABI 约定

#### 3.2.1 通用约定（所有目标）

| 项 | 约定 |
|---|---|
| 整数传参 | 前 6 个（arm64 前 8 个）走寄存器，其余走栈 |
| 浮点传参 | 独立寄存器序列（arm64 `v0-v7`，x86_64 `xmm0-7`） |
| 返回值 | 整数 `x0`/`rax`，浮点 `v0`/`xmm0`；大于 16 字节用隐藏指针 |
| 调用者保存 | 按各平台 ABI |
| 栈对齐 | 16 字节 |
| 布尔 | 1 字节，值只能是 0 或 1 |
| 文本 | 指针 + 长度的胖指针（16 字节） |
| ARC 对象 | 裸指针，头部 8 字节存引用计数 |
| 异常 | 表驱动，不占寄存器 |

#### 3.2.2 文本的内存布局

```
文本值 = { 数据指针: ptr, 字节长度: i64 }

堆块布局：
  [refcount: i64][capacity: i64][bytes...][0]
```

- `容量` 用于 `连接` 时的原地扩展优化。
- 结尾必有 `0`，便于传给 C 接口。
- 空文本是全局单例 `{ptr: 静态空串, len: 0}`，永不释放。

#### 3.2.3 列表的内存布局

```
列表值 = { 数据指针: ptr, 长度: i64, 容量: i64 }

堆块布局：
  [refcount: i64][元素...]
```

- 元素大小由类型决定，编译期已知。
- `追加` 扩容策略：容量不足时翻倍。

### 3.3 统一 IO 抽象（七端解耦的关键）

各端输入输出完全不同：桌面有 stdin/stdout，Web 无 stdin，移动端靠 UI。语言核心必须保持纯净。

#### 3.3.1 三个抽象接口

标准库 `std/输入输出` 定义三个「能力」，各端各自实现：

| 能力 | 签名 | 桌面 | Web | 移动/鸿蒙 |
|---|---|---|---|---|
| `读取文本` | `读取文本【】 → 文本` | stdin 一行 | 绑定的 `<input>` 值 | 绑定的 UI 控件 |
| `写入文本` | `写入文本【文本】 → 空` | stdout | DOM 文本节点 | 日志或 UI |
| `读参数` | `读参数【序号】 → 文本` | `argv[n]` | URL 查询参数 | Intent / Ability 参数 |

#### 3.3.2 平台实现位置

```
std/平台/
├── 桌面.serica      读取文本=stdin，写入文本=stdout
├── 网络.serica      wasm 导入 JS 胶水的三个函数
├── 移动.serica      通过 NDK/JNI 调用宿主提供的回调
└── 裸机.serica      读取文本=串口读，写入文本=串口写
```

编译时按 `--target` 自动选择，源码侧**不需要任何条件编译**。

#### 3.3.3 为什么不做跨端 UI 框架

Dart 靠 Flutter 解决跨端 UI，代价是语言与框架绑定。Serica 的定位是**语言**，不带 UI 框架：

- 移动端 UI 由各端原生写，Serica 编译的 `.so` 被原生代码调用。
- Web 端 UI 由 HTML/CSS 写，Serica 编译的 `.wasm` 负责逻辑。
- 桌面端可选配一个极简的窗口库（P3 之后，不在 1.0 判据内）。

这条边界必须写死，否则语言会被 UI 需求拖死。

### 3.4 各端禁止事项

| 端 | 禁止 | 原因 |
|---|---|---|
| Web | 编译出 JS 源码 | 违反「全自研后端」；且 JS 源码可读性会让人误以为语言只是语法糖 |
| Web | 依赖 `emscripten` | 它是 LLVM 工具链 |
| iOS | `fork` / `exec` | 系统禁止 |
| iOS | 动态生成代码 | JIT 受限，wasm/汇编均不可运行时生成 |
| Android | 直接 `dlopen` 系统私有库 | 版本兼容 |
| 鸿蒙 | 依赖 Android 兼容层 | 不是鸿蒙原生 |
| 裸机 | 依赖任何标准库 | 无操作系统 |
| Windows | 依赖 MSVC 运行库 | 违反零依赖 |

### 3.5 每端验收标准

同一份源码不改，跑通 50 例，输出与 macOS 端**逐字节一致**（Web 端比对 DOM 文本节点，裸机比对串口字节）。

50 例分布：

| 类别 | 例数 | 覆盖 |
|---|---|---|
| 整数算术 | 8 | 加减乘除余、溢出、极值、位运算 |
| 浮点 | 6 | 四则、比较、NaN、Inf、精度 |
| 条件与循环 | 6 | 嵌套、跳出、跳过 |
| 数组与列表 | 6 | 读、写、追加、删除、插入、越界 |
| 记录与枚举 | 5 | 构造、字段读写、匹配 |
| 泛型 | 4 | 单态化、约束 |
| 异常 | 4 | 抛出、捕获、收尾、未捕获 |
| 并发 | 5 | 并行段、锁、原子、通道、手动线程 |
| 文本 | 4 | 连接、截取、字数、比较 |
| IO | 2 | 读取文本、写入文本 |

### 3.6 裸机的三个额外要求

1. **链接脚本**：`boot/<目标>.ld` 定义入口地址与段布局。
2. **中断向量**：`中断【编号】记为处理函数。` 由后端生成向量表。
3. **输出通道**：无 stdout，用串口（x86 用 `0x3F8`，arm64/riscv64 用设备树或固定地址）。`写入文本` 在裸机实现为串口写。

最小内核的出口标准（M8）：

```
qemu 启动 → 打印「Serica 内核启动」→ 建立页表 → 开中断
→ 时钟中断计数到 10 → 打印「中断正常」→ 创建两个线程交替打印 → 停机
```

## 4. 标准库

### 4.1 组织

```
std/
├── 核心/     基本类型操作、断言、错误
├── 文本/     连接、截取、查找、替换、大小写、编码
├── 列表/     追加、删除、插入、排序、查找、切片
├── 数组/     定长数组操作
├── 数学/     整数、浮点、三角、对数、幂、随机
├── 时间/     单调时钟、墙钟、格式化
├── 输入输出/ 读取文本、写入文本、读取参数、文件
├── 平台/     各端实现（3.3.2）
└── 系统/     内存、线程、锁、原子、通道（薄封装）
```

每个目录一个篇（`.serica` 文件），篇名与目录同义。

### 4.2 命名规则

- 全部汉字，双字或三字：`文本长度` 不行（`长度` 不是词，且 `文本` 是词），用 `字数`；`查找子串` 也不用，用 `寻找子串`。
- 动词在前：`截取`、`追加`、`寻找子串`。
- 查询用「名 + 的 + 属性」：`列表的项数`。
- 不缩写：`随机整数` 不写 `rand`。
- **名字若含词表词，必须登记进内置名表（1.4.1）**，否则分词器会切开它。

### 4.3 最小可用集（M4 前必须有）

> 标记 ★ 的名字**含词表词**，必须进内置名表（1.4.1），否则分词器会切开。这些名字已在 1.4.1 的清单里登记。

| 篇 | 必须函数 |
|---|---|
| `核心` | `断言`、`终止` |
| `文本` | `连接`、`截取`、`字数`、`寻找子串`、`替换子串`、`比较文本`、★`文本化`、★`转换整数`、★`转换小数` |
| `列表` | `追加`、`删除`、`插入`、`项数`、`排序列表`、`寻找列表` |
| `数学` | `绝对值`、`最大值`、`最小值`、`平方根`、`幂`、`取整`、★`随机整数` |
| `输入输出` | ★`读取文本`、★`写入文本`、★`读取参数`、★`写入错误` |
| `系统` | `申请内存`、`释放内存`、★`当前时间`、`休眠` |

> **改名说明（v3.1）**：`转整数`/`转小数` 改为 `转换整数`/`转换小数`，与词表词 `转换` 同族，读起来一致；`读文本`/`写文本` 改为 `读取文本`/`写入文本`（`读`、`写` 单字太短，且 `读`+`文本` 会切在 `文本` 前）；`查找` 拆成 `寻找子串`（文本篇）与 `寻找列表`（列表篇）——原来两篇同名 `查找`，跨篇调用必须写前缀，反而不如一开始就不同名。这一批都登记进内置名表。

其余函数可在 M6–M7 补齐，但**每个函数必须有 `例：` 段**。

### 4.4 标准库的编写规范

- 用 Serica 写，不用种子语言写。
- 唯一例外：直接包系统调用的最小桩（如 `write` 系统调用），写在 `runtime/` 里用汇编或系统层 Serica。
- 每个函数 ≤ 40 行。
- 每个函数至少 1 正例 1 反例（反例指「非法输入应抛出什么」）。
- 不依赖平台差异，差异藏在 `std/平台/`。

#### 示例 11：安全除法与查找（可选 + 成败 + 定长数组）

这个程序把 v3.1 补的三样东西一次用全，也是编译器自己写错误处理时的模板。

```
《安全计算》

常数：表长〈整数〉记为4。

输入：键〈整数〉。
设定：分类表〈数组〈整数〉〉、商〈整数〉、说明〈文本〉。

如果表的第位置项等于要找，返回可选【有值：位置】；否则，占位记为位置。

段结束。
返回可选【无值】。
段结束。

匹配：找位置【分类表、键】。

段结束。
段结束。

```

要点：

| 写法 | 说明 |
|---|---|
| `数组〈整数〉【10、20、30、40】` | 定长数组字面量，长度由元素个数决定（1.8.2.1） |
| `找位置，参数为表〈数组〈整数〉〉` | 数组是**值类型**，传参时整体复制；16 字节以下的拷贝由优化 pass 消除 |
| 函数里读 `表长` | `常数：` 允许读（语义规则 6 只禁**可变**篇级名）。若写成 `表的项数` 也可以，不必依赖常数 |
| `可选【有值：位置】` / `可选【无值】` | 可选构造，两种成员（1.8.2.2） |
| `情形有值：` / `情形无值：` | 成员已列全，**省了 `其他：`**，这是唯一允许的场合 |
| `安全除【100、10】的成功` | 成败取值。写成 `.成功` 一律判错 |
| `返回可选【无值】` 在循环之后 | 循环里没提前返回才走到这里，即「找不到」 |
| `否则，占位记为位置。` | 条件句强制成对的占位分支，用**本地名** |

> **为什么占位分支不能写 `说明记为「继续」`**：`说明` 是篇级 `设定`（可变），函数写它就是违反语义规则 6，报 `E5001`。但条件句又强制成对，空分支必须有个句子。这是模型最容易犯的错——它会顺手抓一个「看起来合适」的已存在名字来填空分支，而那个名字往往是篇级的。
>
> 同理，`找位置` 不能直接读篇级 `分类表`，必须把它**作为参数传进去**。示例第一版就是这么写错的，读者可以拿它当反例：只要函数体里出现篇级 `设定` 的名字，无论读写，都是 `E5001`。
>
> 推演结论：**空分支的占位必须用一个本地名**，且这个本地名真被赋值也无害（`占位` 不参与任何计算）。这是零隐式分支的必然代价，写进 M4-02 的正反例对。

### 4.6 这十一个示例暴露的五个规格点

写这十一个程序时发现的问题，必须在 M0-02（规格冻结）前定死，否则模型写真实程序时必然撞上：

| # | 规格点 | 结论 | 落点 |
|---|---|---|---|
| 1 | 函数前向引用 | **允许**。篇级名字在整个篇内可见，与出现顺序无关；递归、互递归都不需要前置声明 | 1.9.5 |
| 2 | `并行：` 段只能写赋值句 | **保留**。段内每条必须是「名记为项」，名的类型必须与右侧返回类型一致；返回 `空` 的函数要赋给 `空` 类型的名 | 1.6.5 |
| 3 | 函数不能修改值类型参数 | **保留并写死**。记录是值类型，按值传递；要改状态只能「记录里放引用类型字段」或「系统层传指针」。不假装能改 | 1.8.3 |
| 4 | 遍历列表要写 3 句 | **不修**。加 `遍历：` 标签会破坏词表封版；十一个示例证明 3 句可读 | — |
| 5 | 空分支的占位句 | **必须用本地名**。条件句强制成对，禁用篇级名填空（模型最高频错误） | 示例 11、M4-02 |

前三条已写进正文：1.9.5（前向引用）、1.6.5（并行段约束）、1.8.3（值类型传参）。第 5 条见示例 11 的要点表。

## 5. 工具链

### 5.1 命令一览

```
serica lex   <文件>              输出 token 流
serica check <文件>              词法 + 语法 + 名字 + 类型
serica ir    <文件>              输出 IR 文本
serica build <文件> -o <产物> --target <目标> [-O0|-O1|-O2]
serica run   <文件> [--参数 …]   编译并运行
serica fmt   <文件> [--check]    格式化
serica doc   <文件>              生成阅读版（HTML）
serica test  <目录>              跑例段
serica pack  <目录>              打包
serica lsp                      语言服务（stdio）
```

全局开关：

| 开关 | 作用 |
|---|---|
| `--严格` | 禁止一切未定义行为，自举与 CI 必开 |
| `--检查泄漏` | 运行时统计未释放块 |
| `--无异常` | 裸机用，`抛出` 变终止 |
| `--启用自动内存` | 裸机打开 ARC |
| `--保留类型信息` | 保留泛型实例的类型名（调试用） |
| `--目标 <目标>` | 见 3.1 |
| `--诊断格式 简/详` | 默认详（三行） |

### 5.2 格式化器（`serica fmt`）

规则固定，无配置项（配置项是团队争吵的源头）：

| 项 | 规则 |
|---|---|
| 顶格 | 所有行不加缩进 |
| 空行 | 段与段之间恰好一个空行；容器段内句子之间不空行 |
| 句号 | 每句独占一行（`如果…；否则，…。` 也算一句，可一行） |
| 段结束 | `段结束。` 单独一行 |
| 逗号 | 全角 `，` 后不加空格（因为没有空格） |
| 长句 | 超过 80 字不换行（换行会破坏「一行一句」）；宁可拆句 |
| 数字 | 小数点归一为 `．` |
| 注释 | 保留原位置，不重排 |

`--check` 只报告不修改，退出码 1 表示需要格式化。

**幂等性要求**：`fmt` 两次结果必须相同。CI 用 `fmt --check` 验证。

### 5.3 包管理（`serica pack`）

极简设计，不做版本求解器：

```
篇依赖声明写在文件末尾：
依赖：《数学》1．2、《文本》2．0。
```

- 版本号是 `主．次`，不引入补丁号（补丁号会诱使频繁发版）。
- `serica pack 目录` 读取全部 `依赖：`，生成 `依赖锁.txt`。
- 包源是本地目录或 Git 仓库地址，不做中心仓库（1.0 前）。
- 无循环依赖：编译器检测并报错。

### 5.4 文档生成（`serica doc`）

从源码的 `例：`、`函数：`、注释生成 HTML：

- 篇名 → `<h1>`
- 每个函数 → 一节，含签名、注释、例段
- 例段渲染为「输入 / 期望输出」表格
- 版式默认为中文论文风格（宋体、段首空两格、行距 1.5）

这是「代码即文档」的落地：例段既是测试，又是文档。

### 5.5 语言服务（`serica lsp`）

提供四个能力，不做更多：

| 能力 | 说明 |
|---|---|
| 诊断 | 保存时推送错误（复用编译器的诊断） |
| 跳转定义 | 名字 → 声明位置 |
| 悬停 | 显示类型与注释首句 |
| 补全 | 只补词表词与当前作用域内的名字 |

不做：重命名、重构、内联提示、语义高亮以外的着色。理由：这些功能维护成本高，且中文编辑器生态尚不成熟。

### 5.6 测试框架（`serica test`）

利用 `例：` 段，不需要额外断言库：

```
serica test tests/一致性/正例/
```

- 每个文件的 `例：` 段被执行，不符则报错。
- 反例目录里每个文件期望**编译失败**，失败即通过。
- 输出格式：

```
通过 47 / 50
失败 3：
  排序.serica:12 例失败：期望「3」，得到「4」
  二分.serica:8 编译失败：未知名字「中间」
  栈.serica:31 运行时异常未捕获：「下标越界」
```

### 5.7 模型产出首检（M0-04 交付物）

`serica check` 之前先用这个脚本兜一遍，把「模型惯性错误」在 1 秒内挡掉。它不做语义分析，只看表层纪律。

```
工具：tools/首检.py（约 80 行，Python 写，属开发工具非产品）
```

检查顺序与退出条件：

| 序 | 检查 | 输出 | 是否阻断 |
|---|---|---|---|
| 1 | 半角符号（`0-9`、数字内 `.` 除外） | `L12 第8列 半角「,」` | 是 |
| 2 | 空格 / Tab | `L12 第22列 空格` | 是 |
| 3 | 行首空白（缩进） | `L12 行首缩进` | 是 |
| 4 | 行尾空白 | `L12 行尾空白` | 是 |
| 5 | 词表外「XX：」标签 | `L20 未知段标签「说明：」` | 是 |
| 6 | 表达式括号 `（…）` 出现在句子中（非整行注释） | `L30 疑似表达式括号` | 警告 |
| 7 | 容器段数量 vs `段结束。` 数量 | `容器段 4 个，段结束 3 个` | 是 |
| 8 | `输出：` 段数量 ≠ 1 | `输出段 2 个` | 是 |
| 9 | 文件末尾无换行 | `文件末尾缺换行` | 是 |
| 10 | 汇编段外的 `汇编结束。` | `L44 孤立「汇编结束。」` | 是 |

为什么单独做这个脚本而不是直接跑编译器：M0 阶段编译器还不存在；M1 之后它仍然有用——`serica check` 的报错更详细但更慢，首检能在模型自检的第一次循环里快速否掉明显违规，省一轮往返。

**这个脚本本身不算产品**，不进 `tools/` 的发布包，只在仓库开发期使用。它的检查逻辑在 M1-01 之后应逐步被词法器吸收，最终退役。

## 6. 面向 qwen3-coder-next 的工作流

### 6.1 模型特性与对策

| 模型特性 | 后果 | 对策 |
|---|---|---|
| 上下文 64k | 塞不下整本手册 | 一次一卡，只给相关章节 |
| 单次输出约 300 行 | 大文件写不完 | 单文件 ≤ 300 行，硬规定 |
| 中文理解强 | 中文规格即最好的提示词 | 规格直接当提示词，不翻译成英文 |
| 易幻觉 API | 编造不存在的函数 | 任务卡给「符号出处：文件:行」 |
| 易自创语法 | 写 `if(){}`、`a.b`、`a[i]` | 60 条反例 + 系统提示词硬禁止 |
| 不会自验证 | 说「已完成」但没跑 | 强制贴命令、退出码、关键输出 |
| 长任务漂移 | 做着做着偏离卡片 | 每步复述目标；偏离即 BLOCKED |
| 不知何时停 | 顺手改别的文件 | 只改卡内文件，超范围即失败 |

### 6.2 任务卡格式（六项，缺一不可）

```
【卡号】M4-03
【目标】一句话，可判定
【改哪些文件】绝对路径，最多 3 个
【规格依据】手册章节号 + 相关文件:行
【正例】2 条，可直接编译
【反例】2 条，必须报错
【验收命令】命令 + 预期退出码 + 关键输出行
```

**卡的质量标准**：

- 目标能用「是/否」判定，不能写「优化一下」
- 正例能直接粘进文件编译通过（不是伪代码）
- 反例对应的错误信息要写出来（模型才知道该报什么）
- 验收命令必须是单条可复制执行的

### 6.3 上下文预算（64k 分配）

| 项 | 预算 | 说明 |
|---|---|---|
| 系统提示词 | 1.5k | 6.5 全文 |
| 语言规格节选 | 6k | 只给当次卡涉及的 1–2 节 |
| 任务卡 | 1k | 六项 |
| 现有源码 | 12k | 只给要改的文件 + 直接依赖 |
| 测试与样例 | 3k | 相关正反例 |
| 余量 | 40k | 留给模型输出与多轮修复 |

**超预算就拆卡**。经验值：一张卡涉及超过 3 个文件，或规格超过 8k，必须拆。

### 6.4 单卡循环

```
1. 读卡
2. 复述：改什么、验收命令、预计行数
3. 列符号：要用的函数/类型 + 「文件:行」出处
4. 写完整文件（不是 diff）
5. 自跑五步链，贴命令与退出码
6. 不过 → 分类（语法/类型/IR/后端/测试）→ 修 → 重跑，≤3 轮
7. 3 轮仍不过 → BLOCKED + 已排除的可能 + 缺什么信息
```

五步链：

```
serica lex   文件        → 无错误
serica check 文件        → 无错误
serica ir    文件        → IR 通过七条不变式
serica build 文件 --target macos -O0 → 产物存在
产物运行                 → 输出符合例段期望
```

### 6.5 系统提示词（全文，直接粘贴）

```
你在 Serica 仓库工作。Serica 是一门中文系统级语言：

- 全角标点定界，零空格，顶格，段标签分块，容器段以「段结束。」收束。
- 编译到七端（macOS/Linux/Windows/Web/Android/iOS/鸿蒙）与三种裸机。
- 除临时种子（Go）外全部自研：词法、语法、类型、IR、优化、后端、运行时、标准库。

你一次只做一张卡，只改卡里列出的文件。

硬规则：
1. 只用词表内的词（手册 1.3，共 115 条目）与内置名表内的名（手册 1.21）。两表之外的写法必须报错，不许「理解后放行」。
2. 禁半角符号，唯一例外是 0-9 与数字内小数点。
3. 禁文言单字：得、之、收、列、连、当、若、则、且、或、为、其、此。
4. 赋值用「记为」，比较用「等于/不等于/大于/小于/不大于/不小于」。
5. 文章层不许出现指针、地址、申请内存、系统调用、汇编；这些只在「系统：」段内。
6. 泛型用「通用〈甲型〉」，调用靠推断，不许写显式类型参数。
7. 异常必须「尝试：…出错：…」，「收尾：」可选；「收尾：」内不许「返回」。
8. 跨线程共享可变状态必须加锁或原子，否则编译器会报错。
9. 容器段必须有「段结束。」；缩进判错；出现空格判错。
10. 表达式没有括号。需要改结合顺序就拆成两个赋值句。
11. 条件句必须成对写「；否则，…」。空分支用**本地名**占位，绝不许拿篇级名填空。
12. 定长数组用「数组〈整数〉【1、2、3】」或「数组〈整数〉〈3〉」；长度必须编译期常量，运行期长度用「列表」。
13. 可选/成败用「可选【有值：7】」「成败【成功：7】」构造，用「匹配」+「情形有值/无值/成功/失败」解包；成员列全可省「其他：」。
14. 字符字面量只有「字符【「中」】」与「字符【20013】」两种；不许写任何含半角字母的形式。
15. 名字不许含词表词，也不许等于「有值/无值/成功/失败」。
16. 不改卡外文件，不加依赖，不调 LLVM/C/解释器，不生成 .c。
17. 每次改完自跑五步链，贴命令、退出码、关键输出行。
18. 规格与实现冲突：以规格为准，报 DRIFT，不擅自改规格。
19. 不确定就输出 BLOCKED + 缺什么信息。

输出四段，只输出这四段：
A 复述：改什么、验收命令、预计行数
B 符号：要用的函数/类型 + 「文件:行」出处
C 完整文件：每块第一行写路径
D 验证：命令、退出码、关键输出行
```

## 8. 转换器

### 8.1 定位

把其他语言的程序转成 Serica 源码，**保留可读性与结构**，不做运行时兼容层。

不是「让 Python 程序在 Serica 上跑」，而是「把 Python 程序改写成 Serica 程序，人还能读懂」。

### 8.2 优先级

| 级 | 源语言 | 为什么这个顺序 |
|---|---|---|
| P0 | Python | 标准库 `ast` 零依赖；语法接近白话，映射直观；用户基数最大 |
| P0 | C | 系统级语言必须能接 C；指针/结构体/位运算全覆盖 |
| P1 | JavaScript | 去原型链后映射简单 |
| P1 | Java / C# | 类 → 记录 + 函数；接口 → 泛型约束 |
| P2 | Go / Rust | 并发模型差异大，放到后面 |

### 8.3 架构

```
源文件
 ├─ 源 AST
 │   ├─ Python：用标准库 ast（白名单允许）
 │   ├─ C：自写子集解析器（约 2000 行，Serica 写）
 │   └─ 其他：各自前端
 ├─ 能力判定：可转 / 需系统层 / 不可转
 ├─ 映射：源 AST → Serica AST
 ├─ 降级：Serica AST → 源码文本
 └─ 报告：跳过的行、降级构造、需人工处理的段
```

**为什么允许用 Python 的 `ast`**：转换器不是产品编译器，它不参与自举链，产物是 Serica 源码。用现成解析器不违反「全自研」——那条红线约束的是编译器。这一点必须在决策记录里写清，否则会被误判为套壳。

### 8.4 构造映射表

| 源构造 | Serica | 备注 |
|---|---|---|
| `x = 1` | `甲记为1。` | 名字要转成汉字（见 8.5） |
| `x: int = 1` | `甲〈整数〉记为1。` | |
| `if c: … else: …` | `如果<条件>，…；否则，…。` | 分支多于 1 句用 `，` 分隔 |
| `elif` | 嵌套条件（抽函数） | 转换器自动生成辅助函数 |
| `while c: …` | `循环：只要<条件>。` + `段结束。` | |
| `for i in range(n)` | `循环：只要序号小于n。` + `序号记为序号加上1。` | |
| `for x in list` | 同上，用 `第序号项` | |
| `break` / `continue` | `停止循环。` / `跳过本次。` | |
| `switch` / `match` | `匹配：` + `情形` | |
| `try/except/finally` | `尝试：/出错：/收尾：` | 异常变量 `e` → `错误` |
| `raise` | `抛出<文本>。` | 非文本异常需 `文本化` |
| `def f(a, b):` | `函数：f，参数为甲〈整数〉、乙〈整数〉，结果为整数。` | |
| `class X:` | `记录：X。` + 方法转函数（首参为 `自身`） | 不做继承 |
| `struct` | `记录：` | |
| `union` | `联合：` | |
| `enum` | `枚举：` | |
| `template<typename T>` / `def f[T]` | `通用〈甲型〉：` | |
| `int* p` | `指针〈整数〉` + 自动包 `系统：` | |
| `*p` / `&x` | `指针的取值` / `甲的地址` | |
| `malloc` / `free` | `申请内存` / `释放内存` | |
| `float` / `double` | `小数32` / `小数` | |
| `list` / `[]` | `列表〈T〉` | |
| `dict` | `列表〈记录〉` + 线性查找函数 | 无哈希表语法，见 8.6 |
| `lambda` | 具名函数 + 函数指针 | |
| `+=` `-=` | `甲记为甲加上乙。` | |
| `++` `--` | 同上 | |
| `&&` `\|\|` `!` | `并且` `或者` `不是` | |
| `==` `!=` `<` `>` `<=` `>=` | `等于` `不等于` `小于` `大于` `不大于` `不小于` | |
| `print(x)` | `写入文本【文本化【x】】。` | |
| `str(x)` | `文本化【x】` | |
| `len(s)` | `字数` | 数组/列表用 `项数` |
| `s[i]` | `甲的第<序号>项`（索引 +1） | **索引基数不同**，见 8.6 |

### 8.5 名字转换

源语言标识符要转成汉字名。三种策略，按顺序尝试：

| 策略 | 做法 | 例 |
|---|---|---|
| 1 词典 | 常见词查内置词典（约 500 条） | `count` → `计数`，`name` → `姓名` |
| 2 拼音 | 词典未命中，转拼音首字母 + 原词标注 | `buffer` → `缓冲`（词典有）；`ptr2` → `指针2` |
| 3 保留 | 仍不行，用 `名1`、`名2` 顺序编号 + 注释写原名 | `（原名：xyz。）` |

**硬约束**：转换后的名字不得包含词表词（1.3.12）。若源名含 `if`、`for` 等，词典必须映射到不含词表词的汉字组合。

### 8.6 语义差异必须报告

转换器不是翻译器，这些差异必须写进报告让人复核：

| 差异 | 说明 | 报告内容 |
|---|---|---|
| 索引基数 | Python/C 从 0 起，Serica 从 1 起 | 每处下标 +1，列出全部改写点 |
| 整数宽度 | Python 任意精度 → Serica i64 | 提示可能溢出 |
| 除零 | Python 抛异常 → Serica 也抛，但文本不同 | 列出异常文本变化 |
| 字符串不可变 | Python 不可变 → Serica 不可变（一致） | — |
| 字典 | 无哈希表语法 | 降级为线性查找，提示性能影响 |
| 类继承 | 不支持 | 展开为记录 + 独立函数，提示手动调整 |
| 闭包 | 不支持 | 转成「记录 + 函数」，捕获变量变成字段 |
| 生成器 | 不支持 | 转成「列表 + 循环」，提示内存变化 |
| 垃圾回收时机 | Python 引用计数 + 分代 → Serica 纯 ARC | 循环引用需手动加 `弱引用` |
| 异常类型 | 类型化异常 → 文本 | 列出全部异常类型映射 |

### 8.7 不可转（仅四类）

| # | 特性 | 原因 | 处理 |
|---|---|---|---|
| 1 | `goto` 跨函数 | Serica 无 goto | 报 `UNSUPPORTED`，提示手动重构 |
| 2 | `setjmp` / `longjmp` | 无此机制 | 报 `UNSUPPORTED` |
| 3 | 复杂宏展开 | 无预处理器 | 报 `UNSUPPORTED`，提示手工展开 |
| 4 | 编译器内建 `__builtin_*` | 无对应 | 报 `UNSUPPORTED`，给出等价 Serica 写法建议 |

**其余全部必须能转**。做不到就改转换器，不是加第 5 条不可转。

### 8.8 验收标准

1. 转换产物通过五步链（6.4）
2. 同一组输入，输出与原程序**逐字节一致**
3. 差异报告完整：跳过的行、降级构造、需人工处理的 `系统：` 段、索引改写点
4. 通过样本：3 个 C（≥200 行，含指针与结构体）+ 3 个 Python（≥100 行，含类与异常）
5. 转换器自身有用例：50 个小片段，每个片段对应一条映射表规则

### 8.9 转换器的边界

明确不做：

- 不做源码级双向同步（改了 Serica 不回写原语言）
- 不做运行时兼容层（不提供 Python 的 `list` 语义）
- 不做库迁移（`import numpy` 无法自动转）
- 不保证性能等价（只保证行为等价）

| L5 端到端 | 十目标 × 50 例 | `make test-all` | ≥ 500 |

合计 ≥ 970 例，超出 0.2 要求的 500 例。

### 9.2 一致性套件

`tests/一致性/cases.json` 是唯一事实源：

```json
{
  "version": 1,
  "total": 500,
  "cases": [
    {
      "id": "lex-001",
      "kind": "lex",
      "file": "正例/算术.serica",
      "expect": "ok"
    },
    {
      "id": "parse-014",
      "kind": "parse",
      "file": "反例/条件缺否则.serica",
      "expect": "error",
      "error_contains": "缺少「否则」"
    }
  ]
}
```

规则：

- `total` 只能增不能减。减少需要决策记录。
- CI 从 `cases.json` 读总数，不硬编码。
- 每个 `error_contains` 必须是稳定的短句，不含行号（行号会变）。

### 9.3 诊断格式（固定三行）

```
文件:行:列 错误：<原因>
建议：<改法>
示例：<正确写法>
```

规则：

- 行列从 1 起，列按**字符**而非字节计（中文一字一列）。
- 原因必须说「错在哪」，不说「invalid syntax」。
- 建议必须给可执行动作。
- 示例必须是一行能编译的正确代码（或标注「见 1.16」）。
- 警告用 `警告：`，不阻断编译。
- 允许在「错误：」前加**稳定代号**（`E1001`），便于一致性套件匹配；代号不进用户可见文案的主体，放在行尾括号里可选。

## 10. 原创性论证（反套壳）

### 10.1 判定标准

**若 Serica 源码能逐行机械翻译成另一门语言且无需重构，就是套壳。**

「机械翻译」指：保持语句数量一一对应、结构一一对应、不需要重新组织逻辑。

### 10.2 逐维对照

| 维度 | C / Go / Rust | Serica | 能否机械对应 | 为什么不能 |
|---|---|---|---|---|
| 块结构 | `{}` 或缩进 | 段标签 + `段结束。` | 否 | `{}` 是嵌套作用域，段是**顺序区域**且可有多个同类段并列 |
| 定界 | 空格 + `;` | 全角标点，零空格 | 否 | 无 `;`，句终靠 `。`；词边界靠虚词不靠空格 |
| 类型标注 | `int x` / `x: i32` | `甲〈整数〉` 后置 + 全角尖括号 | 否 | 语法位置与符号都不同 |
| 调用 | `f(a, b)` | `f【甲、乙】` | 否 | `【】` 与 `（）` 分工不同（后者是注释） |
| 数组访问 | `a[i]` | `甲的第i项` | 否 | 自然语言短语，且索引从 1 |
| 成员访问 | `a.b` | `甲的姓名` | 否 | 用「的」连接，无点号 |
| 表达式 | 任意嵌套括号 | 强制拆句 | 否 | 多步运算被强制展开为具名中间量 |
| 异常 | `try/catch` | `尝试：/出错：/收尾：` 段 | 否 | 段结构，不是语句块；错误变量固定 |
| 并发 | `go f()` / `thread` | `并行：` 段 + 隐式 join | 否 | 段级并发，join 是段结束的语义 |
| 泛型 | `template<T>` / `<T>` | `通用〈甲型〉` | 否 | 类型参数名是汉字占位词 |
| 内存 | 手动 / 所有权 | ARC 默认 + `系统：` 段手动 | 否 | 分层由段决定，不是类型注解 |
| 系统编程 | 关键字（`unsafe`） | `系统：` 段 | 否 | 段级隔离，非表达式级标记 |
| 编译链 | LLVM / GCC | 自研 52 指令 IR + 十后端 | 否 | 无第三方中间层 |
| 模块 | `import` / `mod` | `导入：` + `《篇名》的` | 否 | 书名号前缀是语法的一部分 |

### 10.3 与已有中文语言的差异（必须交代）

| 语言 | 做法 | 与 Serica 的差异 |
|---|---|---|
| 易语言 | 中文关键字替换英文，沿用 C 骨架，靠可视化 IDE | Serica 零空格、标点定界、无 IDE 依赖 |
| 文言（wenyan-lang） | 文言文句式，编译到 JS | Serica 用现代书面白话，编译到机器码 |
| 段言（duan） | 词句段篇，用空格与缩进 | Serica 零空格、无缩进、`段结束。` 显式收束 |
| Inform 7 | 英语整句 + 句号 | Serica 用中文，且封闭词表 + 全角定界 |
| CNL/ACE | 受控自然语言，用于知识表示 | Serica 是通用编程语言，有 IR 与十个后端 |

**不宣称「完全无先例」**。段标签、整句编程、封闭词表都有先例；Serica 的组合（零空格 + 全角定界 + 段结束收束 + 双层系统段 + 例段断言 + 十后端自研）目前没有看到等价物。

### 10.4 三个可检验的反套壳测试

| 测试 | 做法 | 通过标准 |
|---|---|---|
| 机械翻译测试 | 取 1.16 样例，尝试逐行译成 C | 无法保持语句一一对应（段、`的`、`第n项` 都要重构） |
| 符号替换测试 | 把全部汉字换成英文单词，看是否变成已知语言 | 结果既不是 C 也不是 Python，段结构无处对应 |
| 后端独立性测试 | 检查产物是否含 LLVM/`.c`/解释器 | `otool`/`objdump` 只见自研符号；`strings` 无 `LLVM` |

## 11. 风险与取舍

### 11.1 风险表

| # | 风险 | 可能性 | 影响 | 对策 |
|---|---|---|---|---|
| 1 | 十个后端工作量压垮进度 | 高 | 高 | IR 先行；一次一端；每端 50 例卡门 |
| 2 | ARC 循环引用泄漏 | 中 | 中 | `弱引用` + `--检查泄漏` + 逃逸分析 |
| 3 | 异常零成本难实现 | 中 | 中 | 先在 macOS 验证表驱动；裸机可用 `--无异常` |
| 4 | 自举时种子与自研语义不一致 | 高 | 高 | 阶段 1 前种子必须过同一套 500 例；`--严格` 双跑 |
| 5 | 模型被复杂度压垮 | 高 | 中 | 单文件 ≤ 300 行；单卡 ≤ 3 文件；系统提示词硬约束 |
| 6 | 词表膨胀失控 | 中 | 高 | 词表封版；新增必须决策记录 + 人签字 |
| 7 | 裸机引导卡住 | 中 | 中 | 先用 QEMU 的 `-kernel` 直载，自研 bootloader 后置 |
| 8 | 中文标识符影响工具生态 | 中 | 低 | 自研全部工具（fmt/doc/lsp），不依赖外部 |
| 9 | Web 端 wasm 缺 GC，ARC 要自带 | 中 | 中 | ARC 本就是自研，wasm 端不依赖宿主 GC |
| 10 | 转换器被当成「兼容层」期待 | 中 | 低 | 8.9 明确边界，不做运行时兼容 |

### 11.2 必须接受的代价

1. **源码行数约为等价 C 的 1.3–1.8 倍**。拆句、具名中间量、显式 `段结束。` 都要占行。
2. **没有表达式括号**，复杂算式要拆成多行。这是零歧义的代价。
3. **中文标识符无法用 grep/正则友好检索**（没有词边界）。必须用 `serica` 自带工具搜索。
4. **编辑器生态必须自建**。VS Code 插件、语法高亮、LSP 都要自己写。
5. **十个后端意味着十套 ABI 测试**。每加一个平台，测试矩阵翻倍。
6. **系统层有学习成本**，但只对写内核/运行时的人；应用开发者可以一生不碰。
7. **种子是 Go**，M9 之前仓库里始终有 Go 代码。这是「全自研」唯一的临时缺口，且缺口有明确到期点。

### 11.3 三个不能妥协的点

如果进度压力大，可以砍功能范围，但这三条不能动：

1. **零空格 + 全角定界**。这是语言的身份证，动了就变成「中文关键字版 C」。
2. **段结束显式收束**。没有它，段嵌套无解，语言会退化成缩进敏感。
3. **IR 先于后端**。跳过 IR 直接写十个后端，等于写十个编译器。

#### 12.3.1 一份写满的示例（照此格式写）

```
编号：D-0005
标题：数组与列表索引从 1 起
状态：接受
日期：2026-11-27
背景：
  自然语言说「第1项」「第3个」，英文语言从 0 起是历史惯性（指针偏移），
  不是可读性选择。若从 0 起，用户每次读代码都要在心里加 1。
决定：
  数组与列表的下标一律从 1 起。第1项是首项。
  越界（0 或大于项数）抛「下标越界」。
边界：
  不为兼容 C 习惯提供从 0 起的模式；转换器负责把源语言下标 +1。
  内部 IR 的 `gep` 仍按字节偏移，与语言层无关。

  `甲记为三科的第0项。`          → 报 E5009「索引从 1 起」
  `循环：只要位置不大于三科的项数。` 里若位置从 0 起，会漏首项 → 教程要求自增在前
验收：
  `serica test tests/一致性/反例/索引零.serica` 必须报 E5009。
  `serica run 示例3.serica` 输出 55（累加 1..10）。
影响：
  1.7.1、1.8.2、8.6（转换器下标改写）、4.5 示例 3/4/9
签字：<人名>
```
