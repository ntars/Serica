## 项目简介

主流编程语言的词边界依赖空格与半角标点，中文书写不使用空格，句读由全角标点承担。以此为起点，Serica 把中文的书写习惯直接作为语法规则：不留空格、不用缩进、句终用 `。`、列举用 `、`、调用与构造用 `【】`、类型标注用 `〈〉`。源码自上而下顶格书写，读源码与读一段说明文字在排版上没有区别。

语言采用**受控自然语言**（Controlled Natural Language，CNL）：词表封闭，句式固定，表层结构与被编译的逻辑一一对应。词表共 115 个条目、112 个词形，分 11 组；除数字 `0-9` 与小数点外不使用任何半角字符。词表之外不设关键字，也不允许实现方「理解后放行」。

语言是**完全体系统级语言**，并非教学玩具。指针、泛型单态化、异常、并发、浮点、联合、位运算、内联汇编、裸机目标全部在规格内，目标是能编译最小操作系统内核。为同时满足「像文章」与「能写内核」两个相反要求，语言采用**双层同语言**结构：默认的文章层使用自动引用计数（Automatic Reference Counting，ARC），不出现指针与内存操作；`系统：` 段内开放指针、手动内存与内联汇编。两层共享同一套类型系统、同一份中间表示与同一组后端，并非两门语言。

**适用场景**

- 中文为主要工作语言的教学与工程团队，希望降低语法记忆成本。
- 需要一份源码同时产出桌面、移动、Web 与裸机产物的场景。
- 语言设计与编译器实现的研究与教学，规格完整且可逐条核对。
- 以本地代码模型辅助实现编译器，需要封闭词表与机械可判定规则的场景。

**不适用场景**

- 需要即时可用工具链的生产项目。当前无可执行编译器，见[已知问题与限制](#已知问题与限制)。
- 依赖成熟生态与第三方库的项目。本项目不引入第三方运行时依赖，标准库尚在规划中。
- 需要与现有 C 语言头文件或 C++ 库二进制互操作的场景。规格未定义 C 语言应用二进制接口互操作。
- 期望用 ASCII 键盘快速输入且不接受全角符号的团队。语言强制全角定界。

## 核心功能

- 段式程序结构：以 `《篇名》` 起始，`导入：`、`常数：`、`记录：`、`函数：`、`规则：` 等段按固定顺序排列；开启容器段后必须以 `段结束。` 收束，缺少或多出均判错。
- 文章层自动内存：默认层由编译器插入持有与释放操作，`弱引用` 用于打断循环引用；`系统：` 段内改用手动内存，不插入引用计数。
- 泛型单态化：以 `通用〈甲型〉` 声明，编译期为每个具体类型参数生成一份机器码，运行时不保留类型信息。
- 表驱动异常：`尝试：`、`出错：`、`收尾：` 三个子段构成异常结构，正常路径不产生额外指令；运行时错误同样可捕获。
- 段级并发：`并行：` 段内每条赋值句在独立线程求值，`段结束。` 处隐式等待全部完成；跨线程共享可变状态必须加锁或使用原子操作，否则编译报错。
- 十个目标后端：macOS、Linux、Windows、Web、Android、iOS、鸿蒙，以及 x86_64、arm64、riscv64 三种裸机；后端只读中间表示。
- 例段即编译期断言：`例：` 段体内的赋值在编译期求值，出现在 `输出：` 段的名字视为期望值，不匹配即编译失败，无需额外测试框架。
- 三行诊断格式：错误输出固定为「位置 错误」「建议」「示例」三行，共 40 条以上稳定错误代号，便于一致性套件机械匹配。
- 源码转换器：把 C 与 Python 程序转换为 Serica 源码，转换器不参与自举链，不违反自研约束。

## 核心特性

### 零空格与全角定界

- **价值**：中文书写不使用空格，词边界由虚词与标点承担。语言沿用这一事实，源码不需要空格与缩进，格式争议与对齐维护成本消失。
- **实现方式**：词法分析器单遍扫描，遇半角空格或行首空白直接报错；13 类全角符号各自承担唯一职责，`：` 开段、`。` 收句、`；` 引出否则分支、`，` 停顿、`、` 列举、`「」` 文本、`『』` 含引号文本、`【】` 调用与构造、`（）` 注释、`〈〉` 类型与容量、`．` 小数点、`《》` 篇名、`0-9` 数字。
- **差异化**：易语言以中文关键字替换英文关键字，仍沿用大括号与分号骨架；文言语（wenyan-lang）采用文言句式并编译到 JavaScript；段言（duan）使用空格与缩进划分结构。Serica 的组合为零空格、全角定界、显式 `段结束。` 收束。
- **证据**：规格 1.2 符号表（13 类）与 1.2.1 半角规则；规格 1.4.1 分词算法六步；反例 8、9、42 分别对应半角等号、行内空格与缩进，均应在词法层被拒绝。

### 双层同语言

- **价值**：应用代码需要自动内存以保证安全，内核代码需要指针与手动内存以保证可控。若拆成两门语言，类型系统与工具链要维护两套；Serica 用段边界划分层次，一套类型系统覆盖两种用法。
- **实现方式**：文章层默认插入引用计数，禁止出现 `指针〈T〉`、`申请内存`、`汇编：`；`系统：` 段内开放这些构造，且不做引用计数插入。越界使用报 `E5003`。两层共享同一份中间表示与同一组后端。
- **差异化**：Rust 以 `unsafe` 关键字在表达式级标记不安全区域；Serica 以段为单位隔离，段内全部放开，段外全部禁止，边界是结构性的而非注解性的。
- **证据**：规格 1.10 内存模型三层表、1.14 系统层边界、1.17 系统层完整样例（含内联汇编与页表分配）；反例 14、15、20、27 对应文章层误用系统构造。

### 例段作为编译期断言

- **价值**：小语言缺少测试框架时，示例容易与实现脱节。把示例提升为编译期断言，示例失效即编译失败，文档与实现无法悄悄分叉。
- **实现方式**：`例：` 段体内只允许赋值句，不生成运行代码。判定规则不需要新增词：出现在 `输出：` 段的名字，其在例段中的赋值即期望值，其余名字为输入。编译器收集输入、执行 `规则：` 段、逐项比对期望值。
- **差异化**：主流语言的文档示例靠外部测试框架或文档测试工具维持；Serica 把断言写在语言内，不需要额外工具，也不需要引入新词。
- **证据**：规格 1.6.6 例段规则与判定次序；规格 4.5 十一个分级示例全部带 `例：` 段；反例 50 覆盖「例段未断言输出名」。

### 自研编译链与十后端

- **价值**：语言表层与编译链同时自研，才能保证「表层结构决定产物」而非「表层翻译成另一门语言再由其编译」。后者会让语言退化为语法糖。
- **实现方式**：七层结构（词法、语法与名字、类型与单态化、中间表示、优化、代码生成、链接与运行时）；中间表示固定 52 条指令加 4 条异常指令，九道优化 pass 顺序固定；十个后端只读中间表示。种子编译器以 Go 编写，上限 15000 行，仅用于产出第一个后端，自举完成后删除。
- **差异化**：多数新语言复用 LLVM 或转译到 C 语言、JavaScript。Serica 不引入第三方中间层，产物中不得出现 `.c`、`libLLVM`、`libpython`、`libnode`。
- **证据**：规格 2.3.3 指令集 52 条（八组）、2.3.4 异常指令 4 条、2.4 优化 pass 9 个、3.1 平台矩阵十目标；规格 10.4 后端独立性测试以 `otool`、`objdump`、`strings` 核验产物。

### 面向本地代码模型的规格

- **价值**：实现工作由本地代码模型承担时，规格必须可机械执行、可逐条判定，不能依赖「合理推断」。模糊规格会让模型自由发明语法。
- **实现方式**：词表封闭且计数固定；60 条反例逐条给出违反项与正确写法；40 条以上错误代号按层分段且号段不复用；任务卡固定六项格式，含正例、反例与验收命令；每张卡的上下文预算与文件行数上限均有规定。
- **差异化**：常见规格文档面向人类读者，允许「显而易见」的省略；本规格面向模型，省略即歧义，因此把边界、反例、错误代号一并写死。
- **证据**：规格 6.2 任务卡格式、6.5 系统提示词全文、9.3.1 错误代号表、1.19 六十条反例、12.5 十六条初始决策记录。

## 设计细节与工程取舍

### 表达式不提供括号

- **场景**：`（）` 已专用于注释。若同时兼任表达式分组，词法层无法判定一段 `（…）` 是注释还是分组。
- **处理方式**：不提供表达式括号。需要改变结合顺序时，拆成多个具名赋值句。
- **原因**：再加一种括号会破坏「一符一职」，用户需记忆第四种括号，且注释与分组的歧义无法在词法层消除。拆句的代价是多一行，收益是每步中间量有名字，且不存在优先级误读。

### 容器段必须显式收束

- **场景**：段标签开段后，需要判定后续同类标签是嵌套还是同级。
- **处理方式**：段分三类。声明段与叶子段不嵌套；容器段（函数、通用、规则、循环、匹配、尝试、并行、系统、汇编）必须以 `段结束。` 终止，解析器用栈配对，嵌套上限三层。
- **原因**：仅凭「遇下一个标签即终止」无法区分嵌套与同级，这是早期设计中最先暴露的不可实施缺陷。显式收束让解析器无需缩进信息，也无需向前看。

### 词表与内置名分两张表

- **场景**：标准库函数若用中文命名，`文本化`、`随机整数` 等名字必然含有词表词（`文本`、`整数`）。仅按词表分词会把它们切开，标准库不可用。
- **处理方式**：词表管语法骨架，115 个条目，封版，变更需签字；内置名表管标准库，开放增长，变更不需签字。词法层两级匹配，内置名优先。
- **原因**：若把标准库名塞进词表，语言会随标准库膨胀；若不允许标准库名含词表词，标准库命名会变得别扭且难以记忆。分表是唯一同时满足两条原则的方案。

### 记录按值传递且浅复制

- **场景**：记录需要既能高效传递，又能被函数修改状态。
- **处理方式**：记录按值传递，复制为浅复制：标量字段复制值，引用字段复制指针并增加计数。函数内改标量字段不影响调用方，改列表字段内容会影响调用方。要修改状态并让调用方可见，返回新记录，或在 `系统：` 段传指针。
- **原因**：深复制会带来不可预期的开销；全引用语义会让「值类型」名不副实。浅复制的不对称行为必须写进文档，否则使用者必然踩坑，因此规格 1.8.3 用整节说明并给出正误两种写法。

### 种子语言选 Go 而非 Zig

- **场景**：自举需要一个临时编译器，先产出第一个后端，之后由 Serica 自己编译自己。
- **处理方式**：种子用 Go，上限 15000 行，只产出 macOS arm64 一个后端，自举完成后整体删除。置换优先级为解释器、优化 pass、汇编器。
- **原因**：种子只需活到自举完成，Zig 的跨平台交叉编译优势不会进入产品；Zig 尚未发布 1.0，语法变动风险不可接受；本地代码模型对 Go 的生成准确率高于 Zig 与 Rust。种子的目标是尽早删除，而非长期维护。

### 索引从 1 起

- **场景**：数组与列表下标基数。
- **处理方式**：一律从 1 起，`第1项` 是首项。转换器负责把源语言的 0 基下标加 1。
- **原因**：自然语言说「第1项」「第3个」，从 0 起是 C 语言指针偏移的历史惯性。语言以中文书写习惯为设计起点，下标基数应与叙述一致。代价是与既有语言迁移时需转换，此项由转换器承担。

## 安装与部署

当前**没有可安装的发行版**。仓库处于规格冻结、实现未启动阶段，无可执行编译器，也无包管理器条目。以下步骤说明后续安装形态，现阶段执行不会得到可用工具链。

环境要求（实现完成后）：macOS 13 以上、Linux 内核 5.10 以上、Windows 10 以上；Go 1.23 以上，仅在从源码构建种子编译器时需要。

## 快速开始

以下程序取自规格 4.5 示例 1，用于说明语言的书写形态。它**尚不能编译或运行**，因为编译器实现尚未开始。程序语义为输入两个整数，输出二者之和；`例：` 段声明 `甲` 为 2、`乙` 为 3 时 `和` 应为 5，该断言在编译期检查。

```text
《加法》

输入：甲〈整数〉、乙〈整数〉。

规则：
和记为甲加上乙。
段结束。

例：甲记为2。乙记为3。和记为5。

输出：和。
```

预期输出（编译器实现完成后）：

```text
5
```

对照要点：

| 现象 | 原因 |
| --- | --- |
| `《加法》` 独占首行 | 篇名是模块标识，一篇一个 |
| 段落之间有空行，段内无空行 | 空行分隔段，段内一行一句 |
| `段结束。` 收束 `规则：` 段 | 容器段必须显式收束 |
| `记为` 而非等号 | 赋值只有一个词，无复合赋值 |
| `例：` 与正文同行 | 例段是叶子段，不嵌套容器 |

## API 或模块说明

对外接口为命令行程序 `serica`，无库形式接口。下表为规格 5.1 定义的子命令，实现完成后生效。

| 子命令 | 签名 | 返回值 | 说明 |
| --- | --- | --- | --- |
| `lex` | `serica lex <文件>` | 退出码 0 / 1 | 输出词法单元流，用于排查分词问题 |
| `check` | `serica check <文件>` | 退出码 0 / 1 | 执行词法、语法、名字、类型四项检查，不产出文件 |
| `ir` | `serica ir <文件>` | 退出码 0 / 1 | 输出中间表示文本，需满足七条不变式 |
| `build` | `serica build <文件> -o <产物> --target <目标> [-O0\|-O1\|-O2]` | 退出码 0 / 1 | 编译并产出目标文件 |
| `run` | `serica run <文件> [--参数 …]` | 程序退出码 | 编译并立即运行 |
| `fmt` | `serica fmt <文件> [--check]` | 退出码 0 / 1 | 格式化源码，`--check` 只检查不改写 |
| `doc` | `serica doc <文件>` | 退出码 0 / 1 | 生成阅读版 HTML |
| `test` | `serica test <目录>` | 退出码 0 / 1 | 运行目录内全部 `例：` 段 |
| `pack` | `serica pack <目录>` | 退出码 0 / 1 | 打包为可分发单元 |
| `lsp` | `serica lsp` | 常驻进程 | 语言服务，标准输入输出协议 |

错误码按层分段，号段不复用。下表为代表性条目，完整表见规格 9.3.1。

| 错误码 | 含义 | 处理方式 |
| --- | --- | --- |
| `E1001` | 出现半角标点 | 改为对应全角符号 |
| `E1009` | 标识符含 ASCII 字母 | 改用汉字标识符 |
| `E2001` | 容器段缺少 `段结束。` | 在段末补 `段结束。` |
| `E2004` | 条件句缺少否则分支 | 补 `；否则，…。` |
| `E2008` | 匹配段缺少 `其他：` | 补 `其他：`，或列全联合成员 |
| `E3006` | 标识符包含词表词 | 改名，避开词表与内置名 |
| `E4011` | 定长数组长度非常量 | 改用编译期常量，或改用 `列表` |
| `E5001` | 函数写篇级名 | 改为传参或返回新值 |
| `E5009` | 索引从 0 起 | 改为 `第1项` |

调用示例（实现完成后）：

```bash
serica check 加法.serica --严格
```

限流与配额：命令行工具，无限流。语言服务 `lsp` 并发上限由实现规定，规格未约束。

下图为规格 0.5 定义的目录结构。当前仓库仅含文档与规格，代码目录在 M0 建立。

```text
Serica/
├── README.md                  简体中文首页

├── LICENSE                    Apache-2.0 许可证全文
├── NOTICE                     第三方依赖与素材声明

├── spec/                      规格与技术决策
│   └── Serica-开发手册.md     v3.1 完整规格，3593 行
├── seed/                      种子编译器（Go，上限 15000 行，自举后删除）
├── compiler/                  自研编译器（Serica 编写，自举后接管）
```

## 安全与隐私

数据收集与存储：编译器与工具链不收集任何数据，不联网，不写入用户目录之外的路径。规格未定义遥测。

传输加密：本项目不提供网络服务，无传输环节。

权限模型：编译器以调用者权限运行，不请求提权。`系统：` 段可执行内存与端口操作，属语言设计的一部分，调用者需自行评估源码可信度。

已知风险：语言允许内联汇编与手动内存管理，`系统：` 段内代码的正确性由作者负责，编译器不做边界检查。文章层由引用计数保证内存安全，`弱引用` 使用不当会导致对象提前释放。

漏洞上报渠道：通过 [GitHub 安全公告](https://github.com/ntars/Serica/security/advisories/new) 私下上报，流程见 [SECURITY.md](./SECURITY.md)。请勿在公开 Issue 中披露未修复漏洞。

**当前限制**

- 表达式无括号，多步算式需拆句。

- 文本不可跨行，需用 `连接` 拼接。
- 不提供通道关闭语义，改用哨兵值约定。
- 不提供重载、运算符自定义、宏、元编程、反射。

以上每一条在规格 1.18 均有原因与替代方案，属设计决策而非实现缺失。
