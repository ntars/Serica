# D-0090 文本结果值的只读文本操作

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

D-0088/D-0089 的文本结果值现在可直接作为受限文本操作的操作数：

- `textLength（结果值（结果））` 按成功载荷的 Unicode 标量值计长。
- `textConcat（…）` 和 `substring（…）` 可读取成功结果载荷；它们仍沿用现有五层拼接、63 字节切片输入和 63 字节根输出边界。
- `equals`、`notEquals` 以及 `<`、`<=`、`>`、`>=` 可比较结果载荷与静态字符串或其他受支持运行时文本操作数。
- 若结果处于失败状态，上述操作在写 stdout 之前以错误码退出；成功载荷类型仍由声明固定。
- 静态文本结果的存储仍包含根输出所需的一个规范化换行，但四槽中的语义字节长度不含该换行。结果值参与文本操作时使用语义内容，根输出时才额外写出换行。

动态文本结果复制、写入另一个结果、跨函数返回、捕获/恢复和所有权转移仍未开放。

## 理由

结果值通过 `结果值（结果）` 显式解包，能复用现有文本长度、拼接、切片和比较运行时，而不把结果变量隐式转换成文本变量。静态与运行时文本结果共享“长度不含规范化换行”的语义，避免 `textLength`、拼接和比较把输出装饰当成载荷内容。

## 边界

- 结果值前仍必须使用 `结果值（结果变量）`，不能直接输出结果变量。
- 操作只读取现有指针和长度，不复制或转移拥有动态缓冲区的运行时结果。
- 失败结果没有可操作的文本载荷；操作在 stdout 前以错误码退出。
- 本决定不改变能力声明、系统符号白名单、Go 子集、逐行归因、源码/产物独立性和 P3b 删除 `bootstrap/` 的硬门。

- 运行时结果失败后进入文本操作时不产生 stdout，并以错误码 17 退出。
- 整数结果用于文本长度、拼接或文本比较时，`check`/`build` 分别以 `S-3044`、`S-3044` 和 `S-3015` 拒绝。
- `make test-p1b-runtime` 通过 106 个整数形态、10 个静态文本结果和 13 个运行时文本结果 ARM64 产物，覆盖 139 个成功文本输入、187 个编译诊断和 104 个运行时拒绝样例。
- `make seed-audit` 通过 7066/8000 行及 C-1 5270/6733（78.3%），Go 子集和逐行归因完整。
