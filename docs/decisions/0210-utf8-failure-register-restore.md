# D-0210 UTF-8 校验失败路径恢复与临时桥预算 12800 行

状态：已定案

## 背景

`test-p1b-module-graph` 在传入非法 UTF-8 模块时崩溃。根因不在模块图算法，而在 ARM64 UTF-8 校验器的失败出口：

- `emitRuntimeUTF8Validation` 把非法字节分支登记为运行时失败补丁。
- 调用方又会把这些补丁改写为函数自己的错误收束点，而不是直接 `_exit`。
- 原始失败分支跳过了校验器自己的 `ldr x20..x26` 与 `add sp, #80`，因此 `x20` 仍指向被校验的只读文本，`sp` 也停在临时校验帧。
- 后续整数输出把 `x20` 当作栈数字缓冲区游标，向只读文本页写入，触发 `EXC_BAD_ACCESS`。

同一根因也解释了动态环境变量名称路径在失败或空值边界后的异常；静态环境读取、`argumentText` 单独取值和拼接此前已分别通过，问题限定在校验失败后的调用约定。

## 决定

- 校验器新增本地 `failure` 汇合点。所有 29 个非法字节分支只跳到该汇合点，不再直接进入调用方错误收束。
- 成功与失败出口都恢复 `x20..x26` 并执行 `add sp, #80`。
- 成功路径用无条件分支越过失败蹦床；失败蹦床恢复寄存器后，以一个 `b.al` 补丁加入既有 `failurePatches`，继续服从调用方的本地错误处理或最终 `_exit(1)`。
- 共享蹦床避免为 29 个分支各复制一份恢复序列，是本次种子行数审查中的压缩措施。
- 活动 Go 临时自举桥上限由 12600 行调整为 12800 行，只容纳已验证的 P1b 桥接修正。Go 子集、依赖白名单、逐行归因、独立性、许可、平台符号和 P3b 删除门不变。

## 验收

- 最小复现：`printf '\377' > .work/mgbroken/Broken.serica` 后，`module-graph` 输出 `-137438957474` 并以 0 退出。
- `make test-p1b-module-graph` 通过 5 节点共享图、72 层导入、11 份编译器源码、10 个位置诊断及 3 种读取失败。
- `make test-p1b-module-bind`、`make test-p1b-native-emit` 和 `make test-p1b-runtime` 复跑通过。
- `make seed-audit` 实测 10 个活动源码文件、12779/12800 行，归因完整；C-1 为 4929/12583（39.2%），未触发 40% 语言复核条件。

## 后果

P1b 阶段门仍未通过。动态环境变量名称已能通过参数文本路径读取；通用文件/进程 IO、通用容器结果载荷、容器逃逸、跨函数恢复和行简自编编译器仍待实现。预算调整不表示允许长期扩大 Go 实现。
