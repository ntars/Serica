# D-0092 运行时文本表达式结果载荷

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

有界文本结果的成功载荷除直接 `readText（）` 外，还可直接使用受支持的运行时文本表达式：

```serica
变量 文本=readText（）。
变量 结果=成功（textConcat（文本，『！』））。
程序=【能力=array（『stdout』，『stdin』），输出=结果值（结果）】。
```

```serica
变量 文本=readText（）。
变量 结果=成功（substring（文本，1，3））。
程序=【能力=array（『stdout』，『stdin』），输出=结果值（结果）】。
```

- `runtimeResultPayload` 把 `readText`、`textConcat` 和 `substring` 统一识别为有界运行时文本值，结果变量仍采用四槽布局：标签、容量或错误码、UTF-8 指针和有效字节长度。
- `textConcat` 载荷先写入独立临时映射，再复制到目标结果的文本缓冲区；目标可在初始化或重赋值时接收该载荷，从结果自身取操作数时也不会因目标写回覆盖源内容。
- `substring` 载荷复用既有 UTF-8 码位切片与边界检查，再把结果复制到结果缓冲区。越界按既有运行时规则在 stdout 前失败。
- 直接读取另一个结果值作为载荷表达式操作数时，失败源继续传播其 `1..255` 错误码，不写出目标结果。
- 成功载荷的最大内容仍为 16 MiB−1 字节，输出时追加一个规范化换行；结果值的现有长度、拼接、切片、相等和排序读取语义保持不变。

本决定只扩大成功载荷表达式。文本结果复制、跨函数返回和恢复、所有权转移、捕获、通用容器载荷及任意深度的文本表达式仍未开放。

## 理由

复用现有的有界文本表达式验证和代码生成，可以在不增加语法关键字、系统符号或第三方依赖的前提下，让结果构造与当前文本运行时保持同一组边界规则。先暂存再复制使源和目标可以指向同一结果存储，避免别名写回破坏待复制的源字节。

## 边界

- 接受的成功载荷是 `readText（）`、受支持的 `textConcat（…）`、受支持的 `substring（…）` 以及可由这些值组成的现有有界文本表达式；更深限制沿用当前表达式检查。
- 载荷表达式在构造结果时求值；失败结果值作为表达式操作数时优先传播错误，不建立成功载荷。
- 文本结果仍按进程生命周期保留匿名映射，尚无显式释放、引用计数或所有权转移。
- 不改变能力声明、系统符号白名单、Go 子集、逐行归因、源码/产物独立性和 P3b 删除 `bootstrap/` 的硬门。
