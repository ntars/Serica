# D-0063 控制台程序的能力声明

状态：已定案（入口级 stdin/stdout 静态能力检查；不构成完整效果系统）

## 背景

Serica 的设计原点要求副作用由能力声明约束，并在编译期检查。当前 P1b 控制台入口可读取 stdin、输出 stdout，但尚无函数签名或效果类型；在增加文件、网络等接口前，需要先对已有 IO 建立最小安全契约。

## 决定

- 控制台根记录以 `能力` 字段声明能力，值为编译期字符串数组，例如 `能力=array（『stdout』，『stdin』）`。能力标识为标准库/平台接口名，使用 ASCII。
- 根 `输出` 字段要求显式 `stdout` 能力；任何运行时路径调用 `readInteger（）` 或 `readText（）` 都要求 `stdin`。检查覆盖变量初始化/赋值、条件、循环及嵌套表达式，不以运行时分支是否可达为条件。
- 缺少声明、声明未知或重复能力均为编译错误。声明未使用的受支持能力允许存在；构建产物只包含源码确实调用的后端路径。
- 当前声明范围只覆盖 P1b `程序` 根入口。编译器尚无用户函数、函数签名与调用图，故不声称实现函数级效果传播；新增函数时须将能力纳入其签名并检查调用方能力。
- P0b `窗口` 的 UI 副作用和后续文件/网络/进程 IO 暂不纳入本子门，也不因此自动获准；对应接口实现前必须扩展能力检查。动态数组的匿名映射属于语言运行时内存管理，不暴露为用户可调用 IO 能力。

此决定不改变 P1b、独立性、依赖、许可、平台或自举硬门，也不开放通用文件/进程 IO。

## 验收

- [x] `stdout` 单独声明允许纯输出；缺少 `stdout` 拒绝。
- [x] 同时声明 `stdin` 与 `stdout` 可运行整数和 UTF-8 输入。
- [x] 在变量、循环、条件及输出表达式中的输入调用均要求 `stdin`；缺失时 `check`、`build` 均失败。
- [x] 未知、重复及非编译期文本能力声明返回稳定诊断；`make test-p0b-scope`、`make test-p1b-static`、`make test-p1b-modules` 与 `make test-p1b-runtime` 均通过。
- [x] 仅为能力检查更新源码和契约文档，不新增外部依赖或产物系统导入；`make doctor`、`make seed-audit`、`make license` 和 `./tools/check-independence source` 通过。

## 边界

此子门只建立入口能力约束；函数效果签名、能力传递、能力值、文件句柄、路径沙箱和一般 IO 仍未实现。P1b 阶段门保持未通过。
