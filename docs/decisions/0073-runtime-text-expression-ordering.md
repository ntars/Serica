# D-0073：运行时文本表达式排序比较

- 状态：已定案
- 日期：2026-11-21
- 领域：P1b 原生运行时

## 决策

`<`、`<=`、`>`、`>=` 条件可使用 D-0072 支持的运行时文本操作数：已初始化文本变量、`readText（）`、最多四层 `textConcat`、支持源的 `substring`、运行时文本数组 `arrayGet`；另一侧可为相同类型的运行时文本操作数或编译期字符串。编译期文本仍在编译期求值。

所有运行时文本均先通过 UTF-8 验证。按 UTF-8 字节作字典序比较与 Unicode 标量值顺序一致；不做归一化。比较结果只能作为条件使用，不能存储或输出，任意动态文本表达式和 `readText（）` 作为 `substring` 源仍受现有语义限制。

发射第二个比较操作数可能覆盖第一个操作数的 ARM64 临时寄存器。代码生成器在生成右操作数前将左侧长度和地址压入 16 字节对齐的栈区，再恢复寄存器；栈帧另为表达式 scratch 保留所需空间。

## 验收

- `make test-p1b-runtime` 执行两类文本排序比较原生 Mach-O。既有变量比较继续覆盖 ASCII、中文、补充平面码位、前缀、长公共前缀、空值和不做归一化。
- 新增产物覆盖运行时变量与 `textConcat`、运行时变量与 `substring`、动态文本数组 `arrayGet`、直接 `readText（）` 及静态字符串在左右两侧；真实输入分别输出 `15` 和 `17`，同时覆盖真、假分支。
- 等长的运行时文本表达式 `equals` 回归也通过，确认右操作数生成不会覆盖左侧地址或长度；`substring（readText（），…）` 仍由 `check`/`build` 以 `S-3013` 拒绝。
- `make test-p1b-runtime` 覆盖 127 个成功文本输入、94 个编译诊断和 78 个运行时拒绝样例；P1b 阶段门仍未通过。
