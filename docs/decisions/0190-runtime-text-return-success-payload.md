# D-0190 运行时文本返回调用进入成功载荷

## 根因

块体文本返回函数虽能在函数映射中登记 `runtimeReturnsText`，但四个位置未把该事实传播到真实调用点和结果载荷规划：

- 文本返回标记只在表达式体函数上迭代识别，且只做一轮；调用链上游函数无法继承文本返回性质。
- 函数展开时只写入结果载荷，未写入 `runtimeFunctionText`，调用点因此不携带文本返回 ABI。
- 运行时函数参数类型对文本返回函数回退为通用类型，文本实参未登记为 `运行时字符串`。
- `成功（文本返回调用）` 既未通过结果载荷推断识别，也未在代码生成阶段进入既有运行时文本结果分支。

## 修复

- `annotateRuntimeTextReturns` 迭代遍历；允许块体函数文本局部返回传播文本返回性质，并同步到函数声明与运行时函数表。
- `expandFunctionValue` 在登记运行时调用时同步 `runtimeFunctionText`；`runtimeFunctionParameterTypes` 对文本返回函数沿用已推断的运行时字符串/结果参数类型。
- 把文本返回调用加入运行时文本持久副本、`成功` 载荷推断与受支持的调用方边界；`结果值（成功（文本返回调用））` 也纳入同一白名单。
- 代码生成在运行时文本 `成功` 载荷分支中复用文本返回值所有权转移：函数调用后保存 x1/x2/x3 描述符，释放目标旧映射，再把返回值指针/长度/容量交给结果变量；不重复释放刚返回的内存。
- 仍禁止文本返回调用进入任意嵌套表达式、独立条件、函数体或容器；嵌套在 `textConcat` 中的样例继续以 S-3023 拒绝。

## 验证

- 新增 4 个运行时用例：`成功` 载荷经结果变量或直接 `结果值` 输出文本，另以 `是否失败` 和 `错误码` 观察该成功结果的标量状态。
- 直接写成 `结果值（成功（欢迎（输入）））` 的复现样例可生成并执行，输出 `行简！`。
- `make test-p1b-runtime` 通过 213 个 arm64 整数形态产物、16 个文本返回调用方存储产物（含 4 个新成功载荷用例）、162 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例。
- 嵌套 `textConcat（欢迎（输入），『？』）` 仍以 S-3023 拒绝。
- P1b 完整阶段门仍未通过；本决策只闭合该文本返回成功载荷子边界。
