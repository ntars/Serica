# D-0162：文件删除、重命名与自编前端登记

- 状态：已定
- 日期：2026-11-24
- 关联：D-0099、D-0160、S-3075、S-3076

## 背景

D-0160 在 stage0 原生后端加入 `appendFile`，但行简自编编译器的 `effects.serica` 与 `types.serica` 尚未登记编号 38。该前端会把 `appendFile` 当成未知的一元内建，导致效果传播、参数数量和结果类型与 stage0 不一致。文件操作还缺少不经过读写句柄的删除与重命名原语。

## 决策

- 新增 `removeFile（路径）` 与 `renameFile（源路径，目标路径）`，成功返回整数 `0`，失败时不输出并退出 `1`。
- 路径接受静态非空文本或 `argumentText（下标）`，不得包含 NUL；参数路径另要求 `args`。
- 两种调用都要求根能力 `filesystem.write`，并沿函数调用链逐层声明。缺少根能力报告 `S-4102`，隐藏或未传播效果报告 `S-4106`。
- 参数数量或路径类型错误分别报告 `S-3075`、`S-3076`。macOS arm64 后端分别导入 `_unlink` 与 `_rename`。
- 行简绑定编号继续追加：`appendFile=38`、`removeFile=39`、`renameFile=40`。效果表把 38–40 映射到 `filesystem.write`，类型表补齐一元/二元元数和整数结果。

## 验收

- stage0 运行时门执行动态路径删除与重命名，验证源消失、目标内容和 `0` 输出；缺失删除目标与缺失重命名源均无 stdout 退出 `1`。
- 行简模块效果门执行 `appendFile`、`removeFile`、`renameFile`，验证文件结果和三种 `filesystem.write` 映射，并覆盖缺根能力与隐藏效果。
- 行简模块类型门验证三种调用的参数元数、路径类型和整数结果，并比较 stage0 诊断位置。
- 这些原语不提供目录、元数据、原子替换、通用文件句柄或进程 IO；P1b 阶段门仍未通过。
