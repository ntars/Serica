# D-0236 文本数组结果载荷与复制隔离

状态：已定案

## 背景

D-0235 只把整数数组开放为运行时结果载荷。文本元素仍被拒绝，且结果变量复制只处理整数数组，复制文本数组时没有深复制元素映射。最小复现需要同时满足：

```serica
函数 建表（）【返回 成功（array（『甲』，『乙』））。】。
变量 结果=建表（）。
变量 副本=结果。
赋值 结果=成功（array（『新甲』，『新乙』，『新丙』））。
程序=【能力=array（『stdout』），输出=arrayGet（结果值（副本），1）】。
```

若复制只复制描述符，重赋值释放原映射后副本会悬空；若文本数组仍按 8 字节步长布局，`arrayGet` 会把文本指针当作完整元素并读错长度槽。

## 决策

- `成功（array（文本…））` 可保存为受限文本数组结果。结果仍占四槽：标签、容量、数据指针、元素数，调用帧保持 `x0=tag、x1=capacity、x2=data、x3=length`。
- 文本数组元素使用 16 字节步长，依次保存 UTF-8 指针和字节长度；整数数组继续使用 8 字节步长。
- `arrayLength` 与 `arrayGet（结果值（结果），索引）` 按载荷类型选择步长；`arrayGet` 保留失败传播、负下标与越界拒绝。
- 结果变量复制会为目标重新映射数组描述符并深复制每个文本元素；函数返回值仍通过既有四槽 ABI 转移所有权，不走复制路径。复制结束时恢复四槽描述符寄存器，避免后续 `arrayGet` 读错暂存结果。
- 数组结果复制循环与结果字面量暂存循环的分支偏移统一使用 `目标标签位置 - 当前指令位置`，修复少减 1 导致的无限回跳。
