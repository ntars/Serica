# D-0032：有界运行时整数输入

## 决策

新增 `readInteger（）` 控制台表达式，从 stdin 逐字节读取一行 ASCII 十进制有符号整数。支持可选前导 `-`、LF、CRLF 和 EOF 结束；不接受 `+`、空行、空格、非数字或额外行内内容。输入最多 64 字节。有效值覆盖完整有符号 64 位范围。

运行时解析以负数累积，分别检查正数末位 7、负数末位 8 和十进制累积边界，从而正确接受 `-9223372036854775808`。EOF、系统读取错误、空值、非法字符、过长值和溢出均调用 `_exit(1)`，不向 stdout 写入部分结果；成功值使用现有十进制输出路径。

## 边界

- `readInteger（）` 目前只能直接作为 `程序` 的 `输出` 表达式；不允许赋给变量、用于常量或参与算术，因为动态变量状态与数据相关运算错误路径尚未实现。
- 只读取一行 ASCII 整数；不定义通用字符串输入、文件/进程 IO、错误值/传播或异步 IO。此限制由 `S-3042` 和 `S-3043` 固定。
- 原生 Mach-O 直接导入系统 `libSystem.B.dylib` 的 `_read`、`_write`、`_exit`；不引入 C、外部编译器/汇编器/链接器或额外运行时依赖。
- P1b 总门仍未通过。种子继续受 D-0026 行数、Go 子集、归因、许可和 P3b 删除要求约束。

## 后续演进

D-0032 验收时输入仅能直接输出。D-0033 随后允许将解析值写入整数变量并直接读取输出；运行时值仍不能参加算术。这里记录的是 D-0032 当时的子门边界，不代表当前实现边界。

## 验收

- `make test-p1b-runtime` 编译运行整数输入 Mach-O，检查 `_read`、`_write`、`_exit` 导入、原生解析/乘法反汇编、dyld、系统依赖和签名。
- 正例实际传入 `42`、`-17`、CRLF、首行后仍有第二行、int64 正负边界和 `-0`，检查标准输出与退出码。
- 8 个运行时反例覆盖 EOF、空行、孤立负号、显式正号、非法字符、正负溢出；均须非零退出且无 stdout/stderr。19 个编译期诊断继续通过。
- 全部运行时变量赋值、输入参与运算、动态字符串/容器、通用 IO、错误值传播与编译器自举仍未完成。
