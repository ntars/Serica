# D-0099 静态路径文件写入边界

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

控制台根可以调用 `writeFile（静态文本路径，文本）`，把编译期文本或有界运行时文本覆盖写入普通文件。函数返回实际写入的 UTF-8 字节数：

```serica
变量 文本=readFile（『examples/p1b-runtime-file-fixture.txt』）。
变量 字节数=writeFile（『build/p1b-runtime-file-output.txt』，文本）。
程序=【能力=array（『stdout』，『filesystem.read』，『filesystem.write』），输出=字节数】。
```

- 路径必须是编译期非空且不含 NUL 的文本。当前不开放动态路径、目录操作、元数据、追加、原子替换、权限控制或通用文件系统接口。
- 文本参数可为编译期字符串或既有有界运行时文本操作数，包括普通文本变量、`readText（）`、文本结果值和既有受支持拼接/切片结果；内容不自动追加换行。
- 原生后端按需导入 `_creat`、`_write`、`_close` 与 `_exit`。`_creat` 等价于以只写、创建和截断模式打开，文件权限请求 `0644` 并由系统 umask 调整。
- 写入循环处理部分写入并累计字节数。打开失败退出 `21`，写入无进展退出 `22`，关闭失败退出 `23`，均保持 stdout 为空。
- 文件写入属于显式效果。函数调用链须逐层声明 `filesystem.write`，根程序须在 `能力` 数组中授权。隐藏效果、漏传效果和缺少根能力均由 `check` 与 `build` 拒绝。

## 理由

编译器和后续工具必须能把诊断、缓存、构建中间结果和生成源码写回文件。先提供覆盖写入最小闭环，可以验证路径校验、能力传播、系统 ABI、部分写入循环和字节计数，同时不提前承诺通用文件系统抽象。复用既有文本操作数装载路径，也让静态与运行时文本共享同一套长度和生命周期规则。

## 边界

- `writeFile` 每次调用都会创建或截断目标文件；成功写入空文本时结果文件为零字节。
- 当前没有追加模式、临时文件后重命名、父目录创建、文件锁、刷盘、所有权、时间戳或原子性保证。进程被中断时可能留下部分文件。
- 文件路径和普通文件类型仍由操作系统及进程当前目录解释；不承诺符号链接策略、可重入写入、并发写者或超过系统限制的路径。
- `writeFile` 本身不解析或规范化写入内容；调用方负责提供合法 UTF-8 文本。动态文本操作数沿用生成前的 UTF-8 校验与失败边界。
- 不改变系统符号白名单、Go 子集、逐行归因、源码/产物独立性及 P3b 删除 `bootstrap/` 的硬门。

## 验收

- 原生门覆盖静态中文文本写入与字节计数、已有文件截断、空文本截断、补充平面 UTF-8、从文件读取后写入另一文件，以及带 `filesystem.write` 效果的函数返回。
- 失败门覆盖父目录缺失与目录目标打开失败，验证无效源文件在目标写入前失败且目标内容保持不变，并通过文件大小限制验证无进展写入以 `22` 无 stdout 退出。
- 产物未定义符号严格限制为 `_creat`、`_write`、`_close`、`_exit` 及内容表达式所需的已登记文件读取/映射符号。
- `check`/`build` 以 `S-3071` 拒绝参数个数、动态或非文本路径、空路径和非文本内容，以 `S-4102` 拒绝缺少根能力，以 `S-4106` 拒绝隐藏或未逐层传递的效果。
- P1b 阶段门仍未通过；动态路径、目录/元数据、追加与原子更新、通用文件/进程 IO、真实运行时函数 ABI 和行简编译器尚待后续子门。
