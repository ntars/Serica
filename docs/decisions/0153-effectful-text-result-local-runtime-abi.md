# D-0153 效果函数文本结果局部运行时 ABI

带 `stdin` 效果的语句体函数可直接以 `成功（readText（））` 构造运行时文本结果局部，或通过两个分支都构造结果的 `ifElse` 在文本成功与失败之间选择，再把四槽结果描述符返回调用方。函数效果仍须逐层声明并由程序根 `stdin` 能力授权。

## 根因

D-0151 只让整数结果局部进入效果语句体 lowering。文本结果局部虽然已有标签、值、指针和长度语义，但函数分类没有保存局部载荷，帧规划仍按双槽分配；结果缓冲初始化又假定指针槽已归零。未清零的栈槽会被误判为已有映射，导致读取动态文本时写入随机地址，表现为内部失败或无输出崩溃。

## 修复

- 运行时函数局部类型分类同时保存结果载荷；文本载荷局部按四槽分配标签、值、指针和长度，写入与普通文本结果变量相同的 ABI。
- 函数入口统一清零结果局部；文本结果局部同时清零指针和长度，确保首次成功载荷只建立一次匿名映射。
- 效果支持只对结果局部的 `成功` 文本载荷额外放行 `readText`；普通文本局部初始化仍保留 `S-3068` 边界。`ifElse` 仅在两分支都是支持的结果表达式时递归放行，条件仍走通用无效果表达式规则。
- 语句函数返回文本结果局部时从四槽加载 `x0=tag`、`x1=value`、`x2=pointer`、`x3=length`，调用方继续按运行时文本结果接管描述符。
- 入口零点按 `localNames` 的声明顺序发射，不遍历结果局部映射，避免多个文本结果局部因 Go map 迭代顺序产生不同 Mach-O。
- 行简前端与 stage0 共享同一套“零使用优先、单次引用放行、重复引用拒绝”的实参规则；本决策不改变其调用求值顺序。

## 验收

新增两个 macOS arm64 正例：函数声明三个文本结果局部；开关 `1` 依次读取三行并返回第三行输出 `跨函数文本结果局部`，开关 `0` 不读取文本并无 stdout 以 `9` 退出。成功产物另执行 8 次同路径构建并逐字节比较。`make test-p1b-runtime` 通过 187 个 arm64 整数形态产物、15 个函数结果边界产物、309 个编译诊断和 118 个运行时拒绝样例。定向模块、模块 ABI、原生发射、医生、许可和源码独立性门复跑通过。

## 边界

本决策只开放效果语句体函数中直接 `readText` 成功载荷及 `ifElse` 结果选择，不开放任意效果调用、文本拼接/切片结果局部、文本/容器结果参数逃逸、通用调用求值顺序或完整跨函数恢复。P1b 阶段门仍未通过。
