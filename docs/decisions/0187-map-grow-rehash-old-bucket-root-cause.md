# D-0187 映射扩容重散列保留旧桶指针

## 根因

`emitRuntimeMapGrow` 在调用 `emitArrayMapCall` 分配新桶数组前，把旧桶数组指针保存在 `x2`。`emitArrayMapCall` 会覆盖 `x2`，重散列循环却从 `sp+48`（旧指针的栈副本）读取。此栈副本在扩容入口写入，随着调用层级加深，实际变成旧容量或无效值，导致遍历野指针并 `SIGSEGV(139)`。1500 键以下因散列分布未触发该路径，2000 键稳定崩溃。

同时，碰撞链在重散列时可能已经把某个旧桶头链接到新表并清零该旧槽。若再次把该槽当独立链表重散列，会把同一节点重复插入，造成负载错误和链结构破坏。

## 修复

- 在调用 `mmap` 前，把旧桶指针存入 `sp+72`、旧容量存入 `sp+80`；重散列循环始终从这两个槽读取。
- 旧桶槽为零时跳过，表示该节点已在先前同一旧桶的碰撞链中迁移；只处理仍保留旧链表头的桶。
- 哈希常量、桶节点布局、扩容阈值、负载因子与整数键边界全部不变。
