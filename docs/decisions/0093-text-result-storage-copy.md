# D-0093 文本结果值进入普通文本存储

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

文本结果变量可以通过 `结果值（结果）` 初始化或更新普通运行时文本变量，也可以作为文本数组元素初始化和 `arrayPush`/`arraySet` 的深复制来源：

```serica
变量 源=成功（readText（））。
变量 文本=结果值（源）。
程序=【能力=array（『stdout』，『stdin』），输出=文本】。
```

- 普通文本变量使用自己的 16 MiB 匿名映射。复制只写入结果当前有效字节长度，并在目标长度位置写入规范化换行。
- 文本数组初始化、追加和替换继续按元素深复制；源结果之后成功重赋值或失败替换不会改变已保存的文本变量或数组元素。
- 失败结果进入上述任一入口时，在分配目标数组槽或写出内容前传播其 `1..255` 错误码，stdout 保持为空。
- 源可以是直接 `readText（）`、受支持的 `textConcat`/`substring` 载荷或已拥有的文本结果；成功载荷类型在结果变量声明后保持不变。

本决定只开放结果值到普通文本存储的单向深复制。结果所有权转移、跨函数返回/恢复、捕获、共享引用、通用容器载荷和任意深度文本表达式仍未开放。

## 理由

普通文本变量和文本数组已经有独立存储、长度和边界检查。复用结果值的现有四槽描述符读取有效字节，再进入这些存储，可以打通结果与后续文本操作，同时保持各组件的所有权和失败传播边界清晰。

## 边界

- `结果值` 必须是文本载荷结果；整数结果不能写入文本变量或文本数组，现有类型诊断继续生效。
- 复制仍限制为结果载荷的 16 MiB−1 字节内容和目标文本变量的 16 MiB 容量。
- 文本数组追加仍需要根 `array.write` 能力，失败结果不会绕过能力或写入检查。
- 不改变系统符号白名单、Go 子集、逐行归因、源码/产物独立性和 P3b 删除 `bootstrap/` 的硬门。
