# D-0206 标准输出精确写入边界

状态：已定案

## 背景

现有根输出只支持带换行的整数或文本格式，文本拼接也会在末尾追加终止换行。语言缺少把一段已构造文本逐字节写到标准输出、且不隐式改写内容或行结构的表达式。直接用单次 `write` 假定完整写入，还会在短写时丢失尾部字节并返回错误计数。

## 决定

- 新增内建表达式 `writeText（文本）`，文本操作数遵循既有纯表达式、运行时文本变量和受支持拼接/切片边界。
- 写入内容为操作数的有效 UTF-8 字节，不追加换行或终止字节；返回实际写入的字节数。
- 程序根必须声明 `stdout` 能力；缺少能力时以 `S-3084` 拒绝，函数调用链继续执行逐层效果检查。
- macOS arm64 原生桥使用 `_write` 循环推进缓冲区、长度和累计值，允许系统调用短写，只有剩余长度归零才成功。
- 自编前端同步登记内建编号 `52`、`stdout` 效果、一个文本参数和一个整数结果，并覆盖元数、参数类型和隐藏效果诊断。
- 该表达式只开放标准输出写入。文件句柄、进程标准错误、二进制流、缓冲策略配置和通用 IO 仍不开放。

## 验收

- `make test-p1b-runtime` 新增静态补充平面 UTF-8、空文本、多次有序写入及字节数求和、运行时 `readText`、效果表达式函数和效果语句体局部等执行用例。
- `writeText` 的结果可在后续 `isDirectory`、`fileSize` 和 `exists` 调用后保持正确；缺少 `stdout`、隐藏函数效果、错误元数和非文本参数均被拒绝。
- 模块效果门与模块类型门覆盖 `writeText` 的效果传播、根能力、元数和参数类型。

## 后果

程序可以把文本作为精确 stdout 数据写出，并可靠取得短写后的累计字节数。该边界不提供隐式换行，也不会替代通用流或文件句柄 API；完整 IO 和 P1b 阶段门仍未完成。
