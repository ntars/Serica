# D-0157 直接结果观察与成功文本释放

状态：已验收（P1b 子门；不代表阶段门通过）

## 背景

`是否失败`、`错误码` 和 `结果值` 原先只接受结果变量引用。返回结果的调用必须先写入临时结果变量，才能观察或提取载荷。这使常见表达式 `结果值（选择（开关））` 无法直接表达，也迫使调用方手工扩大结果局部的作用域。

直接接受结果调用还暴露出三个代码生成问题：结果操作数可能被重复求值；成功运行时文本载荷的映射所有权没有统一释放；条件跳转把 `是否失败` 的布尔值按相反条件分支。

## 决定

- `isResultOperand` 接受运行时结果函数调用、`ifElse` 结果表达式、`成功`/`失败` 构造和模块读取结果；三个观察函数不再要求引用中转。
- 直接结果操作数在一次观察中只求值一次。运行时文本成功载荷由观察路径负责释放，失败路径不写 stdout 并保留错误码。
- `结果值` 的成功文本载荷可进入根输出、文本长度和结果接收方；整数成功载荷与静态结果保持原有标签/值语义。
- 函数入口重新标注运行时载荷信息，带有文本结果的递归运行时函数在帧内预留四槽返回描述符。
- 修复三个根因：结果函数文本返回描述符初始化覆盖参数寄存器；直接 `是否失败` 条件码反向；结果观察临时帧 24 字节扩容后未同步栈平衡。

## 验收

`make test-p1b-runtime` 在 macOS arm64 实际执行直接文本结果成功/失败、直接文本长度、直接整数结果状态/错误码和直接静态结果。任意非结果调用、整数和控制表达式仍以 `S-3013` 拒绝；重复或嵌套结果消费不在本决策范围。

成功运行时文本结果输出、状态观察、错误码观察和长度计算均释放结果映射；失败结果无 stdout。空文本与补充平面文本 `𠮷野家` 的码位长度为 `3`。

运行时门当前覆盖 202 个整数形态产物、43 个运行时文本结果产物、27 个函数结果边界产物、315 个编译诊断和 118 个运行时拒绝样例。活动种子上限由 D-0158 的检查工具迁移守住，当前 11996/12000 行，C-1 为 4850/11615（41.8%）。

## 边界

本决策只开放单层直接结果观察。通用文本/容器结果载荷、多个观察者共享同一所有权、嵌套结果消费、容器逃逸、完整跨函数错误恢复和完整 P1b 仍未实现。
