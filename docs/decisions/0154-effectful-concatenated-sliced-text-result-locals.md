# D-0154 效果函数拼接与切片文本结果局部

带 `stdin` 效果的语句体函数可把 `readText（）` 的受支持 `textConcat` 或 `substring` 结果放入 `成功` 载荷，再经文本成功/失败分支返回四槽结果。普通文本局部初始化仍保持 `S-3068` 边界。

## 根因

D-0153 只在函数帧内规划结果和文本状态槽，并把临时缓冲起点放在状态槽之后，却没有为效果语句体保留临时区。直接 `readText` 不需要外层拼接暂存，因此没有暴露该缺口；拼接结果会在状态槽之后写入左右操作数的 256 字节暂存区，越过当前帧并破坏调用方状态，实测退出 `139`。切片也依赖临时输入区，必须由同一帧规划统一覆盖。

## 修复

- 效果语句体函数帧在状态槽之后至少保留 360 字节临时区，为读取、结果复制和切片输入提供帧内空间。
- 扫描函数语句中的嵌套 `textConcat` 深度；存在拼接时按 `512 + 512 × 层数` 保留操作数暂存区，覆盖每层左右两个 256 字节缓冲。
- 临时缓冲起点绑定当前函数状态槽末尾；发射前后保存并恢复文本描述符、结果槽和失败补丁状态，避免函数体污染程序根或后续函数。
- 效果检查仅在 `成功` 载荷子树内放行 `readText`，其余语句仍只允许 `readInteger`；普通文本局部因此继续由 `S-3068` 拒绝。

## 验收

新增四个 macOS arm64 正反例：拼接成功输入 `1` 和 `行简` 输出 `行简尾`，切片成功输入 `1` 和 `行简语言` 输出 `简语`；两者切换为 `0` 时均不读取文本、无 stdout 并以 `9` 退出。两种成功产物各连续 8 次同路径构建并逐字节比较。另加入效果函数普通文本局部反例，`check` 与 `build` 均保持 `S-3068`。

`make test-p1b-runtime` 通过 191 个 arm64 整数形态产物、19 个函数结果边界产物、311 个编译诊断和 118 个运行时拒绝样例。种子 11996/12000 行、C-1 4914/11434（43.0%）。

## 边界

本决策只开放效果语句体函数中由 `readText` 支撑的受支持拼接与切片文本成功载荷。任意效果调用、文本结果参数逃逸、容器结果载荷、通用调用求值顺序、完整跨函数恢复和完整 IO 仍未实现，P1b 阶段门未通过。
