# D-0098 文件输入到动态文本变量

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

`readFile（静态文本路径）` 现在可以初始化或更新普通动态 UTF-8 文本变量：

```serica
变量 文本=readFile（『examples/p1b-runtime-file-fixture.txt』）。
赋值 文本=textConcat（文本，『！』）。
程序=【能力=array（『stdout』，『filesystem.read』），输出=文本】。
```

- 文件读取继续使用 D-0097 的 `filesystem.read` 能力、静态非空路径、16 MiB−1 字节上限、完整关闭后 UTF-8 校验和无部分输出约束。
- 装载成功后，原生后端把匿名映射的所有权转交给文本变量的指针、字节长度和容量槽。成功内容不含自动追加的换行；终止换行只由文本变量的既有根输出路径添加。
- 重新赋值为另一个文件时，先完整读取并校验新文件；成功后释放旧映射并替换描述符。读取或校验失败会在 stdout 前退出，不会留下可见的半更新文本。
- 装载后的变量可直接参与既有文本长度、相等与排序条件、拼接、切片、结果复制和文本数组写入路径。文件输入不再只是直接根输出。
- 文件装载仍属于显式效果。所有调用链和根程序继续按 D-0097 声明并复核 `filesystem.read`。
- 本子门仍不提供动态路径、目录/元数据、文件写入、环境变量展开、通用文件系统接口或文件值作为任意临时表达式操作数。需要参与文本运算时，先写入普通文本变量。

## 理由

编译器读取源文件后必须保留内容，才能执行长度、切片、解析和诊断。把已验证文件映射直接转交给既有动态文本表示，可以复用成熟的长度、比较、拼接和切片机制，同时避免二次复制和另一套文件缓冲生命周期。先读入新映射、再释放旧描述符，也让重赋值在失败时保持明确的无输出边界。

## 边界

- 每个文件文本变量持有最多 16 MiB 的虚拟映射；合法内容最多 16 MiB−1 字节，余量保存输出所需换行。
- 文件内容本身若以换行结束，变量保留该换行；根输出仍追加一个终止换行，因此会出现连续换行。这是文本输出规范，不改变变量字节长度。
- 只支持普通文本文件的内容；文件类型语义、符号链接策略和通用路径安全仍由操作系统结果及调用者当前目录决定。
- 不改变系统符号白名单、Go 子集、逐行归因、源码/产物独立性及 P3b 删除 `bootstrap/` 的硬门。

## 验收

- `examples/p1b-runtime-file-variable.serica` 从固定文件读取“行简文件读取”，追加“！”后输出“行简文件读取！\n”。
- 原生门执行文件变量直接输出、Unicode 标量长度、第二次文件读取替换旧映射及文件内容拼接四个成功场景；非法 UTF-8 和超限文件装载到变量均 stdout 为空且非零退出。
- 产物仍只导入 `_open`、`_read`、`_close`、`_mmap`、`_munmap`、`_write` 与 `_exit`，并通过 Mach-O、dyld、系统库、签名及未定义符号白名单检查。
- 现有动态文本变量、拼接、切片、比较、函数效果和根能力检查继续通过。
- P1b 阶段门仍未通过；编译器解析、动态路径、文件输出和通用文件/进程 IO 尚待后续子门。
