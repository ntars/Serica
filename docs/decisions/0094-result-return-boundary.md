# D-0094 函数结果返回边界

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

纯表达式函数可以返回整数、文本或失败结果，调用点继续把结果当作有标签值使用：

```serica
函数 校验（数值）=ifElse（数值<0，失败（31），成功（数值*2））。
变量 输入=readInteger（）。
变量 结果=校验（输入）。
```

当前实现仍以有界 AST 展开完成函数调用，因此本决定中的“返回”是展开后跨过函数边界的值语义，不是运行时函数 ABI。

- 条件结果的两个成功分支必须具有相同载荷类型；双文本分支返回有界运行时文本结果，双整数分支返回整数结果。
- 结果分支与普通值分支混合时继续以 `S-3023` 拒绝。整数、文本和布尔仍保持静态类型分离。
- `ifElse` 只执行被选择的函数结果分支。未选择分支中的输入不会发生，失败码也不会被观察。
- 失败结果穿过调用边界后保留 `1..255` 错误码；只有 `结果值` 在失败时传播错误码，`是否失败` 与 `错误码` 仍可安全观察。
- 调用链继续执行既有效果检查，`readInteger` 等输入效果必须由每一层函数声明并由根能力复核。
- 文本结果分支使用既有四槽描述符和有界运行时文本存储；条件返回的文本结果同样登记所需的 `_mmap`/`_munmap` 导入。

## 理由

函数结果值最常用的控制流形态是成功与失败两支之一。允许条件表达式选择同类结果，可以把错误构造、返回和调用点观察连成一条可执行路径，同时复用已经验证的惰性选择、结果标签、文本存储和效果传播实现。

## 边界

- 只支持表达式函数及有界 AST 展开；语句函数、局部作用域、真正返回点、调用栈、递归和运行时调用约定仍未开放。
- 成功载荷只覆盖当前已支持的整数与有界文本结果，未接受数组、映射、记录或一般容器载荷。
- 不提供捕获、恢复、所有权转移或跨函数错误处理块；失败仍通过 `结果值` 向进程退出传播。
- 不改变系统符号白名单、Go 子集、逐行归因、源码/产物独立性及 P3b 删除 `bootstrap/` 的硬门。
