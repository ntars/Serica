# D-0171 环境变量读取边界

## 背景

P1b 的文件与参数能力已覆盖有限输入，但程序无法在当前进程环境中读取命名变量。包管理、缓存位置和工具链探测都需要可审计的只读环境查询，同时不能扩大为通用进程控制或任意键值容器。

## 决策

新增 `readEnvironment（静态文本名称）`：名称必须是编译期非空文本，禁止 NUL 与等号；参数和任何动态文本名称由 `S-3083` 拒绝。查询结果按 `args` 能力声明，函数内使用时须逐层传递且根能力一致，缺失能力为 `S-4102`，隐藏效果为 `S-4106`。macOS arm64 后端导入 `_getenv`，借用返回的 NUL 终止文本，不复制、不改写环境；按字节扫描长度并复用现有 UTF-8 校验，缺失或空值返回空文本。直接根输出和借用文本变量各自以精确长度写出再附加规范换行，避免借用指针没有可写终止字节时被当成栈缓冲读取。

## 根因与边界

本轮修复了三个实现根因：UTF-8 校验会把 x22–x25 当暂存寄存器，因此长度不能放在这些寄存器跨越校验；借用环境文本只有只读 NUL 末尾，旧的输出助手读取 `长度+1` 会把进程环境相邻字节输出；返回描述符必须与计算出的长度和借用指针一致。动态参数名称在语义和后端之间曾出现可接受的错觉，现统一收紧为静态名称，后端不再保留半支持的分支。

本决策不引入环境变量枚举、写入、取消、动态名称、`argv` 容器、子进程或通用进程 IO；只开放对当前进程中一个编译期固定名称的只读 UTF-8 查询。P1b 阶段门仍未通过。

## 验证

`make test-p1b-runtime` 新增静态名称直接输出、中文值、`textLength`、缺失/空值、无能力 `S-4102`、非法名称 `S-3083`、隐藏效果 `S-4106`，并断言产物只导入 `_exit`、`_getenv`、`_write`；模块效果门与模块类型门同步覆盖能力、类型和产物参照。全量源码门、doctor、许可、种子审计和源码独立性检查复跑通过；活动种子 11798/12000 行、C-1 4786/11641（41.1%）。
