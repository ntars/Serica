# D-0110 运行时循环内整数提前返回

状态：已验收（P1b 子门；不代表阶段门通过）

## 决定

无效果整数块体运行时函数可在 `凡` 循环、`若`/`否` 分支或任意嵌套层执行 `返回 整数表达式。`。返回表达式先使用当前函数帧中的参数、顶层局部和块局部状态求值，再生成一个统一跳转到函数收束点的原生分支；函数收束点恢复 `x29`、`x30`、`x19` 并执行 `ret`。

本子门保持以下边界：

- 循环体和分支的返回表达式必须是整数或运行时整数；文本、容器和结果载荷仍由 `S-3068` 拒绝。
- 同一语句列表中，`返回` 后出现任何语句均被 `S-3068` 拒绝；条件分支中的提前返回不阻止其他可达分支继续执行。
- 函数顶层仍必须以整数 `返回` 结束，即使循环中已有提前返回。这保证当前有限分析至少存在一条显式回落路径。
- 返回表达式继续受无效果约束，`readInteger（）` 等隐藏 IO 以 `S-4106` 拒绝；返回不跳过函数帧恢复，也不改变现有整数寄存器 ABI。
- 文本/容器/效果函数返回、通用结果载荷和多返回值仍未进入该 ABI。

## 理由

编译器与运行时需要根据即时条件结束当前函数，例如记录首个越界位置、在扫描中出现终止标记或在嵌套循环中返回结果。把所有返回推迟到函数末尾会迫使调用者维护额外状态，并增加后续分支误执行的风险。统一收束跳转可复用现有直接调用帧，且无需引入新的调用约定。

## 验收

- `examples/p1b-runtime-loop-return.serica` 对输入 `5` 在第三次迭代返回 `30`，对输入 `2` 未命中并回落返回 `-1`。
- 原生门新增提前返回、未命中回落和嵌套循环返回 3 个产物；嵌套场景对输入 `3` 输出 `12`。三个产物均要求真实 `bl` 与 `ret`。
- `check` 与 `build` 新增循环内返回后不可达语句、文本返回和隐藏输入返回反例，分别返回 `S-3068`、`S-3068`、`S-4106`；旧“循环体返回尚不支持”诊断被移除。
- `make test-p1b-runtime` 通过 148 个 arm64 整数形态、其中 15 个运行时整数块循环函数产物、255 个编译诊断和 116 个运行时拒绝样例。
- `make seed-audit` 通过 8910/12000 行及 C-1 5894/8535（69.1%）。
- P1b 阶段门仍未通过；文本/容器返回值、通用结果载荷、效果函数帧和跨函数错误恢复留待后续子门。
