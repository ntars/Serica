# D-0064 纯表达式函数与能力边界

状态：已定案（P1b 函数组合子门；不构成完整函数系统）

## 背景

P1b 已有表达式、运行时变量和控制流，但无法定义可复用计算，也无法拆分编译器所需的语言逻辑。D-0063 已为控制台 IO 建立入口能力检查；新增函数不能成为绕过能力检查或隐藏可变状态修改的路径。

## 决定

- 增加顶层表达式函数语法 `函数 名称（参数，…）=表达式。`。名称与参数为以中文汉字开头的标识符；函数体是单个返回表达式，类型按每个调用处的参数推断。
- 这一子门只接受纯函数：函数体不得调用 `readInteger`、`readText`、`arrayPush` 或 `arraySet`。这些 IO/变更操作尚无函数级能力签名；使用它们时返回能力诊断，不能借用调用方的根能力隐式通过。
- 支持函数嵌套调用和通过静态模块闭包导入；检查重复定义、重复参数、实参数量、未知调用和递归。纯函数以有界 AST 展开实现，不生成运行时调用约定；设置展开深度上限，后续可替换实现而不改变源码语义。
- 参数以绑定值替换，调用点经过现有统一类型检查和原生代码生成。为保持展开语义，调用实参限整数/字符串字面量或变量/常量引用；复合表达式先写入变量再传参，参数必须在函数体中使用。函数表达式可以参与现有运行时整数/文本上下文；不提供语句函数、闭包、泛型、递归、函数值或函数级副作用声明。

此决定不开放一般 IO、不改变 D-0063 的入口能力规则、平台 ABI 白名单、依赖、许可、自举和 6500 行临时种子上限。完整 P1b 阶段门仍未通过。

## 验收

- [x] 运行时整数与 UTF-8 文本变量参数、嵌套纯函数在原生 ARM64 产物中得到独立预期结果；静态上下文可编译期求值。
- [x] 模块闭包中的纯函数可按稳定顺序导入；跨模块重复名称、重复参数、错数量、未知函数、直接/间接递归、非法复合实参及展开超限得到诊断。
- [x] 纯函数隐藏 `readInteger`/`readText`/`arrayPush`/`arraySet` 时由 `check` 和 `build` 拒绝；根声明 `stdin` 也不能替代函数级能力签名。
- [x] P0b、静态、模块、运行时、Go 子集/归因、doctor、许可、源码独立性门全部通过；种子为 6174/6500 行。

## 边界

该方案用有界 AST 展开换取较小的临时桥实现；它不代表运行时函数 ABI 已定。递归与效果函数必须在后续类型系统中具备显式签名和调用图检查后才可启用。
