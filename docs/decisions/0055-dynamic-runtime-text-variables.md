# D-0055 动态 UTF-8 文本变量

状态：已定案（P1b 子门；不代表阶段门通过）

运行时文本变量保存映射指针、UTF-8 字节长度和容量。初始化时分配 64 字节；变量初始化或赋值为 `readText（）` 时，若输入超出容量则按几何级数增长，最大映射容量为 16 MiB。实现会复制现有有效字节并解除旧映射。输入按单行读取，移除 LF/CRLF，校验完整 UTF-8 后才写入长度；映射失败、读失败、非法 UTF-8 或超出容量时以非零退出，stdout 不含部分结果。最大有效内容为 16 MiB−1 字节，为 UTF-8 校验及输出终止字节保留容量。

动态变量可用于输出、文本长度、字节相等条件及 Unicode 码位排序条件。运行时 `textConcat` 仍限制结果不超过 63 字节；`substring` 仍限制索引在 0–63，但会从完整动态文本中按码位扫描，因而 UTF-8 字节偏移可超过 63。直接将 `readText（）` 放在程序根输出或 `textLength（readText（））` 的现有路径仍使用原 63 字节缓冲区。此决策不增加任意嵌套动态文本表达式、文本数组、哈希表、结构化错误值或一般文件/进程 IO。

运行时文本变量产物按需仅导入系统 `_mmap`/`_munmap`；读取依旧使用登记的 `_read`，输出使用 `_write`。映射在扩容时释放旧缓冲区，进程退出时由系统回收最终映射。

## 验收

- `make test-p1b-runtime` 实际执行 ARM64 Mach-O，验证小输入、多次扩容后的 100 个补充平面码位、重复读取增长、独立变量映射、长文本长度/相等/排序、90 字节 UTF-8 偏移切片，以及非法 UTF-8 无输出。
- 同一子门接受最大有效内容 16 MiB−1 字节并检查 `textLength`，拒绝 16 MiB 内容且 stdout 为空；拼接继续拒绝超过 63 字节的输入文本结果。
- 当前子门运行 73 个整数 Mach-O，覆盖 98 个成功文本输入、55 个编译诊断及 72 个运行时拒绝样例；文本变量产物导入限于 `_read`/`_write`/`_exit`/`_mmap`/`_munmap`。
- `make seed-audit` 检查活动 Go 种子 5317 行（5500 行上限）及完整逐行归因；P1b 阶段门仍未通过。哈希表、结构化错误传播、一般文件/进程 IO 和 Serica 编译器仍未实现。
