# D-0209 标准错误精确写入边界

状态：已定案

## 背景

D-0206 已建立精确标准输出写入，但控制台诊断仍只能混入 stdout，或在失败路径直接无输出退出。语言需要一个与 stdout 分离、可捕获、可计算写入字节数的标准错误边界，为后续结构化诊断和完整进程 IO 打基础。

## 决定

- 新增内建表达式 `writeError（文本）`，向文件描述符 2 精确写出有效 UTF-8 字节，不追加换行，返回实际写入字节数。
- 程序根、函数和调用链须声明 `stderr` 能力；缺少根能力以 `S-4102` 拒绝，隐藏或漏传函数效果以 `S-4106` 拒绝，不得借用 `stdout` 或静默回退。错误元数与非文本参数使用独立诊断 `S-3085`。
- 原生桥复用 D-0206 的短写循环，只切换文件描述符；短写推进、零进展失败和部分累计语义与 `writeText` 一致。
- 自编前端同步登记内建编号 `53`、`stderr` 效果位 `128`、一个文本参数和整数结果，并覆盖元数与参数类型诊断。能力名称表增至八项会多占一个自编译根槽；根因修复复用 `效果根记录` 的非零状态替代冗余 `效果根` 布尔标志，释放一个状态槽，不提高 502 槽硬上限。
- 本次只开放标准错误流。标准输入字节流、文件句柄、缓冲配置、信号、子进程和通用进程 IO 仍未开放。

## 验收

- `make test-p1b-runtime` 必须分别捕获 stdout 与 stderr，验证补充平面 UTF-8、空文本、顺序写入、运行时文本和写入字节计数。
- 缺少 `stderr`、隐藏函数效果、错误元数和非文本参数必须被拒绝；模块效果门和模块类型门须同步覆盖。效果来源数组扩展到八项后不得改变源码诊断位置。
- 既有 `_write` 导入白名单、`writeText` 回归、全量源码门、种子审计和源码独立性检查继续通过。

## 后果

程序可以生成与正常输出分离的精确字节流，并以返回计数参与控制流。该边界不等于完整日志、结构化诊断或通用 IO；P1b 阶段门仍未完成。
