# D-0207 Darwin stat 缓冲区覆盖根因

状态：已定案

## 背景

新增 `writeText` 返回值回归时，`writeText（『帧』）` 后调用 `isDirectory（『.』）` 会把已取得的写入字节数破坏为 0，而单独调用两者均正常。继续检查发现该问题不是 `writeText` 的返回值约定错误，而是三个既有文件元数据原生桥共享的栈帧缺陷。

## 决定

- Darwin arm64 的 `struct stat` 大于原临时帧预留的 128 字节。`fileSize`、`exists` 和 `isDirectory` 原先把 `stat` 写到 `sp+32`，会覆盖 `sp+0` 保存的调用方返回值。
- 三个发射路径统一扩大临时帧到 176 字节，并把 `stat` 缓冲区放到 `sp+32`；保存的返回值继续位于 `sp+0`，调用参数位于其后的独立槽位。
- `isDirectory` 的临时帧此前还缺少 `sp += 160` 恢复，导致栈指针在查询后永久偏移；该路径现与 `fileSize`、`exists` 一样在成功和失败出口恢复栈指针。
- 修复只调整既有元数据桥的帧布局和收束点，不改系统调用顺序、能力检查、路径规则或返回语义。

## 验收

- `make test-p1b-runtime` 新增 `writeText` 结果跨越 `isDirectory`、`fileSize` 和 `exists` 仍保持正确的执行用例。
- 既有文件大小、存在性和目录类型查询的分支、导入白名单、拒绝样例以及模块效果/类型测试继续通过。
- 该缺陷由 D-0206 的组合测试暴露，但按独立根因单独记录，避免把栈损坏修复静默并入新表达式实现。

## 后果

文件元数据查询不再覆盖此前取得的标量返回值，也不会在返回后遗留错误栈偏移。P1b 的通用文件句柄、目录遍历和进程 IO 仍未完成。
