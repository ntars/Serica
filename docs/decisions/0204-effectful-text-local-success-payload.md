# D-0204 效果语句体文本局部与成功载荷

状态：已定案

## 背景

D-0203 已让普通运行时文本变量进入成功结果载荷，但效果语句体函数仍不能直接把 `readText（）` 存入文本局部。`check` 在局部变量处报 `S-4106`，因为效果支持白名单只在结果局部的 `成功（...）` 路径允许 `readText`；文本局部的初值和赋值仍按无输入副作用处理，随后又被独立副本检查拒绝。

代码生成实际已经具备 `readText（）` 写入函数文本局部、几何扩容、函数收束清理和结果深复制路径。阻断点位于语义层的两处旧限制，而不是原生发射能力。

## 决定

- 效果语句体函数的运行时文本局部可在声明初值和后续赋值中直接使用 `readText（）`；函数仍须声明 `stdin`，程序根仍须声明对应能力。
- `成功（文本局部）` 可包装该局部并返回调用方；结果局部拥有独立四槽缓冲，函数退出时文本局部的映射按既有收束路径释放。
- 重赋值继续使用既有文本局部动态读取与容量策略，不从旧映射借用描述符。
- 该开放只适用于文本局部进入结果载荷。效果函数直接把 `readText（）` 文本局部作为普通文本返回值仍走另一条纯块降级/所有权路径，当前继续拒绝；递归运行时结果 ABI、容器结果载荷、跨函数错误恢复和完整效果函数 ABI 未开放。

## 验收

- `make test-p1b-runtime` 新增 1 个效果语句体函数执行用例：首次读取 `第一行`，随后把同一文本局部重赋值为 `𠮷第二行`，再包装成 `成功` 结果并返回调用方。
- 根输出精确为 `𠮷第二行`，同时覆盖补充平面 UTF-8、文本局部重赋值、成功载荷深复制和函数返回路径。
- 运行时门现为 251 个 arm64 整数形态产物、29 个函数结果边界产物、182 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例。
- 活动种子压缩空白和重复初始化后为 12498/12500 行，归因完整；C-1 为 4894/12316（39.7%）。

## 后果

效果语句体现在可直接读取、保存和重赋值运行时文本局部，并把它包装成成功结果。直接效果文本返回、通用效果函数 ABI、递归结果 ABI、容器结果载荷、跨函数恢复和完整 IO 仍未实现；P1b 完整阶段门仍未通过，本轮不创建发布包。
