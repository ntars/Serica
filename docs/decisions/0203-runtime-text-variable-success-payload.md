# D-0203 普通运行时文本变量进入成功结果载荷

状态：已定案

## 背景

D-0202 已让 `成功（...）` 接受直接运行时文本和编译期文本，但普通运行时文本变量的结果载荷判定仍不完整。`check` 接受 `成功（文本变量）`，`build` 却按整数表达式处理同一个引用；直接 `结果值（成功（文本变量））` 报“控制台整数表达式无法解析常量”。

根因是生成器的结果载荷分类只检查显式文本生产者，没有把已分配文本槽的引用覆盖进去。语义层的统一载荷判定虽然能识别引用，但生成器在根输出和结果变量初始化前仍靠局部的一次性生产形态分支决策。

## 决定

- 已存在的运行时文本变量可作为 `成功` 载荷，包括 `readText（）`、受支持拼接/切片、文本数组元素、环境变量和无效果函数文本形参等已进入文本槽的引用。
- 结果变量持有四槽文本缓冲区并对源文本执行深复制；之后修改、拼接或重赋值源变量不影响结果载荷。
- 直接 `结果值（成功（文本变量））`、`textLength（结果值（成功（文本变量）））`、`是否失败（成功（文本变量））` 和 `错误码（成功（文本变量））` 可用。直接观察使用既有临时结果槽，输出、计长或状态观察后释放临时映射。
- 无效果纯函数的文本形参可包装为成功结果并交回调用方；返回值继续使用既有文本结果 ABI。效果语句体函数的局部成功文本变量构造、递归运行时结果 ABI、通用容器结果载荷、容器逃逸和跨函数错误恢复仍未开放。
- 生成器的最小载荷识别辅助只补充文本槽引用，不改变其他结果形态的判定顺序。

## 验收

- `make test-p1b-runtime` 新增 5 个执行用例：结果变量文本载荷及源变量后续修改、直接结果输出、长度观察、状态/错误码联合观察，以及文本形参包装后返回调用方。
- 直接输出输入 `𠮷直接载荷`，验证补充平面 UTF-8 的复制与输出；输入 `行简` 验证长度 `2`、状态 `0` 和错误码 `0`。
- 源变量在结果保存后追加尾文本，输出仍为原始输入，证明结果缓冲与源变量独立。
- 运行时门现为 250 个 arm64 整数形态产物、28 个函数结果边界产物、182 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例。
- 活动种子 12500/12500 行且归因完整，C-1 为 4896/12318（39.7%）。种子预算已用满；后续新增桥代码必须先压缩等量行或由新决策审查扩额。

## 后果

普通运行时文本变量现在可进入成功结果边界并接受直接观察，结果变量保持深复制语义。动态文本分支、效果函数局部成功文本构造、递归结果 ABI、通用容器结果载荷、容器逃逸、完整效果函数 ABI、通用调用求值顺序和跨函数错误恢复仍未实现；P1b 完整阶段门仍未通过，本轮不创建发布包，也不宣称语言完成。
