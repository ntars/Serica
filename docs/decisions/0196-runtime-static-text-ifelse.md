# D-0196 运行时条件选择静态文本分支

状态：已定案

## 背景

`ifElse` 的真、假分支同为编译期字符串且条件含运行时值时，语义层已能推导 `运行时字符串`，但原生代码生成没有根输出分支；仅开放静态文本作为分支操作数，就能闭合一个确定的文本选择闭环，不必扩大到任意运行时文本表达式。

## 决定

控制台根输出在 `ifElse` 的静态字符串分支上生成条件跳转：条件为真时写出真分支常量及换行，为假时走补丁后的假分支；D-0197 后续把分支选择抽成共享操作数，两个文本常量独立进入 `__cstring` 段，换行由根输出单独写出，不复用相邻数据、不依赖未初始化栈区，也不改变现有运行时文本数组、拼接与函数文本 ABI。

该能力仅是 P1b 的小步闭环：动态文本分支、将文本 `ifElse` 用作子串/比较/容器操作数及跨函数文本恢复仍按既有边界拒绝。

## 验收

- `make test-p1b-runtime` 通过：同一源码输入 `1` 输出 `甲\n`、输入 `2` 输出 `乙\n`；两个产物通过 Mach-O、签名、导入白名单和反汇编结构校验。
- 全量源码门、doctor、license、ci-preflight 与 seed-audit 通过；运行时门现为 215 个 arm64 整数形态产物、168 个成功文本输入、349 个编译诊断与 123 个运行时拒绝样例。
- `make seed-audit` 报 10 个活动源码文件、12465/12500 行、归因完整；C-1 为 4890/12281 行（39.8%），未触发 AST 比例复核条件。

## 后果

静态文本分支选择已有真实 ARM64 条件跳转和 UTF-8 输出证据；P1b 完整阶段门仍未通过，且本次不创建新发布包、不宣称语言完成或具备正式分发资格。
