# D-0213 源码 NFC 诊断进入编译器门

词法规范 `docs/spec/lexical.md` 已要求源码为 NFC，但此前只有 `tools/punct_scan.py` 在仓库扫描时检查，编译器 `serica lex/check/build` 仍接受分解形式。该缺口使同一字符的 NFC 与 NFD 写法可以生成不同常量字节，规范与实现不一致。

本决策在种子词法入口拒绝源码中的 Unicode 组合标记（Mn/Mc/Me），以 `S-1004` 报告首个标记所在行列、实际码位并建议直接输入合成字符或由编辑器在保存前规范化；绝不自动改写源码，也不执行 NFKC。此规则是本项目 NFC 输入约束的可审计实现：所有允许的连接形式须由预组字符表示，既有示例和编译器源码的 NFC 扫描仍由 `punct_scan` 独立复核。诊断覆盖所有源码入口（顶层入口和模块读取），字符串与注释同样适用，因为规范化边界属于源文件字节，而不是某个词元类别。

验收：`make test-p1b-lex` 增加 NFC 正例和分解形式反例，分解字符出现在字符串、注释和标识符中时均须稳定报告 `S-1004`；模块读取复用同一词法入口；`make verify` 完整门链通过。该规则是既有 D-0012 冻结符号表与词法规范的实现收口，不增加语言特性，不改变运行时文本比较的无归一化语义。
