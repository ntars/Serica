# D-0100 动态命令行下标与参数文本存储

状态：已定案（P1b 子门；不代表阶段门通过）

> 参数文本未存储时直接参与拼接、切片和结果载荷的边界其后由 D-0102 开放。

## 决定

`argumentText（下标）` 的下标在 D-0096 的编译期整数基础上开放运行时整数变量和纯整数表达式。静态负下标继续由 `S-3069` 拒绝；运行时下标在原生代码中先求值，再检查 `0 ≤ 下标 < argc`，不合法时保持 stdout 为空并退出 `2`。

参数值仍是 dyld 启动 ABI 提供的只读 NUL 终止文本。每个参数最多扫描 4096 字节；超过上限时无 stdout 退出 `3`。扫描成功后先完整校验 UTF-8，无效文本由既有无输出失败路径退出。选择、校验和复制都不改写 `argv`。

原生入口把 `argc`/`argv` 缓存到舞台栈帧，后续文本操作可以复用通用寄存器而不丢失进程参数。校验参数文本时，目标长度、目标缓冲寄存器也临时保存在栈上，避免既有 UTF-8 校验器使用 `x20`、`x21`、`x22`–`x25` 时破坏通用调用方状态。

`argumentText` 结果现在可以：

- 直接作为根文本输出；
- 初始化或更新普通动态文本变量；
- 初始化文本数组元素；
- 作为 `textLength（argumentText（下标））` 的操作数；
- 经变量存储后进入既有长度、比较、拼接、切片、结果和数组路径。

普通文本变量首次位于栈上的 64 字节映射不足时，复制前按“参数字节数 + 换行”建立新映射，复制有效字节并规范化 LF，再解除旧映射并原子更新描述符。文本数组继续按元素深复制。

直接运行时参数文本尚未开放为 `textConcat`/`substring` 的未存储操作数，也尚未作为成功结果载荷；调用函数时仍须逐层声明 `args`，根程序仍须声明该能力。

## 理由

编译器入口需要根据用户输入或计算后的值选择源文件、输出路径和诊断上下文。只支持静态下标会把参数读取限制为一组写死分支，也无法验证参数文本进入语言值系统后的所有权和长度规则。本子门把下标求值、启动 ABI 边界、UTF-8 校验和动态存储连接起来，同时继续拒绝环境变量、参数改写和任意进程控制。

实现中还修复了 D-0096 参数扫描循环只回跳到多指令立即数装载中段的问题。旧循环会把刚读入的字符字节当作下一次扫描上限，导致短 ASCII 参数偶然通过、较长参数提前误报退出 `3`；现在每轮都重新装载完整 4096 上限。

## 边界

- 不提供环境变量、参数改写、`argv` 容器值、环境指针或任意进程控制。
- 参数扫描上限仍为 4096 字节；不把参数扫描描述为通用 C 字符串库。
- 参数下标结果若大于 `i64` 或由错误整数表达式产生，沿用既有整数运行时失败，不产生部分 stdout。
- 不改变系统符号白名单、Go 子集、逐层归因、源码/产物独立性及 P3b 删除 `bootstrap/` 的硬门。

## 验收

- `examples/p1b-runtime-argument-dynamic.serica` 以整数变量下标 `1` 输出第一个用户参数。
- 原生门覆盖整数变量下标、运行时 `readInteger（）` 下标、普通文本变量初始化与重赋值、超过 64 字节的中文参数复制、动态文本数组元素、`textLength` 和补充平面 UTF-8。
- 运行时负数下标和超过实际 `argc` 的下标均保持 stdout 为空并退出 `2`；没有 NUL 或超过 4096 字节的参数退出 `3`；无效 UTF-8 不产生部分输出。
- `check`/`build` 以 `S-3069` 拒绝负数静态下标、错误参数数量和错型下标；动态/非负整数下标获得类型 `运行时字符串`。

- 完整硬门 `make stage0 test-p0b-scope test-p1b-static test-p1b-modules test-p1b-runtime doctor license seed-audit` 复跑通过；源码独立性、参数示例 NFC/半角标点/禁用字符、JSON 解析和 `git diff --check` 同时通过。
- `make seed-audit` 通过 7967/8000 行及 C-1 5879/7617（77.2%）。本子门验收完成，但 P1b 阶段门仍不因本子门自动通过。
