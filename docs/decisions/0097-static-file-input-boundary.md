# D-0097 静态路径文件输入边界

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

控制台程序可按需声明 `filesystem.read` 能力，并以 `readFile（路径）` 直接输出一个普通文件的内容：

```serica
程序=【能力=array（『stdout』，『filesystem.read』），输出=readFile（『examples/p1b-runtime-file-fixture.txt』）】。
```

- `readFile` 只接受一个非空、不含 NUL 的编译期文本路径。路径按进程当前工作目录解析，不执行环境变量、波浪号或 shell 展开。
- 文件内容上限为 16 MiB−1 字节。合法文件先完整读取、关闭，再执行 UTF-8 标量编码校验；校验通过后才输出内容和一个终止换行。空文件输出一个换行。
- 打开、读取、关闭、映射、超限或 UTF-8 校验失败均以非零状态退出，且 stdout 为空。直接根输出不暴露部分文件内容。
- 原生后端直接调用已登记的系统 ABI：`_open`、`_read`、`_close`，并复用现有匿名虚拟内存映射的 `_mmap`、`_munmap` 以及控制台的 `_write`、`_exit`。不引入 C/Go 运行时、第三方源码或仓库内依赖。
- 文件读取属于显式效果。函数使用 `readFile` 时必须声明 `filesystem.read`，每个调用方函数都须逐层传递该效果，根程序须声明同名能力。
- 本子门只允许直接根输出。文件内容尚不能写入文本变量、容器、字符串拼接、切片或结果载荷；这些生命周期与所有权边界留给后续子门。

## 理由

编译器要读取 `.serica` 源文件，首先需要一条可审计的文件输入路径。先锁定静态文件名、严格大小上限、关闭后校验和无部分输出，可以证明原生文件 IO 的安全边界，同时把动态路径、长生命周期缓冲和通用文件系统操作隔离开。选择一个独立能力名也让模块、函数和根程序的效果声明能覆盖后续通用的文件读写。

## 边界

- 路径是编译期常量；不接受 `readText（）`、`argumentText（）`、变量或任何运行时表达式。
- 不区分文件类型、不跟随 shell 语义，也不提供目录枚举、文件元数据、文件写入、网络或进程 IO。
- 16 MiB−1 字节是当前文本输入上限；失败路径必须在 stdout 写入前完成。
- 输出规范化追加一个换行。若文件自身已经以换行结尾，直接根输出会出现连续换行；这不改变读取得到的字节数或 UTF-8 校验范围。
- 不改变系统符号白名单、Go 子集、逐行归因、源码/产物独立性及 P3b 删除 `bootstrap/` 的硬门。

## 验收

- `examples/p1b-runtime-file.serica` 读取 `examples/p1b-runtime-file-fixture.txt` 并输出 `行简文件读取\n`。
- 原生门执行 ASCII、中文 UTF-8、空文件和最大合法 16 MiB−1 字节文件；另测缺失文件、非法 UTF-8 与 16 MiB 超限文件，后三者均 stdout 为空且非零退出。
- 文件产物只导入 `_open`、`_read`、`_close`、`_mmap`、`_munmap`、`_write` 与 `_exit`；`file`、`dyld_info -validate_only`、`otool -L`、`codesign --verify --strict` 和未定义符号集合检查通过。
- `check` 与 `build` 以 `S-3070` 拒绝参数个数错误、动态或非文本路径及空路径；以 `S-4102` 拒绝缺少根 `filesystem.read` 能力，以 `S-4106` 拒绝未声明或未逐层传递的文件读取效果，并以 `S-3044` 拒绝本子门尚不支持的文本变量存储。
- P1b 阶段门仍未通过；通用文件读写、动态文本缓冲装载和 Serica 编译器尚待后续子门。
