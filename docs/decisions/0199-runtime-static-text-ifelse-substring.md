# D-0199 运行时文本分支作为有界切片源

状态：已定案

## 背景

条件选择的两个编译期文本分支已能进入根输出、长度和比较，但 `substring` 的源码边界仍只接受变量、参数文本、结果值、`textConcat`、数组元素和直接输入。切片原生实现已经先求值源描述符并保存到栈槽，再求值索引，因此可安全复用共享的条件文本选择器。

## 决定

`ifElse（运行时条件，编译期文本，编译期文本）` 现可作为 `substring` 的源。条件可依赖运行时整数或运行时文本比较；真、假分支各自使用独立 UTF-8 常量，真实 ARM64 条件跳转选出缓冲区与字节长度，再由既有码位扫描、边界检查和有界复制逻辑切片。切片结果继续可用于根输出、文本排序、拼接和比较等既有受限消费者。

两个分支仍必须是编译期字符串。动态文本分支及条件选择进入容器或跨函数恢复继续拒绝。

## 验收

- `make test-p1b-runtime` 新增四个实际执行用例：
  - `substring（ifElse（数值==1，『甲乙』，『丙丁』），1，2）` 输入 `1` 输出 `乙\n`、输入 `2` 输出 `丁\n`。
  - 以 `equals（文本，『x』）` 选择 `『ab』`/`『cd』`，切片后与 `『b』` 排序的结果输入 `x\n` 输出 `1`、输入 `y\n` 输出 `0`。
- 原先以 `S-3013` 拒绝“动态条件文本切片”的反例已由两个真实执行正例取代；运行时门现为 223 个 arm64 整数形态产物、168 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例。
- 全量源码、模块、原生发射、doctor、license、ci-preflight 与 seed-audit 门通过；活动种子 12477/12500 行、C-1 4893/12293（39.8%）。

条件选择的已知文本现在覆盖输出、长度、比较和切片四类消费者，且切片源与索引求值顺序由既有栈槽保存保证。P1b 完整阶段门仍未通过，本轮不创建发布包，也不宣称语言完成。
