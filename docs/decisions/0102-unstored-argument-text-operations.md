# D-0102 未存储参数文本组合与结果载荷

状态：已验收（P1b 子门；不代表阶段门通过）

## 决定

`argumentText（下标）` 不再要求先写入普通文本变量，才能进入语言的其他文本路径。本子门开放：

- 作为 `textConcat` 的左或右操作数；
- 作为 `substring` 的直接源，继续使用 0–63 的 Unicode 码位半开区间；
- 在 `equals`、`notEquals` 和文本排序条件中与静态文本及既有运行时文本操作数比较；
- 作为 `成功（argumentText（下标））` 的运行时文本载荷，复制到结果变量自己的 16 MiB−1 字节映射；
- 经既有 `结果值`、`textLength`、根输出及复制路径继续使用。

参数装载仍执行 `0 ≤ 下标 < argc`、单参数 4096 字节扫描和完整 UTF-8 校验。拼接、切片和结果写入在操作完成前传播既有错误码或退出状态，不产生部分 stdout。参数文本进入结果时获得独立内容副本，之后的参数读取或文本变量更新不会改变该结果。

本子门不新增参数改写、环境变量、环境指针、`argv` 容器、任意进程控制或超过 4096 字节的参数读取；`substring` 的 0–63 码位边界不变。

## 理由

编译器入口需要把参数文本直接用于拼接、截取和结果传播。强制先声明临时文本变量会扩大调用方状态并让纯表达式函数更难表达同类操作。底层通用文本操作数装载已经能读取缓存的 `argv`，本子门把语义检查、条件动态性和结果所有权路径补齐，并用原生产物验证真实寄存器与缓冲区边界。

## 验收

- `examples/p1b-runtime-argument-combine.serica` 对参数 `行简` 输出 `行简尾`，覆盖未存储参数文本的两段切片和多层拼接。
- `examples/p1b-runtime-argument-result.serica` 把参数文本直接装入成功结果并输出。
- `make test-p1b-runtime` 新增未存储拼接、切片、相等、成功载荷和结果码位长度 5 个成功产物；参数文本结果产物按需导入 `_mmap`/`_munmap`，拼接与切片产物仍只需 `_exit`/`_write`。
- 既有参数边界继续覆盖动态下标、文本变量重赋值、文本数组存储、4095/4096 字节、无效 UTF-8、负数与越界退出。
