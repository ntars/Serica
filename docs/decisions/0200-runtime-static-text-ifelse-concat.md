# D-0200 运行时文本分支作为拼接操作数

状态：已定案

## 背景

条件选择的已知文本已覆盖输出、长度、比较和切片，但 `textConcat` 的类型边界仍拒绝该表达式。拼接原生实现本来按左右顺序求值文本操作数，并在求值右操作数前把左描述符保存到临时栈，因此共享条件文本选择器可以安全进入左右任一位置。

## 决定

`ifElse（运行时条件，编译期文本，编译期文本）` 现可作为 `textConcat` 的左或右操作数。共享选择器用真实 ARM64 条件跳转选出独立 UTF-8 常量的缓冲区与字节长度；拼接路径保存左描述符后求值右侧，再执行既有 63 字节边界检查、复制和终止字节写入。

两个分支仍必须是编译期字符串。动态文本分支及条件选择进入容器或跨函数恢复继续拒绝。

## 验收

- `make test-p1b-runtime` 新增四个实际执行用例：`textConcat（ifElse（数值==1，『甲』，『乙』），『丙』）` 输入 `1`/`2` 输出 `甲丙`/`乙丙`；`textConcat（『丙』，ifElse（数值==1，『甲』，『乙』））` 输入 `1`/`2` 输出 `丙甲`/`丙乙`。
- 运行时门现为 227 个 arm64 整数形态产物、168 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例；D-0196 至 D-0199 的十例继续通过。
- 全量源码、模块、原生发射、doctor、license、ci-preflight 与 seed-audit 门通过；活动种子 12477/12500 行、C-1 4893/12293（39.8%）。

## 后果

条件选择的已知文本现在覆盖输出、长度、比较、切片和左右拼接消费者。P1b 完整阶段门仍未通过，本轮不创建发布包，也不宣称语言完成。
