# D-0096 命令行参数边界

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

控制台程序可按需声明 `args` 能力，并读取自身命令行参数：

```serica
程序=【能力=array（『stdout』，『args』），输出=argumentText（1）】。
```

- `argumentCount（）` 返回包含可执行文件路径在内的参数总数，类型为运行时整数。
- `argumentText（下标）` 以 0 至 255 的编译期整数下标读取一个参数，要求该下标对应实际存在的参数；当前输出路径把参数值视为运行时文本。
- 原生入口从 dyld 传入的 `x0`/`x1` 保存 argc 与 argv，再建立舞台帧；参数读取只访问进程启动 ABI 提供的内存。
- 每个参数按 NUL 终止扫描，最多读取 4096 字节。缺少该参数时静默退出 2；扫描超过上限时退出 3。直接根输出前执行完整 UTF-8 校验，无效文本不会产生部分 stdout。
- 参数文本目前只支持直接根输出，以及在有界 AST 函数展开后作为根输出；尚不能写入文本变量、容器或结果载荷。
- 参数读取属于显式效果。函数使用 `argumentCount`/`argumentText` 时，必须在每层函数签名声明 `args`，根程序也必须声明 `args`。
- 本子门不新增系统动态库符号；仍只使用登记的 `_write`、`_exit`，按需使用既有的 `_read`、`_mmap` 和 `_munmap`。

## 理由

编译器入口首先需要知道“调用的是哪个源文件”和“输出到哪里”。先建立只读、静态下标、UTF-8 校验的命令行参数边界，可以从真实进程入口取得路径文本，同时把动态字符串存储、文件读写和参数索引求值留给后续子门。该边界也验证了函数效果系统能够把进程输入传递到调用链根。

## 边界

- 不提供动态参数下标、环境变量、参数改写、`argv` 容器值或任意进程控制。
- 不把参数文本直接存进普通文本变量；当前全程序生命周期内只允许直接输出。
- 参数扫描不是通用 C 字符串库；4096 字节是当前明确上限，超出即失败。
- 不改变系统符号白名单、Go 子集、逐行归因、源码/产物独立性及 P3b 删除 `bootstrap/` 的硬门。

## 验收

- `examples/p1b-runtime-arguments.serica` 在第一个用户参数为 `甲乙` 时输出 `甲乙\n`。
- 原生门另行执行 `argumentCount（）`，以两个用户参数得到 `3\n`；用编译期常量下标读取参数并通过带 `args` 效果的表达式函数返回文本，也得到预期 UTF-8 输出。
- 缺少调用下标对应的参数时，产物在 stdout 为空时退出 2。
- `check` 与 `build` 以 `S-3069` 拒绝参数个数错误、负数下标和运行时下标，以 `S-4102` 拒绝缺少根 `args` 能力，以 `S-4106` 拒绝未声明 `args` 的函数效果。
