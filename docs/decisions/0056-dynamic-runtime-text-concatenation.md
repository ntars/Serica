# D-0056 动态运行时文本拼接

状态：已定案（P1b 子门；不代表阶段门通过）

变量初始化或赋值中的 `textConcat（左，右）` 使用运行时文本字节长度，结果最多 16 MiB−1 字节。两个静态操作数仍各自限 63 字节；运行时变量操作数可使用完整的动态文本长度。根程序直接输出 `textConcat（…）` 保留 63 字节 scratch 上限，`substring` 索引也继续限制在 0–63。

拼接总长先与最大内容长度比较，且必须在任何输出前完成。实现为目标分配独立的动态映射，复制左右输入，写入 LF，再解除目标变量原有映射并提交新指针、长度和容量。原映射在复制完成前保持有效，因此目标可与任一输入别名。超限、映射失败或解除旧映射失败均以非零状态退出且不输出部分结果。仅使用登记的系统 `_mmap`/`_munmap`，不引入分配器或第三方运行时。

每次拼接都分配新映射并复制全部输入，单次 O(n)；重复向同一变量追加会重复复制，不承诺摊销 O(1)。未来可在安全证明和独立验收后复用目标容量。

## 验收

- `make test-p1b-runtime` 实际执行最大 16 MiB−1 字节变量拼接成功，以及 16 MiB 结果无输出失败；覆盖 64 字节扩容、补充平面 UTF-8、多次扩容和向任一源变量别名写回。
- 同一门继续通过直接根输出的 63 字节成功及超限失败、变量 UTF-8 校验、编译诊断和运行时拒绝；共执行 73 个整数 ARM64 Mach-O、101 个成功文本输入、55 个编译诊断和 70 个运行时拒绝样例。
- `make seed-audit` 检查活动种子 5384/5500 行、白名单子集及完整逐行归因。P1b 阶段门仍未通过；哈希表、一般容器、结构化错误传播、一般 IO 和 Serica 编译器仍未实现。
