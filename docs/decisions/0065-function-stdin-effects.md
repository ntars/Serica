# D-0065 用户函数的 stdin 效果签名

状态：子门通过（P1b 效果传递子门；不代表 P1b 阶段门通过）

## 背景

D-0064 为避免函数体隐藏 IO，限制所有用户函数为纯表达式。已有控制台根能力声明 `stdin`，但可复用函数无法显式表达输入效果，导致函数不能组合运行时输入。

## 决定

- 以可选语法 `函数 名称（参数，…）能力=array（『stdin』）=表达式。` 声明函数效果。未写签名表示纯函数。
- 当前函数签名只支持 `stdin`；函数体调用 `readInteger` 或 `readText` 必须声明该效果。调用方函数也必须逐层声明其被调函数的效果，效果不自动向上冒泡。
- 展开后的根程序仍由 D-0063 的根能力检查验证：经任意函数调用链输入时，`程序` 根必须声明 `stdin`。纯函数及缺少 `stdin` 签名的函数不能调用有输入效果的函数。
- `arrayPush`/`arraySet` 仍不允许出现在函数中；本决定不增加数组写入能力、stdout、其他 IO、递归或运行时调用 ABI。
- 未知/重复/非静态效果声明沿用 `S-4103`/`S-4104`/`S-4105`；未声明或未逐层传递效果返回 `S-4106`。不允许以根 `stdin` 声明替代函数签名。

此增量不改变平台符号白名单、运行时 ABI、许可、Go 子集/6500 行预算、自举独立性或 P3b 删除要求。

## 验收

- [x] `stdin` 签名函数和声明效果的嵌套调用可编译为原生 ARM64，并实际读入整数/文本得到独立预期输出。
- [x] 效果未声明、调用链漏签名、根能力缺失、未知/重复/错型效果均由 `check` 与 `build` 稳定拒绝。
- [x] 纯函数、模块导入、数组变更拒绝及 P0b、静态、模块、运行时、种子、doctor、许可和源码独立性门继续通过。证据与计数见 `DECISIONS.json` D-0065。

## 边界

函数仍由有限 AST 展开实现，不生成调用栈或 ABI。后续一般效果系统可扩展显式能力集合，但必须继续按调用图验证，不允许调用方根能力隐式穿透函数声明。
