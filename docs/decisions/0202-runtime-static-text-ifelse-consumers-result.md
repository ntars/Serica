# D-0202 运行时文本分支进入容器、函数与成功结果载荷

状态：已定案

## 背景

D-0201 把 `ifElse（运行时条件，编译期文本，编译期文本）` 登记为运行时文本，既让普通文本变量取得独立缓冲，也使共享文本分类开始覆盖其他消费者。审计发现该表达式已经能够进入文本数组构造、`arraySet`、`arrayPush`、无效果函数的只读文本实参和函数局部返回，但缺少正式回归证据，公开文档仍错误地声称这些路径全部拒绝。

`成功（ifElse（运行时条件，编译期文本，编译期文本））` 则只完成了一半：`check` 接受该结果载荷，`build` 却报“无法生成运行时文本结果载荷”。根因是结果发射器只处理直接输入、拼接、切片、文本数组元素和文本返回调用，没有复用统一的条件文本操作数选择器及结果复制路径。

## 决定

- 条件选择的两个分支仍必须是编译期 UTF-8 文本，动态文本分支继续拒绝。
- 文本数组可以以该表达式初始化，也可通过 `arraySet`/`arrayPush` 更新；数组复制选中分支的字节内容，不保存指向共享选择器栈描述符的引用。
- 该表达式可作为无效果运行时文本函数的直接实参，也可在函数顶层初始化文本局部并交给既有的有界返回所有权路径；不接受完整效果函数递归、容器逃逸或跨函数结果恢复。
- `成功` 接受该表达式作为文本载荷，包括直接 `结果值（成功（...））` 观察和先写入结果变量再观察。生成器先把选中分支复制到结果变量拥有的四槽文本缓冲区，再由既有结果输出路径释放，不借用分支常量或选择器临时区。
- 结果发射器抽出通用文本操作数复制辅助，文本数组元素和条件文本载荷共用同一容量检查、复制与终止字节写入实现。

## 验收

- `make test-p1b-runtime` 新增 14 个实际执行用例：条件文本数组构造、替换、追加各 2 例；直接函数文本实参 2 例；效果语句体函数局部条件文本返回 2 例；直接和结果变量成功载荷各 2 例。
- 输入 `1`/`2` 分别验证分支文本 `甲乙`/`丙丁`；函数实参用例同时以长度 `2`/`1` 证明调用前完成条件选择。数组产物验证 `_mmap`/`_munmap` 白名单及独立存储。
- 运行时门现为 245 个 arm64 整数形态产物、182 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例。
- 活动种子 12490/12500 行，逐行归因完整；C-1 为 4893/12306（39.8%）。全量源码、模块、原生发射、doctor、license 和 ci-preflight 在提交前复跑。

## 后果

条件选择的已知文本现在可进入已列出的容器、无效果函数和成功结果边界，并保持深复制或只读借用边界。动态文本分支、通用容器结果载荷、容器逃逸、完整效果函数运行时 ABI、通用调用求值顺序及跨函数错误恢复仍未实现；P1b 完整阶段门仍未通过，本轮不创建发布包，也不宣称语言完成。
