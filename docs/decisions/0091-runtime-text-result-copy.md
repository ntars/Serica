# D-0091 运行时文本结果独立复制

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

文本结果变量现在可以作为另一个同类文本结果变量的初始化值或赋值来源：

```serica
变量 原结果=成功（readText（））。
变量 副本=原结果。
赋值 原结果=成功（readText（））。
程序=【能力=array（『stdout』，『stdin』），输出=结果值（副本）】。
```

- 复制保留四槽布局中的标签、值或错误码、内容字节长度和成功载荷类型。
- 源结果持有运行时文本时，目标结果首次接收副本会建立自己的 16 MiB 匿名映射，只复制当前有效内容字节，并在目标缓冲区有效长度末端写入规范化换行。
- 副本创建后，源成功重赋值、失败替换或再次复制都不会改变目标内容；目标也可继续初化为另一个副本。
- 从失败结果复制时保留失败标签和 `1..255` 错误码，不复制旧成功载荷长度；随后 `结果值` 仍按该错误码无 stdout 退出。
- 编译期文本结果仍复制常量区指针；整数结果继续复制两槽。结果成功载荷类型在变量声明时固定，文本结果不能复制到整数结果，反之亦然。
- 文本结果槽预算按实际载荷计入：整数结果 2 槽，编译期或运行时文本结果 4 槽。

本决定只开放进程内深复制。所有权转移、共享引用、捕获、结果作为函数返回值、跨函数恢复和通用容器载荷仍未开放。

## 理由

深复制把结果值和拥有的动态存储绑定到同一个四槽描述符，避免源重赋值或失败替换后副本跟随源状态变化。复制仅按有效长度执行，既不需要暴露映射容量，也不改变已有根输出、文本操作和失败传播语义。

## 边界

- 复制仍要求两侧都是结果变量且成功载荷类型相同。
- 目标缓冲区在首次运行时文本复制或成功输入时建立，后续重赋值复用。
- 复制只保存有效内容和一个规范化换行，不承诺保留映射中的其余陈旧字节。
- 旧内存仍按进程生命周期保留，尚无显式释放、引用计数或所有权转移。
- 本决定不改变能力声明、系统符号白名单、Go 子集、逐行归因、源码/产物独立性和 P3b 删除 `bootstrap/` 的硬门。
