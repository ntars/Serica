# D-0145 递归结果函数的状态参数 ABI

递归运行时函数可把已有结果值的标签和值作为相邻两个整数寄存器传入，调用帧按 16 字节固定槽位保存这对状态。函数体可用 `是否失败`、`错误码` 读取结果参数状态，并把状态重新包装为成功或失败结果返回；调用方仍能读取返回结果的错误码与状态。整数载荷正例 `判（源）` 在失败码 7 上输出 `14`（失败变换）或 `0`（恢复为成功），递归累计结果保持既有 15 与 31 的返回证据。

补充验证覆盖自递归和互递归的“结果状态参数原样转发”正向例：调用方把失败结果传给递归函数，函数在终止分支直接返回该结果参数。产物经真实 ARM64 `bl`/`ret` 调用帧传播，终止分支直接返回参数时调用方可观察到原始失败码（自递归为 7，互递归为 9）。上一轮观察到错误码为 0 的根因是返回引用时把 x0/x1 写成载荷/标签，与 成功/失败 的标签/载荷顺序相反；现已按 `x0=tag`、`x1=payload` 修复。运行时门中另有普通递归整数结果 ABI 的 6 个既有正例和 5 个编译期文本结果 ABI 正例。

本轮排除了根因明确的调用帧回归：参数槽从原来每参数 8 字节改成紧凑布局后破坏了递归整数调用帧，已恢复每参数 16 字节固定槽；`emitRuntimeResultRegisters` 中把返回标签复制到 x1 的多余指令会覆盖既有结果值寄存器，也已移除。原生参照产物改按新槽位核对 `str x1, [x19, #0x10]`。

## 边界

- 只有递归运行时函数的结果状态参数进入该 ABI；普通静态函数仍按 AST 展开。
- 文本载荷结果跨函数传参、容器载荷结果、跨函数错误恢复的完整语义、效果函数运行时 ABI 和完整 P1b 仍未实现；本决策只覆盖整数状态标签和值域的调用帧传递。
- 失败码保持在 `1..255`，结果返回仍遵守既有 `x0` 标签、`x1` 载荷/错误码约定；文本结果继续由既有的静态/拥有映射 ABI 管理。

## 验收

`make stage0`、`make test-p1b-runtime`、`make test-p1b-module-abi` 与 `make seed-audit` 在 macOS arm64 通过。运行时门当时为 176 个整数形态产物、36 个运行时文本结果产物、22 个文本参数桥产物、10 个文本返回调用方存储产物、8 个递归整数结果 ABI 产物（含 2 个结果状态参数跨帧正例）、311 个编译诊断和 118 个运行时拒绝样例；模块 ABI 门核对 6 个原生参照产物、4 种返回约定和 81 个运行时示例。当时种子 10937/12000 行、C-1 4141/10432（39.7%），归因完整；当前基线见 D-0149。

P1b 阶段门仍未通过；本决策不宣称通用文本/容器结果载荷、完整 IO 或语言完成。

## 文本载荷结果传入纯函数（P1b 续）

运行时文本载荷结果作为非递归纯函数实参曾可被静默内联，错误码观察得到 0 而非编译期拒绝。根因是纯函数展开发生在结果载荷标注和调用点类型校验之前，且展开器不持有运行时结果环境。现由 `seedRuntimeResultPayloads` 在展开前计算独立载荷环境，展开器对文本载荷结果引用返回 S-3023；编译器测试与真实 ARM64 产物均验证拒绝路径。
