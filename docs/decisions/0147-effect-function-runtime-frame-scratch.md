# D-0147 效果函数运行时帧内暂存区

带 `stdin` 效果的块体函数可进入运行时函数 ABI；函数体中的 `凡` 循环可直接调用 `readInteger`，也可调用另一带 `stdin` 效果的函数。当前证据程序输入 `3/1/2/3` 输出 `15`，输入 `3/1/2/3` 的直接读取循环输出 `6`；循环函数调用链缺少 `stdin` 能力仍由 `S-4106` 拒绝。

## 根因

两个语义路径此前不一致：含 `凡` 的效果块函数若被排除在表达式 lowering 之外，却仍按旧规则从运行时函数表中排除，根调用就会成为未知调用并退化为 `S-3023`。即使恢复运行时注册，`emitReadInteger` 仍使用按程序根栈帧计算的 `temporaryBufferOffset`；运行时函数建立自己的 `x19` 帧后，该偏移指向函数帧之外，循环中的重复读取会破坏保存的帧指针、链接寄存器或局部槽，表现为退出码 1 或错误累加值。

## 修复

- 有语句体且带效果的函数保留运行时函数 ABI；纯表达式效果函数继续按既有表达式路径处理。
- 效果函数体中的 `凡` 循环不进入纯函数块 lowering，避免把循环语句错误降级。
- 进入运行时函数体时按状态槽数建立帧内暂存区，并在生成期间切换 `temporaryBufferOffset`；函数返回前恢复调用方偏移，使 `readInteger` 写入当前函数自己的栈帧。
- 显式效果能力检查覆盖循环体表达式与跨函数调用，根能力缺失继续报 `S-4106`。
- 运行时结果参数与文本参数一致，按相邻标签/值双寄存器计入展平 ABI 预算；混合整数与结果参数调用不再按单寄存器错位传参。

## 边界

- 本决策只闭合整数 `stdin` 读取与嵌套效果函数在运行时循环中的帧内暂存区问题。
- 通用文本/容器结果载荷、完整跨函数错误恢复、通用 IO、进程能力、通用容器和 P1b 完整阶段门仍未通过。

## 验收

macOS arm64 通过 `make stage0`、`make test-p1b-runtime`、`make test-p1b-static`、`make test-p1b-modules`、`make test-p1b-native-emit` 与 `make doctor`。运行时门包含嵌套效果函数循环正例输出 `15`、直接 `readInteger` 循环正例输出 `6`、`readInteger（）` 作为加法左操作数的效果函数循环正例输出 `6`、缺失 `stdin` 能力反例 `S-4106`。当前种子审计为 11897/12000 行、C-1 4838/11334（42.7%），归因完整。P1b 阶段门仍未通过。

## 续：读取原语寄存器边界

`readInteger` 不再把调用方 `x20` 缓存到 `x28`，而是进入时在自身 16 字节临时栈保存调用方 `x20`，收束前显式恢复并弹出。这消除了文本拼接等路径复用 `x28` 后错误恢复栈地址的风险，也让读取原语不依赖外部帧状态。右操作数读取循环已由现有门覆盖；左操作数读取与临时栈求值顺序耦合，仍列为边界。

## 续：状态边界

运行时函数体把失败分支补丁限制在当前函数帧内生成，返回前恢复调用方补丁列表；结果槽也限制为当前函数的参数和局部结果，不再按名字继承调用方或程序根槽。这防止后续函数或根表达式把失败分支改写到前一个函数，也避免同名结果变量错误访问当前 `x19` 帧偏移。

## 续：混合结果参数 ABI

`函数 转发（甲，源）` 同时接收普通整数和直接结果调用。输入 `3` 时结果为 `9`；输入 `-1` 时把错误码 `31` 与整数 `5` 组合并输出 `36`。两个混合参数正例已加入运行时门，证明结果参数在参数序列中按双寄存器参与调用帧，而不是只按槽位布局隐式补偿。
