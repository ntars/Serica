# D-0216 兼容策略与诊断格式草案成文

语言项目在 1.0 前可以频繁变更，但必须有可引用的规则，否则用户无法判断升级风险，贡献者也无法判断某个行为变化是否需要单独公告。本决策新增 `docs/spec/compatibility.md`：区分语言版本、编译器版本和种子预算版本；以“既有合法程序行为是否变化”作为版本位判定核心，明确 bug 修复导致行为变化也按 MAJOR（或显式 PATCH 公告）处理；定义弃用流程、平台事实与发布证据边界。该文档是策略草案，不宣称 1.0 已发布。

`docs/spec/diagnostics.md` 固化当前编译器的四段诊断格式，要求路径、行列、显示列、S-code、期望/实际/建议齐全；词法层错误允许 `0:0` 定位；运行时失败必须在 stdout 之前非零退出。该规范与 `conformance/` 的 9 个反例、`tools/test_p1b_*` 的位置断言相互支撑，但只记录当前实现约束，不表示 M4 规范冻结。
