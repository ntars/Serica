# D-0027：原生整数表达式与标准输出子门

## 决策

为推进 P1b，增加 `程序=【输出=整数表达式】` 入口。stage0 将整数字面量、整数常量引用、加减乘除、一元负号和 `bitAnd`/`bitOr`/`bitXor` 直接生成为 macOS arm64 指令；生成的 Mach-O 执行十进制转换并通过登记的系统 `libSystem` `_write` 向 stdout 输出一行整数，再以 `_exit` 结束。

此决策最初只涵盖固定整数表达式在原生产物中执行。D-0029 后续增加整数变量栈槽，D-0030 增加静态可证的变量运算，D-0032/D-0033 增加有界输入及输入变量，D-0034 增加带溢出/除零/移位检查的运行时算术。失败通过非零退出报告，仍无结构化错误值、恢复或传播；动态字符串、通用文件/进程 IO 和完整 P1b 也尚未实现。

## 边界

- Mach-O 与 ARM64 指令由仓库内后端直接写出；不生成 C、不调用外部编译器、汇编器或链接器、不包含 Go 运行时。
- 原生产物仅导入系统 `libSystem.B.dylib` 的 `_write` 和 `_exit`；平台范围仅为当前 macOS arm64。
- 此实现属于 D-0026 临时 Go 自举桥；正式编译器/运行时仍由 Serica 实现，P3b 删除整个 `bootstrap/`。
- P1b 总门仍要求完整变量语义及运算、运行时字符串、动态数组/哈希表、一般 IO、错误传播、模块与编译器表达能力。

## 验收

- `make test-p1b-runtime` 编译并实际执行 9 个 Mach-O 样例，检查加减乘除、位运算、常量引用、负数和 `int64` 最小值；另检查溢出、除零和错型 3 个拒绝用例。
- 每个产物都检查 Mach-O 架构、dyld、系统库依赖、导入符号与 ad-hoc 签名；输出必须匹配，且预期结果不作为文本写入产物。
- 除零输入必须在生成前返回 `S-3024`。
