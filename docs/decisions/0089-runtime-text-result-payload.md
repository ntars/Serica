# D-0089 有界运行时文本结果载荷

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

在 D-0088 的编译期文本结果之上，接受直接运行时输入作为文本成功载荷：

```serica
变量 结果=成功（readText（））。
程序=【能力=array（『stdout』，『stdin』），输出=结果值（结果）】。
```

- 文本结果继续占四个原生槽：标签、容量/错误码、UTF-8 指针和内容字节长度。
- 结果变量第一次成功持有运行时文本时，通过登记的 `_mmap` 建立最大 16 MiB−1 字节内容容量的匿名映射；后续成功重赋值复用该映射。
- `readText（）` 在读取一个完整行后校验 UTF-8，保存时不含行结束符；成功结果根输出时追加一个规范化换行。
- 失败结果将标签改为失败并把错误码写入值槽，指针保留、长度归零，不产生 stdout。之后再次成功重赋值可复用已有映射。
- 动态文本结果复制暂不开放；`变量 副本=原结果` 由 `S-3023` 拒绝。拼接、切片或文本变量等其他运行时文本表达式也不能作为 `成功` 载荷。
- `是否失败`、`错误码`、失败传播和四槽栈预算沿用 D-0088；既有静态文本结果复制、重赋值和根输出保持不变。

## 理由

直接输入载荷把结果 ABI 从常量区指针扩展到拥有动态缓冲区的运行时值，同时避免在同一个子门中引入深复制、别名、捕获和跨函数所有权。固定容量映射让错误码写入值槽后不会污染真实容量，并使后续成功可安全复用缓冲区。

## 边界

- 动态文本结果仍是进程内、单线程、不可复制的四槽值；不提供所有权转移、共享引用、捕获或函数返回。
- 尚不支持 `成功（textConcat（…））`、`成功（substring（…））`、从文本变量或结果复制载荷。
- 结果文本尚未参与 `textLength`、拼接、切片或比较；只有 `结果值` 可作为成功文本根输出。
- 本决定不改变能力声明、Go 子集、平台符号白名单、源码/产物独立性和 P3b 删除 `bootstrap/` 的硬门。
