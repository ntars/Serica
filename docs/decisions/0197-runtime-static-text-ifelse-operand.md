# D-0197 运行时文本分支作为长度操作数

状态：已定案

## 背景

D-0196 只允许静态文本 `ifElse` 直接作为控制台根输出，同样的运行时条件分支进入 `textLength` 时仍被静态求值器拒绝。为继续闭合 P1b 的通用文本表达式边界，需要先把“条件选择已知文本描述符”抽成可复用操作数，而不是为每个消费者复制根输出分支。

## 决定

`ifElse（运行时条件，编译期文本，编译期文本）` 推导为运行时字符串后，可作为 `textLength` 的文本操作数。原生后端从同一个共享辅助函数取得真、假分支的独立 UTF-8 数据常量，按真实 ARM64 条件跳转选择缓冲区与字节长度，再由既有 Unicode 码位计数循环返回运行时整数；控制台根输出复用同一辅助函数，随后单独写出换行，避免读取常量边界之外的数据。

本次仍只接受两个分支均为编译期字符串。动态文本分支与跨函数文本恢复继续拒绝；文本 `ifElse` 进入比较和 `substring` 分别由 D-0198、D-0199 后续开放。

## 验收

- `make test-p1b-runtime` 通过新增两例：`textLength（ifElse（数值==1，『甲乙』，『丙』））` 输入 `1` 输出 `2`、输入 `2` 输出 `1`；D-0196 的根输出输入 `1`/`2` 仍分别精确输出 `甲\n`/`乙\n`。
- 运行时门通过 217 个 arm64 整数形态产物、168 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例；全量静态、模块、原生发射、doctor、license、ci-preflight 与 seed-audit 门保持通过。
- `make seed-audit` 报 10 个活动源码文件、12471/12500 行、归因完整；C-1 为 4890/12287 行（39.8%），未触发 AST 比例复核条件。

## 后果

运行时条件选择的已知文本现在既可直接输出，也可参与码位长度计算；文本描述符选择逻辑只有一份实现。P1b 完整阶段门仍未通过，本次不创建发布包，也不宣称语言完成。
