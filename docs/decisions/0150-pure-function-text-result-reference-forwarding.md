# D-0150 纯函数内的运行时文本结果引用转发

无效果纯函数可以把结果引用原样转发、在两个结果分支之间选择，或观察结果参数的状态；结果描述符不再因为经过有界 AST 展开而丢失。运行时文本成功载荷在转发后仍可动态输出，失败载荷仍保留错误码，未失败文本结果的状态查询返回 `0`。

## 根因

此前语义检查把“运行时文本结果作为纯函数实参”整体视为不支持的嵌套消费，并提前报 `S-3023`。这个判断基于错误假设：纯函数内联替换会丢失实参的结果标签、文本指针和字节长度。实际上参数引用在替换后仍指向原结果变量，既有结果描述符和运行时文本结果缓冲可以安全穿过纯函数边界；过宽拒绝反而阻断了合法的引用转发和状态查询。

## 修复

- 移除纯函数实参位置对运行时文本结果引用的提前 `S-3023` 拒绝，让既有结果描述符随引用替换进入函数体。
- 保留结果消费边界：直接对非引用结果表达式调用 `结果值`、`是否失败`、`错误码` 仍由 `S-3013` 拒绝。
- 不用特殊代码生成绕过纯函数展开，也不放宽效果函数、嵌套结果值消费或通用文本结果 ABI。
- 新增 4 个运行时产物：文本结果引用转发、文本成功/失败分支选择、失败结果引用转发，以及跨函数文本结果参数状态查询。

## 验收

macOS arm64 的 `make test-p1b-runtime` 通过 181 个 arm64 整数形态产物、1 个静态 UTF-8 文本产物、10 个静态文本结果产物、40 个运行时文本结果产物、11 个函数结果边界产物、309 个编译诊断和 118 个运行时拒绝样例。输入 `跨函数文本载荷` 时文本转发输出原载荷；分支开关 `0` 时选择失败路径、无 stdout 并以 `29` 退出；失败结果转发输出错误码 `37`；文本结果状态查询输出 `0` 并正常退出。

定向 `make test-p1b-static`、`make test-p1b-modules`、`make test-p1b-module-abi`、`make test-p1b-bind`、`make test-p1b-native-emit` 与 `make seed-audit` 通过。种子审计为 11897/12000 行、C-1 4838/11334（42.7%），归因完整。

## 边界

本决策只开放无效果纯函数中对已有运行时结果引用的转发、选择、失败码观察和文本状态查询。它不提供效果函数的运行时结果 ABI，不开放 `结果值（成功（readText（）））` 一类嵌套消费，不提供容器结果载荷、通用文本结果参数 ABI 或完整跨函数错误恢复。P1b 阶段门仍未通过。
