# D-0198 运行时文本分支作为比较操作数

状态：已定案

## 背景

D-0197 已把两个编译期文本分支的条件选择接入 `textLength`，但同一描述符进入 `equals`/`notEquals` 和文本排序时仍被语义白名单拒绝。比较路径已有左右描述符分阶段保存机制，可直接复用同一操作数发射器。

## 决定

`ifElse（运行时条件，编译期文本，编译期文本）` 现可进入 `equals`、`notEquals` 与 `<`/`<=`/`>`/`>=` 的任一文本操作数位置。原生后端用共享辅助函数按真实 ARM64 条件选择独立 UTF-8 常量，并由比较路径在求值右操作数前把左缓冲区与长度保存到临时栈，避免条件计算覆盖已选描述符。

动态文本分支，以及该选择进入容器、函数调用或跨函数恢复仍拒绝；作为 `substring` 源由 D-0199 后续开放。

## 验收

- `make test-p1b-runtime` 新增两例：`equals（ifElse（数值==1，『甲』，『乙』），『乙』）` 的结果经整数 `ifElse` 输出，输入 `1` 输出 `-1`、输入 `2` 输出 `42`。
- 运行时门通过 219 个 arm64 整数形态产物、168 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例；D-0197 的长度两例与 D-0196 的根输出两例继续通过。
- 全量源码、模块、原生发射、doctor、license、ci-preflight 与 seed-audit 门通过；活动种子 12474/12500 行、C-1 4890/12290（39.8%）。

## 后果

条件选择的已知文本现在可参与长度和相等比较，描述符选择与保存均复用既有实现。P1b 完整阶段门仍未通过，本轮不创建发布包，也不宣称语言完成。
