# D-0232 文本数组复制的调用约定根因修复

状态：已定案

## 背景

`array（文本变量）`、`arrayPush（数组，文本返回调用）` 与 `arraySet（数组，下标，文本返回调用）` 的最小复现构建失败，报“有界运行时切片需要 substring”。实际根因不在语法语义门：`emitRuntimeTextArrayCopy` 让通用文本操作数把描述符发射到 x21/x22，随后 UTF-8 校验和 `emitArrayMapCall` 会覆盖这些调用者保存寄存器；数组初始化/追加路径在调用前又依赖这些寄存器保存元素数和长度，导致复制循环读到被覆盖的值。此前 `arraySet` 因先把索引存入帧槽而侥幸通过。

## 决策

文本数组复制前把 x21/x22 描述符保存到当前帧槽；调用通用文本操作数和内存分配后从帧槽恢复，再执行逐字节复制。32 字节临时区在复制完成时平衡，不改变源程序语义、诊断边界或数组所有权模型。

## 验收

- `make test-p1b-runtime` 通过，新增 3 个真实执行用例：文本返回调用分别进入数组初始化、数组追加和数组更新，精确输出均为 `行简！\n`。
- 运行时成功文本输入从 188 增至 191，文本返回调用方存储产物从 22 增至 25，编译诊断 411 个、运行时拒绝 125 个保持不变。
- `make seed-audit` 通过：11 个活动源码文件、12877/13200 个掩码代码行、余量 323、归因完整。

## 后果

修复的是受支持的文本返回调用进入数组元素的边界，不开放通用容器结果载荷或任意文本嵌套。完整 P1b 阶段门及 P2b–P6b 仍未通过。
