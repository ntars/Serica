# D-0149 结果状态参数查询保留运行时函数 ABI

无效果块体函数只要通过 `是否失败`、`错误码` 或 `结果值` 观察参数，就必须保留语句形态和真实 ARM64 调用帧；结果状态参数按相邻标签/值双槽进入展平 ABI。`转发（甲，源）` 可同时接收普通整数和结果状态参数，在失败路径输出错误码组合，在成功路径输出成功载荷组合。程序根和普通表达式中的状态查询仍只接受结果变量引用，`结果值（成功（1））` 等非引用形态继续由 `S-3013` 拒绝。

## 根因

D-0146 已要求含结果状态查询的块体函数保留局部双槽语义，但观察判定把参数引用排除在外。仅观察参数的 `转发（源）` 因而重新进入表达式 lowering，绕过运行时结果参数 ABI；调用实参 `转发（5，内层（输入））` 被当作普通整数运算处理，最终在 `是否失败（源）` 条件处退化为不支持的整数比较。与此同时，参数分类仍把 `成功（参数）`/`失败（参数）` 当作结果 ABI 证据，与 D-0146 的边界不一致。

## 修复

- 任何 `是否失败`、`错误码`、`结果值` 查询都会保留所在无效果块体函数的语句形态，不再区分观察局部还是参数。
- `成功（参数）` 和 `失败（参数）` 不再独立决定参数 ABI；只有实际状态查询的局部或参数进入结果状态槽。
- 结果状态参数在寄存器计数和调用帧布局中继续占标签/值两个槽位，直接结果调用实参由既有结果操作数路径发射。
- 静态结果查询继续要求单参数引用，避免把根级临时结果表达式误开为可观察结果对象。

## 验收

macOS arm64 通过 `make stage0`、`make test-p0b-scope`、`make test-p1b-static`、`make test-p1b-modules`、`make test-p1b-runtime`、`make test-p1b-bind`、`make test-p1b-module-abi`、`make test-p1b-native-emit`、`make seed-audit`、`make license`、`make doctor` 与 `./tools/check-independence source`。

运行时门完整执行 177 个 arm64 整数形态产物、10 个静态文本结果产物、40 个运行时文本结果产物、7 个函数结果边界产物、311 个编译诊断及 118 个运行时拒绝样例。混合整数/结果参数转发输入 `3` 输出成功载荷 `9`，输入 `-1` 输出错误码组合 `36`；产物包含直接函数调用和返回。`examples/p1b-runtime-recursive-result.serica` 的 `S-3023` 回归恢复为 `check` 通过。种子审计为 11897/12000 行、C-1 4838/11334（42.7%），归因完整。

## 边界

本决策只闭合整数状态结果参数的块函数观察和混合转发，不提供文本或容器结果参数 ABI，不提供效果函数上的任意结果转发，也不改变 `结果值` 在失败时的无 stdout 传播语义。P1b 阶段门仍未通过。
