# D-0088 有界编译期文本结果载荷

状态：已定案（P1b 子门；不代表阶段门通过）

## 决定

在 D-0085 的双槽整数结果之上，增加一种带编译期文本成功载荷的有界结果：

- `成功（编译期文本）` 生成文本载荷结果；`失败（1..255）` 继续表示失败状态。
- 文本结果变量占用标签、值、文本指针和字节长度四个原生栈槽；整数结果继续占两个槽。
- `结果值（文本结果变量）` 只允许作为根输出表达式。成功时输出已校验的 UTF-8 文本和规范化换行；失败时保持零 stdout，并以错误码退出。
- 文本结果可复制和重赋值，也允许被失败结果替换。结果变量的成功载荷类型在声明后保持不变，禁止文本载荷与整数载荷互相改写。
- `是否失败` 和 `错误码` 对整数、文本结果使用相同状态布局和观察规则。

当前接受可由 `evaluateString` 静态求值的文本字面量、拼接、切片或条件表达式。`成功（readText（））` 等运行时文本载荷仍被拒绝，避免在本子门中同时引入结果持有动态缓冲区、别名和所有权规则。

## 理由

文本载荷验证结果 ABI 能从纯整数标签/值扩展到指针/长度，同时继续限制临时状态、失败传播和输出边界。先使用编译期文本，可以把 UTF-8 校验和数据驻留留给现有常量区；后续动态载荷再复用文本变量存储模型。

## 边界

> 后续状态：D-0089 已扩展直接 `成功（readText（））` 的运行时文本成功载荷；本节描述的编译期限制仅代表 D-0088 定案时边界。

- 尚不支持运行时文本成功载荷、动态文本结果缓冲区、文本结果参与切片/拼接/长度/比较，或结果作为函数运行时返回值。
- `结果值` 仍只接受结果变量引用；失败结果的载荷不得输出。
- 文本结果成功载荷只驻留于 Mach-O 常量区，输出时追加一个换行字节。
- 本决定不改变 `map.write`、函数 AST 展开、平台符号白名单、源码/产物独立性和 P3b 删除 `bootstrap/` 的要求。

- 文本成功结果被 `失败（9）` 替换后不产生 stdout，并以退出码 9 传播。
- `成功（readText（））`、文本/整数载荷互换、文本结果参与整数算术均由 `check` 与 `build` 拒绝。
- 125 个四槽文本结果变量达到 500 槽并可构建；126 个触发 `S-3040`。251 个双槽整数结果变量边界继续通过。
