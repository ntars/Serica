# D-0160 追加文件写入边界

状态：已验收（P1b 子门；不代表阶段门通过）

## 背景

D-0099 的 `writeFile` 每次创建或截断目标文件，适合生成完整产物，却不能在不重写既有内容的前提下追加日志、诊断或缓存。文件写入能力已经沿函数调用链和程序根传播，追加语义可以复用同一能力与路径边界，而不引入新的权限模型。

macOS arm64 的 `_open` 是可变参数接口。`O_CREAT` 的文件权限参数必须按该平台 ABI 放在调用栈上；只写入 `x2` 会创建权限位为零的文件，随后调用方无法读取或继续写入。

## 决定

- 新增内建函数 `appendFile（路径，文本）`。它以追加方式写入 UTF-8 文本，目标不存在时创建，已存在时保留原内容；返回本次实际写入的字节数。
- 路径与文本边界沿用 `writeFile`：路径可为静态非空文本或 `argumentText（下标）`，文本沿用已登记的运行时文本操作数。调用要求 `filesystem.write`，参数路径另要求 `args`。
- 原生后端按调用区分写入方式。`writeFile`/`writeByteArray` 继续导入并使用 `_creat`；`appendFile` 导入 `_open`，使用 `O_WRONLY|O_CREAT|O_APPEND`（macOS 数值 `521`）和权限 `0644`。
- 追加调用的权限参数放在调用栈，并在系统调用后恢复栈指针。写入循环、短写处理、关闭检查和失败前零 stdout 规则与 `writeFile` 共用。
- 同一程序同时包含读取和追加时复用读取路径已导入的 `_open`，仍只导入一次；只含覆盖写入时不得无谓引入 `_open`。

## 理由

日志追加是编译器、构建工具和诊断管线最直接的文件写入需求。先补一个明确的追加原语，可以验证创建、保留、字节计数、能力传播、路径复用和平台可变参数 ABI，同时避免提前设计开放模式、目录操作或通用文件句柄。

## 边界

- 只支持普通文件追加，不提供显式打开标志、文件句柄、偏移定位、截断、原子替换、文件锁、刷盘、权限控制、目录或元数据接口。
- 多个并发写入者只依赖操作系统的追加写入语义；本层不承诺跨调用事务、崩溃一致性或日志轮转。
- `appendFile` 不自动添加换行，也不解析内容。调用方须提供合法 UTF-8 文本；非法动态文本仍在系统调用前失败。
- 本决策扩展 D-0099 的写入方式，不改变其“`writeFile` 创建或截断”的既有语义，也不改变种子额度、系统符号登记、效果检查和 P3b 删除硬门。

## 验收

- `make test-p1b-runtime` 在 macOS arm64 实测已有文件 `开头` 追加 `尾` 后内容为 `开头尾` 并输出 `3`；缺失目标追加 `新` 后创建文件并输出 `3`。
- 参数文本动态路径追加同样实测输出 `3`，并保留既有内容；产物导入 `_open` 与 `_close`。
- 覆盖写入产物继续只要求 `_creat` 与 `_close`；读取后写入和参数路径写入产物按实际调用同时登记 `_open`、`_read`、`_creat`、映射与关闭符号。
- 缺少根 `filesystem.write` 的 `appendFile` 由 `S-4102` 拒绝。
- 全量源码门、词法/语法/绑定/模块门、原生发射门、`doctor`、许可、种子审计和源码独立性检查通过。运行时门当前为 202 个 arm64 整数形态产物、43 个运行时文本结果产物、27 个函数结果边界产物、317 个编译诊断和 118 个运行时拒绝样例；活动种子为 11999/12000 行，C-1 为 4850/11618（41.7%）。

## 后果

文件写入子门同时具备覆盖和追加两种语义，后续诊断输出和构建缓存可以不再重写完整文件。P1b 仍缺通用文件句柄、目录/元数据、进程 IO、通用结果/容器载荷和完整跨函数错误恢复，阶段门仍未通过。
