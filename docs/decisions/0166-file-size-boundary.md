# D-0166 文件大小元数据边界

## 背景

P1b 的文件边界已覆盖读取、写入、追加、删除、重命名、目录创建/删除和权限设置，但仍缺少对已有文件字节数的只读元数据查询。本决策在不引入通用文件句柄的前提下补上这个最小闭环。

## 决策

新增 `fileSize（路径）`，路径可为编译期静态文本或 `argumentText（整数下标）`；返回现有文件的字节数，失败时无 stdout 且以 `1` 退出。静态与动态路径均要求 `filesystem.read`，动态路径另要求 `args`。语义诊断码为 `S-3080`。macOS arm64 后端导入 `_open`、`_fstat`、`_close`，采用 O_RDONLY 打开、从 `stat` 缓冲读取 `st_size`、并在返回整数结果前关闭描述符；根因修复点是 `fstat` 必须使用独立缓冲地址、保留文件描述符并在输出前释放，且不能把 `st_size` 读入后立即被输出例程覆盖的寄存器。行简前端登记 `fileSize=45`，效果表映射到 `filesystem.read`，类型表补元数、路径类型和整数结果。

## 验证

完整源码门通过。`make test-p1b-runtime` 实测动态路径对 5 字节文件输出 `5`，缺失路径无输出退出；运行时门为 204 个 arm64 整数形态产物、43 个运行时文本结果产物、27 个函数结果边界产物、335 个编译诊断和 123 个运行时拒绝样例。模块效果门新增缺根能力与隐藏效果诊断，为 7 种能力、4 个正例图、22 个位置诊断、编译器自检；模块类型门新增 `S-3080` 位置诊断，为 29 个类型查询、27 个位置诊断、3 个原生参照产物、编译器自检。活动种子 11965/12000 行、C-1 4915/11807（41.6%）。P1b 阶段门仍未通过。
