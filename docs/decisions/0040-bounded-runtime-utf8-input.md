# D-0040 有界运行时 UTF-8 文本输入/输出

状态：已落地子门；不构成 P1b 阶段门通过。

## 决定

新增 `readText（）` 作为原生控制台运行时输入起点。当前只接受无参数调用，并且只允许直接出现在 `程序` 根绑定的输出表达式中。产物逐字节读取一行，最多缓冲换行符之前的 63 字节（CRLF 中的 CR 计入上限），接受 LF、CRLF 和 EOF 结束的行；输出前验证完整 UTF-8 标量编码，成功时写出文本并追加一个 LF。

非法续字节、过长编码、UTF-16 代理项、超出 U+10FFFF 的码点、截断序列和超长输入都在输出前拒绝，以非零状态退出且不产生部分 stdout。CRLF 被规范为 LF。

## 范围

此子门验证的是有界输入行到 stdout 的原生路径。它不提供可存储的运行时字符串值；`readText（）` 不能用于常量、变量初始化或一般表达式。动态字符串缓冲区、拼接/切片、文件/进程 IO 和结构化错误值/传播仍未实现。

## 验收

- `make test-p1b-runtime` 构建并执行 1 个运行时文本输入 ARM64 Mach-O，覆盖 10 个成功输入场景，包括 ASCII、中文、空行、LF/CRLF、EOF 结束、63 字节上限和 UTF-8 标量边界。
- 同一产物对孤立续字节、过长编码、代理项、超范围码点、截断序列和超过 63 字节等 9 个拒绝场景以非零退出，stdout 为空。
- 当前完整运行时子门实际执行 68 个整数 Mach-O、1 个静态 UTF-8 文本 Mach-O 和 1 个运行时 UTF-8 文本输入 Mach-O；通过 37 个编译诊断与 31 个运行时拒绝样例。
- 反汇编检查原生 `_read`/`_write`/`_exit` 路径、缓冲区字节读写与长度上界分支；产物平台、依赖、符号和签名检查通过。
- P1b 阶段门仍未通过：一般字符串运行时、动态容器、文件/进程 IO、错误值传播和行简编译器尚未实现。
