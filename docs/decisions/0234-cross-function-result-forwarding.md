# D-0234 直接跨函数返回结果调用的根因修复

状态：已定案

## 背景

最小复现：

```serica
函数 乙（数）【若（数<0）【返回 失败（9）。】。返回 成功（数）。】。
函数 甲（数）【返回 乙（数）。】。
变量 外=甲（3）。
程序=【能力=array（『stdout』），输出=结果值（外）】。
```

构建失败，报 `S-3015`，`实际：运行时整数`。`甲` 的块体只有 `返回 乙（数）。`，`乙` 已被登记为递归环外的块体结果函数并降级为普通函数；结果形态推断只查 `runtimeFunctions` 候选表，因此看不到 `乙` 是结果函数，`甲` 被判成整数函数，调用处的 `结果值` 被拒。

## 决策

`annotateRuntimeFunctionResults` 与 `blockFunctionReturnsResult` 接收完整函数表，而不是只看运行时候选表。块体函数返回一个“已标注为结果形态”的普通函数调用时，同样把当前函数标记为结果函数。仅运行时候选仍写入 `runtimeFunctions`，不改变调用帧、寄存器 ABI 或槽位布局。

## 验收

- `make test-p1b-runtime` 通过：274 个 arm64 整数形态产物 + 1 个静态 UTF-8 产物、31 个函数结果边界产物（含 2 个新增：成功转发与失败转发）、411 个编译诊断、125 个运行时拒绝样例。
- 最小复现输出 `3\n`、退出 0；失败路径 `甲（-1）` 退出 9 且无 stdout。
- `make verify` 通过；`git diff --check` 与 `check_seed_subset.py` 通过（12883/13200）。

## 后果

修复的是结果形态推断的可见范围，不开放容器/通用结果载荷、完整跨函数错误恢复或效果函数运行时 ABI。P1b 阶段门仍未通过。
