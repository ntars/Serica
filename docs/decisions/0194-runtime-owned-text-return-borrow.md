# D-0194 文本返回调用借用消费的 ABI 根因修复

状态：已定案

## 背景

函数可把已初始化文本局部的所有权通过 x1/x2/x3 交还给调用方；`textLength`、`equals` 与 `notEquals` 可以借用文本返回调用。既有成功用例只返回原参数描述符，未覆盖函数体先经 `textConcat` 生成新映射再返回的形态。运行时门复现两个缺陷：借用 `textLength` 的变形返回值时进程 SIGSEGV（139）；借用 `equals`/`notEquals` 的变形返回值时 `ifElse` 恒走真分支。

## 决定

保留语义边界：文本返回调用仍只能直接输出、存入受支持文本变量、进入成功载荷，或作为 `textLength`/`equals`/`notEquals` 的借用参数；不得借此开放任意嵌套表达式、容器逃逸或通用载荷。

代码生成按根因修复三处 ABI 问题：

1. owned 返回描述符按 `x1=buffer`、`x2=byte length`、`x3=capacity` 保存；调用参数在 `bl` 前和返回描述符在 `bl` 后均先落到临时栈，避免调用参数生成覆盖已保存描述符；unmap 后从临时栈恢复目标寄存器。
2. owned 文本相等/不等比较不再提前返回空 false 补丁，而是与既有文本比较共用真实长度与逐字节比较逻辑；比较失败路径仍由调用方正常跳转。
3. `textLength` 的 owned 分支先保存调用参数与返回描述符，unmap 后恢复长度/缓冲区，再计算 UTF-8 码位数；结果寄存器 `x24` 不再被释放调用破坏。

文本返回借用参与比较时，比较操作数另保留一级 512 字节 scratch；帧预算相应增加一级，避免 owned 返回保存区与既有操作数 scratch 重叠。

## 验收

- `tools/test_p1b_runtime.py` 新增三组：函数体 `textConcat` 后返回的文本分别进入 `textLength`、`equals`、`notEquals`，期望 `3`、`1`、`1`；借用比较采用整数 `ifElse` 分支，绕开仍受限的 S-3042 字符串分支。
- 反汇编断言只适用于直接文本返回存储产物；借用消费产物改由实际执行结果和退出码证明，不再误套“调用后三周期内保存 x1”形态断言。
- `make test-p1b-runtime` 通过 213 个 arm64 整数形态产物、19 个文本返回调用方存储产物、168 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例。
- 全量 P0b/P1b 源码门、doctor、license、ci-preflight 与 seed-audit 通过；活动种子 12421/12500 行，C-1 4887/12237（39.9%）。P1b 完整阶段门仍未通过。

## 后果

变形后的 owned 文本返回不再因描述符顺序或调用寄存器覆盖而崩溃或误判，调用方借用语义与先存储再消费的结果一致。该修复不扩展语义边界，也不证明通用结果载荷、容器逃逸或完整跨函数错误恢复；这些仍按路线图后续阶段推进。
