# D-0131 行简静态控制台原生发射

首个行简发射路径复用模块绑定、入口能力检查和静态求值。前端的 `native-data` 模式接受只有 `能力` 与 `输出` 字段的控制台入口，要求实际效果为 stdout、顶层无运行时语句且输出可静态求为整数、布尔或 UTF-8 文本。整数按有符号十进制编码，布尔编码为 `1` 或 `0`，输出末尾追加 LF。运行时求值和窗口入口目前以 `S-3080` 拒绝。

`compiler/emit-console.serica` 写出 ARM64 指令、Mach-O 段和节、入口、重定位绑定及符号表。生成的程序经 `_write` 循环处理短写，经 `_exit` 返回退出状态，系统调用库为 libSystem。`__TEXT` 的上限为 1 MiB，段按 16 KiB 对齐。系统 `codesign` 在映像写出后执行 ad hoc 签名。

原始字节 IO 由有限的种子桥 `writeByteArray（路径，运行时整数数组）` 提供。它复用 `filesystem.write`、静态或参数文本路径和文件短写循环，先在匿名映射中校验并打包 0–255 的元素，再打开目标文件。写完关闭描述符并释放映射。桥随 P3b 的种子删除。

`tools/build-serica-native` 在目标目录内隔离暂存，校验前端与发射器的返回长度，验签成功才替换目标。工具本身由 stage0 构建。消费 ABI 描述来生成动态控制流、函数调用和运行时槽位留待下一子门。P1b 总门继续推进。

## 验收

```sh
env GO=/Users/ntars/.local/go1.27.4/bin/go make test-p1b-native-emit
```

macOS arm64 实测 9 个签名运行产物、8 个 stage0 参照、72,801 字节多页输出和 8 个拒绝场景。检查严格签名、dyld 布局、段权限、系统导入和 ARM64 指令，覆盖同路径重建逐字节一致、失败保留旧产物及二进制字节写入。原始字节超过 255 或小于 0 时，在打开目标前退出。种子审计通过，活动种子为 10347/12000 行，C-1 为 6634/9896（67.0%）。
