# D-0228 进程命令执行与退出状态规范化

状态：已定案

## 背景

P1b 的进程 IO 缺口需要先让控制台程序执行外部命令并观察退出状态。此前效果位只覆盖八种能力；加入 `process` 后，效果需求与出处表仍按每个所有者八个槽位写入，导致根能力缺失时无法产生 `S-4102`，效果函数也无法稳定传播第九位能力。

## 决策

- 新增 `runCommand（命令）`，命令只接受静态文本或 `argumentText（整数下标）`，通过 `/bin/sh -c` 执行。
- 子进程继承当前 stdin、stdout 与 stderr；成功和失败都由同一表达式返回整数状态。
- 正常退出返回低 8 位状态 `0..255`；被信号终止返回 `128 + signal`，并只保留有符号状态低 8 位参与计算。
- 空命令、内嵌 NUL、非法参数下标、缺少 `process` 根能力、隐藏效果和错误元数都在写出输出前拒绝。
- 根程序及每层调用链必须显式声明 `process`。效果出处表按每个所有者九个槽位计算，并遍历九位，修复第九位能力丢失。

## 验证

- `make test-p1b-runtime` 覆盖静态命令 `exit 7`、动态命令 `exit 9`、真实文件副作用、`kill -TERM $$` 返回 `143`、空动态命令失败及全部诊断边界。
- `make test-p1b-module-effect`、`make test-p1b-module-type` 与 `make test-p1b-module-const` 覆盖 `process` 位、函数传播、类型查询和静态求值。
- `/bin/sh -c` 与 `_system` 导入进入原生产物白名单；P1b 阶段门仍未通过。

## 后果

进程执行已可用于受控的效果函数和根程序，但 stdout/stderr 捕获、argv 数组、管道、超时和通用进程句柄仍未开放。种子实现行数增加只用于已验证功能，Go 子集、依赖白名单、逐行归因、独立性、许可和 P3b 删除门不变。
