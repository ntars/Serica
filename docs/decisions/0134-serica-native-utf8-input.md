# D-0134 行简原生 UTF-8 输入与字节访问

行简将 `readText（）` 发射为直接的 ARM64 控制台读取例程。文本槽保存映射指针、有效字节数和容量字节数。文本变量初始映射为 64 字节，按需加倍至 16 MiB，并为输出的 LF 预留一个字节。重新读取同一变量可复用既有映射。直接输入表达式独立占用一个临时文本槽，保留 63 字节的直接输入边界。函数帧和根程序按各自的清理路径释放映射。

读取在 LF 或 EOF 结束，按现有语义去掉末尾 CR，并在发布文本前验证完整 UTF-8。验证器拒绝超长序列、截断、代理区和超出 U+10FFFF 的编码。原始字节保持原样。根输出处理短写，并在原内容后写入 LF。

`textLength` 计算 Unicode 标量数，`textByteLength` 读取有效字节数，`textByteAt` 在读取前检查从零开始的有符号索引。可静态求值的文本长度和字节访问可折叠到动态整数表达式。由不同输入表达式取得的临时描述符互相独立，可在另一段文本的字节下标求值期间存活。

原生载荷增加 `T` 和 `U`，分别表示存在文本输入及文本、标量数组同时存在。行简发射器据此生成 UTF-8 例程、映射和系统导入。本文本路径覆盖 stdin、stdout、读取式重赋值及只读字节操作。文本字面量寻址、通用拷贝、文本借用和返回、文本数组及文件 IO 保留后续阶段卡。

## 验收

```sh
env GO=/Users/ntars/.local/go1.27.4/bin/go make test-p1b-native-emit
```

macOS arm64 实测签名和原生导入、补充平面字符与组合字符的原始字节、CRLF 和 EOF、跨页增长、16 MiB−1 字节内容上限、超限无 stdout、只读字节边界、多变量隔离、重新读取及同路径逐字节重建。矩阵另运行独立的临时描述符产物，验证不同输入在同一表达式中的稳定性。编译拒绝覆盖缺少能力、静态负字节下标和暂未开放的运行时文本比较。

UTF-8 验证器另以 Python 严格解码为独立参照，检查全部 256 种单字节输入和 256 组确定性生成的字节序列。
