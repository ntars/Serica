# D-0030：静态可证整数变量运算子门

> D-0031 后续扩展此子集，加入有符号余数与移位；当前验收见 [D-0031](0031-integer-remainder-and-shifts.md)。

> 后续演进：D-0034 允许运行时输入值参与算术、位运算和移位，并在 ARM64 产物中检查边界；失败以非零退出报告，不提供结构化错误值或传播。

## 决策

扩展 `程序=【输出=...】` 的整数变量表达式。已声明变量可参与一元负号、加减乘除、`bitAnd`、`bitOr` 和 `bitXor`。原生 ARM64 后端必须从变量栈槽加载操作数并执行对应运算指令，不能把编译期结果直接写成输出常量。

语义检查按程序语句顺序维护变量的当前整数值。无输入或控制流时，编译器可证明各变量值并拒绝有符号 64 位溢出与除零，再生成实际运行运算。变量更新后，后续表达式使用更新值。D-0034 后，运行时值路径由 ARM64 溢出/除零/移位检查保护；错误值、恢复/传播及控制流语义仍待实现。

## 边界

- 只支持有符号 64 位整数。变量字符串、动态存储、通用 IO、条件/循环及函数作用域仍未实现。
- 当前 `程序` 根绑定之前的变量语句仍受 D-0029 的声明顺序、名称和 502 槽上限约束；模块继续只导入静态常量。
- 产物继续由仓内代码直接生成 macOS arm64 Mach-O，使用已有系统依赖白名单；不调用外部编译器、汇编器、链接器，不引入第三方实现或 Go 产品运行时。
- 这只是 P1b 原生整数子门扩展，不构成完整语言运行时或 P1b 阶段出口。临时种子继续受 D-0026 的行数、Go 子集、归因、许可和 P3b 删除约束。

## 验收

- `make test-p1b-runtime` 实际运行 17 个整数 Mach-O 和 1 个 UTF-8 文本 Mach-O，并检查 Mach-O 架构、dyld、系统依赖、导入符号和签名。
- 反汇编检查变量栈槽的 `str`/`ldr`，并确认变量加减乘除和位运算指令；正例覆盖表达式、赋值后的再次读取、静态模块常量初始化及 502 槽边界。
- 11 个拒绝用例覆盖静态溢出、除零、类型/名称/顺序错误、错误根类型和 503 槽超限。
- 本决策命令只证明静态可证值的原生执行；数据相关整数运算与失败退出由 D-0034 验收。动态字符串/容器、通用 IO、结构化错误传播和完整 P1b 仍未实现。
