# D-0023：P1b 文件模块导入语义

> 当前实现状态：stage0 已通过静态模块闭包子门。该加载器属于 D-0026 临时自举桥；行简实现接管前，不代表 P1b 阶段门通过。

## 决策

为 P1b 规定基于文件的模块导入：`导入 『相对路径.serica』。` 只能出现在文件开头；导入文件只含导入和顶层 `常量`，根文件最后有唯一 `窗口` 或 `程序` 绑定。被导入文件不允许声明程序根绑定。

路径相对当前导入文件，使用 `/` 分隔并以 `.serica` 结尾；每段只允许 ASCII 字母、数字、点、下划线和连字符，不展开环境变量或 `~`。解析后的目标必须留在入口文件所在项目目录内，路径中的符号链接不跟随。拒绝绝对路径和越界路径。ASCII 路径让跨平台文件名规范化与排序保持稳定；模块源码中的标识符仍使用中文。模块只能导出顶层常量，不提供别名、命名空间、私有项或动态加载。

依赖先于导入方解析；同一文件经不同路径导入只解析一次。模块依赖必须无环。模块常量按文件内声明顺序求值，可引用本文件此前声明和依赖模块导出的常量。不同文件导出同名常量时报告冲突；根文件也不能遮蔽导入的名称。模块合并使用单一全局名称空间。

为保持诊断和产物稳定，导入路径按规范化后的 `/` 路径字节序排序后遍历；诊断位置以入口目录为基准的项目相对路径表示。此排序不改变单个文件内的声明顺序。

## 取舍与差异

表层接近 Rust 等语言的源文件模块组织方式；差异是这里用中文 `导入` 加显式路径字面量直接导入文件，暂不增加 `use` 路径树、别名或命名空间。这样先建立编译器需要的文件读取、依赖图、名称合并和确定性顺序，避免把包管理与模块解析混在一起。模块系统属于语言理念，不以与其他语言不同为目标。

不选择源码文本拼接，因为它会使模块边界、诊断位置和同名来源难以追踪；不选择动态加载，因为 P1b 编译器需要静态闭包、可重复构建和早期错误检查；暂不引入命名空间/别名，因为它会扩大第一版语法及名称解析规则。

## 诊断与边界

- `S-4001`：非法模块路径（绝对路径、非 `.serica`、符号链接或解析后越出项目根）。
- `S-4002`：模块文件不存在、不可读或不是有效 UTF-8。
- `S-4003`：模块依赖环；报告按稳定遍历顺序遇到的回边。
- `S-4004`：被导入文件声明 `窗口` 根绑定。
- `S-4005`：来自不同文件的同名导出，含根文件遮蔽导入名称。

不在本决策范围内：运行时加载、包下载器、版本约束、模块别名、私有可见性、函数和类型导出，以及大小写折叠名称规则。D-0023 只冻结模块语言语义。D-0026 允许临时 Go 自举桥；最终模块实现仍须由 Serica 接管，并随 `bootstrap/` 在 P3b 删除。

## 验收

规范输入位于 `examples/p1b-modules.serica` 与 `examples/modules/`，诊断输入位于 `examples/diagnostics/p1b-module-*.serica`。`make test-p1b-modules` 检查模块闭包、路径边界、诊断来源位置、依赖顺序稳定性，以及 arm64 Mach-O 的 dyld、系统依赖、符号和签名；其中运行时加载、包管理与行简实现仍未验收。
