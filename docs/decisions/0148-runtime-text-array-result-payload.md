# D-0148 文本数组元素作为运行时结果载荷

`成功（arrayGet（文本数组，运行时索引））` 现可构造运行时文本结果。数组元素从已登记的动态文本数组读取，复制进结果自有的匿名映射缓冲；索引仍在执行时检查边界，负索引或超出长度时无 stdout 并以退出码 1 终止。

## 根因

语义层此前只把直接输入、参数文本和受支持的拼接/切片识别为运行时文本载荷，`arrayGet` 元素虽已有原生文本读取路径，却没有进入结果载荷类型判定和原生发射分派。原生分派中复制循环又因为 `emitRuntimeTextOperand` 使用相邻指针/长度寄存器约定而传反了 `x3`/`x5`，导致复制源成为错误指针并触发段错误。

## 修复

- 结果载荷类型检查与运行时文本值判定加入动态文本数组 `arrayGet`，仍要求数组变量为引用且索引为运行时整数。
- 顶层文本变量/数组元素发射分派把 `arrayGet` 成功载荷路由到深复制路径。
- 结果深复制先由 `emitRuntimeTextOperand` 取元素长度 `x3` 与指针 `x5`，再写入结果槽的独立映射、长度与终止字节。
- 索引边界沿用既有 `arrayGet` 原生检查，错误路径与运行时文本结果失败路径统一为无 stdout 非零退出。

## 边界

- 仅闭合顶层动态文本数组元素作为运行时文本成功载荷；不闭合任意容器/通用结果载荷、结果值作为数组元素载荷、跨函数文本结果 ABI、容器逃逸或完整错误恢复。
- 不改变普通文本数组读取、切片和写回的既有边界。

## 验收

macOS arm64 的 `make test-p1b-runtime` 新增四个场景：索引 `0` 输出 `甲`、索引 `1` 输出 `乙`、索引 `2` 与 `-1` 均无 stdout 并以退出码 `1` 结束。运行时门完整结果为 177 个 arm64 整数形态产物、10 个静态文本结果产物、40 个运行时文本结果产物、311 个编译诊断及 118 个运行时拒绝样例。当前 `make seed-audit` 为 11897 行、C-1 4838/11334（42.7%），归因完整。P1b 阶段门仍未通过。
