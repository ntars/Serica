# D-0169 原子文件替换边界

## 背景

P1b 已有覆盖写入、追加、删除、重命名、目录、权限、大小和存在性查询，但发布缓存与安装器需要把临时文件一次性替换为目标路径，避免读者看到截断或半写入内容。现有 `renameFile` 已具备 POSIX  rename 的原子替换语义，但缺少面向语言使用者的独立名称与前端登记。

## 决策

新增 `replaceFile（源路径，目标路径）`，两条路径均可为编译期文本或 `argumentText（下标）`；成功返回 `0`，失败无 stdout 退出非零。macOS arm64 后端复用 `_rename`，由既有路径字节编码器分别编码源与目标路径，要求 `filesystem.write`，参数路径另要求 `args`，诊断码为 `S-3082`。行简前端登记 `replaceFile=47`，效果表映射到 `filesystem.write`，类型表登记两参数文本、整数结果，绑定和类型边界由模块前端与 stage0 分别验证。

## 根因与边界

首轮前端登记曾把 `47` 放入 `filesystem.read` 效果分支，且类型表把 `47` 纳入通用 `>=35` 元数错误与参数顺序使用错误，导致已有 `exists` 诊断回归。修正后 `45`/`46` 保持只读能力、`47` 归写能力，`47` 的元数错误在通用分支之前独立返回 `S-3082`，路径类型校验按调用实参数组位置取实参而非借用函数形参列表。

本决策只提供同一卷内 POSIX rename 语义的原子替换：目标已存在时原子覆盖，源缺失或无权限时失败；不提供跨卷复制、临时目录策略、目录替换、符号链接策略、文件句柄、目录遍历或进程 IO。P1b 阶段门仍未通过。

## 验证

`make test-p1b-runtime` 新增独立参数文本路径替换产物：源文件被移除、目标文件内容等于源内容、stdout 为 `0` 且产物导入限定 `_rename`；源缺失时非零退出且无 stdout。模块效果门新增缺根能力与隐藏效果诊断，为 7 种能力、4 个正例图、26 个位置诊断、编译器自检；模块类型门保持 29 个类型查询、28 个位置诊断、3 个原生参照产物、编译器自检。全量源码门、doctor、许可、种子审计和独立性检查通过。活动种子 12000/12000 行、C-1 4927/11842（41.6%）。
