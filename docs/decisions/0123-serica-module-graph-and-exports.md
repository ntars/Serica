# D-0123 行简模块依赖闭包与导出表

行简前端在同一进程中对实际源码做深度优先遍历。每个文件使用 D-0122 的受限读取，词法、语法和导入规范化沿用同一套实现。规范化的项目内路径作为文件身份，依赖的边按其所在文件的规范化导入键排序。共享依赖只加载一次，重复语句各自保留来源节点。遇到正在处理的模块时，在发起导入的位置报告 `S-4003`。

每个模块按首次发现分配编号，入口编号为 `1`。完成顺序保持依赖先于使用方。节点表跨文件追加，文件记录保存所属语法树根，正文快照按文件编号保存。顶层常量和函数分属两个名称空间，导出表按完成顺序和文件内声明顺序登记。导出保留文件、声明、名称节点和函数形参数。重名诊断定位到后登记的声明。

## 查询

命令行依序指定入口文件名、`module-graph`、项目目录。入口文件名是一个规范化 ASCII `.serica` 文件名，查找以项目目录为边界。标准输入读取一个有符号 64 位查询整数。

| 查询 | 结果 |
|---|---|
| `-1`、`-2`、`-3` | 分别返回文件、导入边和导出数量 |
| `(i << 32) + n` | 读取完成顺序中的第 `i` 个文件。字段 `0–4` 依次为编号、路径长度、AST 根、直接边数、正文长度，字段 `5` 起为路径字节 |
| `(1 << 60) + (i << 32) + n` | 按文件发现顺序及文件内规范化顺序读取边。字段 `0–3` 依次为源文件编号、目标文件编号、导入字节起点、导入 AST 节点 |
| `(2 << 60) + n` | 读取全图节点表第 `n` 槽 |
| `(3 << 60) + (i << 32) + n` | 读取第 `i` 条导出。字段 `0–4` 依次为文件编号、声明类别、声明节点、名称节点、形参数量。常量用 `-1` 表示无形参 |
| `(4 << 60) + ((id-1) << 32) + n` | 读取文件 `id` 正文中的第 `n` 个字节 |

越界查询返回 `0`。语法、路径拼写、导入环和导出重名使用 `-((id << 37) + (字节偏移 << 13) + S 码数字部分)`。系统读取错误沿用 D-0122 的状态 `41` 和 `42`，其退出位置尚待关联发起导入的节点。跨文件引用与实参检查由后续名称绑定消费导出表。

D-0124 扩展了本接口，读取失败和跨文件绑定的当前行为见 [D-0124](0124-cross-file-binding-and-located-module-errors.md)。

## 验收

macOS arm64 的 `make test-p1b-module-graph` 验证 5 节点菱形图、72 层导入、编译器自身 7 文件闭包、10 条与 stage0 对齐的位置诊断和三种读取失败。菱形图逐项核对边、源文件字节、导出名称、函数形参和各文件的 AST 根。两个等价导入排列的 stage0 参照产物均输出 `50`，Mach-O 字节一致。

```sh
env GO=/Users/ntars/.local/go1.27.4/bin/go make stage0 test-p0b-scope test-p1b-static test-p1b-modules test-p1b-runtime test-p1b-scan test-p1b-lex test-p1b-parse test-p1b-program test-p1b-bind test-p1b-import-paths test-p1b-module-read test-p1b-module-graph doctor license seed-audit
./tools/check-independence source
build/punct-scan compiler/parse-expression.serica compiler/binding-names.serica
```

上述命令均退出 0。活动 Go 种子保持 10191/12000 行，C-1 为 6565/9746（67.4%）。P1b 继续推进。
