# D-0025：严格执行种子冻结与全阶段门

> 历史裁定。项目所有者于 2026-11-20 明确手册是设计方向、实现路线可灵活调整；D-0026 取代本决策中禁止临时 P1b 种子桥的部分。自举、独立性、许可和 P3b 删除种子等核心目标继续有效。

## 决策

按项目所有者建立的全项目目标，严格遵守《行简 Serica 开发手册》对种子的约束。§3.7 的“只修 bug”与 §4.6 的边界不能被任务内例外覆盖。D-0024 被本决策取代；不得继续把 P1b 语言功能加入 Go 种子，也不得将已有 Go P1b 扩展计作符合手册的阶段验收。

## 当前偏差和阶段判定

此前工作树加入的字符串/整数常量扩展、数组和静态模块 P1b 语义已从活动 `bootstrap/` 撤出；当前活动 parser/semantic 仅处理 P0b 窗口记录子集。历史 P1b 规范和样例保留为目标资料，不表示功能已实现。严格阶段清单仍将 P1b 标为未通过，并要求在进入 P2b 前建立不违反种子冻结的自举路径。此决策不修改或解释性改写外部开发手册。

手册现有约束下的具体技术缺口：P1b 要求字符串、位运算、容器、IO、错误处理和模块系统足以表达编译器；当前 stage0 只有受限窗口记录值语法，且不能编译行简编译器源代码。仓库尚无能够同时满足这两个要求的实现路线与验收证据。不得用伪造产物、外部编译器、转译/透传或进一步扩大 Go 种子来填补。

## 验收与后续

- `docs/roadmap/p0b-p6b.md` 是 P0b–P6b 状态及硬门的主清单；未实现的目标命令明确标记为待建。
- 每阶段只按手册阶段顺序推进；P1b 硬门通过前不得开始 P2b。
- 种子边界、许可、依赖、五层独立性和自举复现证据均须通过对应可复跑检查；D-0024 历史内容仅用于追溯，不是当前豁免。
- 只有 P0b–P6b 各自适用的硬门都以实际证据通过，且满足手册 1.0 定义后，才可将项目目标标记完成。P6b 仍不属于 1.0 定义，也不得挤占 P0b–P5b 主线。
