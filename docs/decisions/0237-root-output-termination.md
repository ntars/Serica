# D-0237 根整数与文本输出终止指令的发射顺序

状态：已定案

## 背景

根整数输出与静态 UTF-8 文本输出的后端发射代码中，成功路径的 `_exit(0)` 和失败块曾写在 `//` 注释之后，或者与注释同处一行却没有进入实际发射的指令序列。Go 代码仍能编译，但生成的可执行程序在写出文本后没有可靠终止，或在失败补丁跳转后落入未定义字节序列；最小复现表现为 `udf`、异常退出或输出后不返回。动态环境变量名称读取曾把这类尾块问题误表现为“输出空文本”或死循环，排查时发现参数帧、寄存器保存和 UTF-8 校验本身已正确，根因在尾块实际未发射。

## 决策

- 根整数直接输出成功后必须实际发射 `mov x0,#0` 与 `_exit(0)`，随后发射共享失败块。
- 静态 UTF-8 文本直接输出成功后必须实际发射 `mov x0,#0` 与 `_exit(0)`，随后发射共享失败块。
- 终止指令与失败块必须出现在独立源码行，不能放在 `//` 注释之后；注释不得吞掉控制流指令。
- 所有失败补丁统一指向 `_exit(1)`，失败路径不得产生部分 stdout。
- 动态环境变量名称读取继续复用既有参数帧、调用约定和 UTF-8 校验隔离规则，不再为尾块问题另设寄存器约定。

## 验收

- `make test-p1b-runtime` 通过：289 个 arm64 整数形态产物、43 个运行时文本结果产物、46 个函数结果边界产物，成功样例退出 0。
- `RESULT_FAILURE_CASES` 中 6 个失败样例退出指定错误码且无 stdout。
- `make verify` 完整门通过；`python3 tools/check_decisions.py` 与 `python3 -m json.tool DECISIONS.json` 通过。

## 后果

该决策修复输出终止指令和失败块的实际发射顺序，不改变 Serica 源码语义。它不等于通用文本、容器、完整效果函数 ABI 或跨函数错误恢复已经完成，P1b 阶段门仍未通过。
