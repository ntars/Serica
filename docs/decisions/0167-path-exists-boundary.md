# D-0167 路径存在性查询边界

## 背景

P1b 已有文件大小查询，但 `fileSize` 对缺失路径以非零状态退出，无法在程序中判断路径是否存在。目录生命周期与包管理、缓存和发布验收需要非抛出的只读存在性判断。

## 决策

新增 `exists（路径）`，路径可为编译期静态文本或 `argumentText（整数下标）`。路径存在时输出 `1`，缺失时输出 `0`；两者均要求 `filesystem.read`，参数路径另要求 `args`，诊断码为 `S-3081`。macOS arm64 后端导入 `_open`、`_fstat`、`_close`：先以 `O_RDONLY` 打开；打开失败即返回 `0`，成功后再做 `fstat` 并关闭描述符，成功后返回 `1`。这里刻意不调用 `___error`：除缺失以外的打开、`fstat` 或关闭错误仍按既有运行时失败约定无 stdout 退出 `1`，避免把权限和 I/O 故障误判为不存在。行简前端登记 `exists=46`，效果表映射到 `filesystem.read`，类型表补元数、路径类型和整数结果。

## 根因与边界

首轮实现曾把返回值分支写成 `b.eq`，导致缺失路径被误报为存在；修正为以 `b.ge` 跳转成功路径，未跳转时返回 `0`。同时恢复被全局替换误改的 `argumentText` 长度扫描补丁，保证本次增量不破坏既有参数文本路径。

本决策不提供目录遍历、路径规范化、符号链接策略、原子替换、通用文件句柄或进程 IO；只对当前进程可解析的路径给出存在性判断，目录同样视为存在。P1b 阶段门仍未通过。

## 验证

`make test-p1b-runtime` 新增一个产物，实测文件、目录和缺失路径三种场景，产物导入严格限定为 `_open`/`_fstat`/`_close`；运行时门当前为 204 个 arm64 整数形态产物、43 个运行时文本结果产物、27 个函数结果边界产物、335 个编译诊断和 123 个运行时拒绝样例。模块效果门新增缺根能力与隐藏效果诊断，为 7 种能力、4 个正例图、24 个位置诊断、编译器自检；模块类型门新增 `S-3081` 位置诊断，为 29 个类型查询、28 个位置诊断、3 个原生参照产物、编译器自检。活动种子 11997/12000 行、C-1 4923/11839（41.6%）。
