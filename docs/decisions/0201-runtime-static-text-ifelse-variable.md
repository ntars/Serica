# D-0201 运行时文本分支进入有界文本变量

状态：已定案

## 背景

条件选择的已知文本已可直接输出并进入长度、比较、切片和拼接消费者，但普通文本变量仍把该表达式归类为整数，导致 `变量 文本=ifElse（运行时条件，『甲』，『乙』）` 不能分配文本缓冲，也无法在后续赋值中更新。

## 决定

`ifElse（运行时条件，编译期文本，编译期文本）` 现可作为普通文本变量的初始化值和赋值来源。类型阶段登记该表达式为运行时文本；槽位分类为其分配固定 64 字节文本缓冲、长度和容量；发射阶段通过共享选择器取得所选分支的独立 UTF-8 缓冲区与字节长度，再经既有容量检查、复制和终止字节写入落到变量自己的缓冲区。

变量仍拥有自己的有界缓冲区，不借用两个静态分支或共享选择器的栈描述符。初始化与重赋值都走同一复制路径，因此原分支常量不会被改写。动态文本分支仍拒绝；容器、无效果函数和成功载荷消费由 D-0202 后续审计并开放。

## 验收

- `make test-p1b-runtime` 新增四个实际执行用例：条件文本变量输入 `1`/`2` 输出 `甲乙`/`丙丁`；先读取文本再赋值为条件文本并拼接后，输入 `x`/`y` 输出 `甲乙尾`/`丙丁尾`。
- 新增产物同时验证 `_mmap`/`_munmap` 导入、条件文本复制及变量文本存储；原 227 个整数形态运行产物及全部文本、结果、模块和拒绝样例继续通过。
- 运行时门现为 231 个 arm64 整数形态产物、168 个成功文本输入、349 个编译诊断和 123 个运行时拒绝样例。
- 全量源码、模块、原生发射、doctor、license、ci-preflight 与 seed-audit 在提交前复跑；活动种子与 C-1 归因按实测同步。
- D-0202 后续审计确认该文本分类可安全进入文本数组、无效果函数实参/局部和成功载荷，并为这些路径新增正式回归；当前精确数字由 D-0202 记录。

## 后果

条件选择的已知文本现在可先物化为普通有界文本变量，再进入既定文本消费者；D-0202 进一步把已验证消费边界扩展到文本数组、无效果函数和成功载荷。这仍未提供动态文本分支、通用容器结果载荷、容器逃逸或跨函数结果恢复。P1b 完整阶段门仍未通过，本轮不创建发布包，也不宣称语言完成。
