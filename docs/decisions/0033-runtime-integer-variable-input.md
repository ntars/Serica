# D-0033：运行时整数写入变量

## 决策

允许 `readInteger（）` 作为整数变量的初始化值或赋值表达式。生成的 macOS arm64 Mach-O 使用现有有界解析器读取 stdin，将结果写入变量栈槽；后续整数变量引用从槽中读取并可直接输出。多次输入复用栈帧末尾的 64 字节缓冲区。

语义分析沿语句顺序区分编译期已知整数与运行时整数。运行时整数可复制到变量并可被直接输出；一元负号、二元算术、位函数和移位仍拒绝运行时操作数（`S-3042`），直到实现数据相关溢出、除零和移位错误路径。输入解析失败继续以非零退出结束，不产生部分 stdout。

## 边界

- 仍只接受单行有符号十进制整数；输入最多 64 字节，错误通过进程退出码报告，不提供错误值/传播。
- 变量只能在程序顶层声明，赋值只能作用于此前声明的整数变量；没有条件、循环或函数作用域。
- 每个原生栈帧最多容纳 502 个整数变量；读取缓冲区与现有整数输出缓冲区共用 64 字节空间。
- 运行时整数不能参加任何算术/位运算、移位、数组构造或索引；动态字符串、容器、通用文件/进程 IO 未实现。
- P1b 总门仍未通过。Go 种子仍受 D-0026 的行数、子集、逐行归因、许可和 P3b 删除要求约束。

## 验收

- `make test-p1b-runtime` 实际执行输入初始化变量、输入赋值变量和同一产物重复读取的 ARM64 Mach-O，检查 `_read`/`_write`/`_exit`、栈槽加载/存储、反汇编、dyld、系统依赖和签名。
- 输入验收覆盖 CRLF、重复读取、完整 int64 上界和既有解析正反例；变量初始化及赋值结果通过 stdout 和退出码断言；赋值时的非法输入同样须非零退出且无输出。
- 20 个编译期诊断包含运行时变量算术和取负拒绝；当前共 9 个运行时非法输入检查，均以非零退出且不输出。
