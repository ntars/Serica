# D-0235 受限整数数组结果载荷的调用帧 ABI

状态：已定案

## 背景

`成功（array（…））` 只能作为普通数组变量初始化使用。把它作为运行时结果载荷时，构建期就失败或运行期崩溃，最小复现：

```serica
函数 内核（数）【返回 成功（array（数，数+1））。】。
函数 代理（数）【返回 内核（数）。】。
变量 输入=readInteger（）。
变量 结果=代理（输入）。
程序=【能力=array（『stdout』，『stdin』），输出=arrayLength（结果值（结果））】。
```

根因有四处，叠加在一起：

1. 结果槽位只有 tag/value 两个槽，数组载荷没有地方保存 `data/length` 描述符。
2. 块体（表达式体）运行时函数不分配帧临时区，数组字面量暂存写到帧外，触发 `SIGBUS`。
3. `emitResultValueRegisters` 对非文本载荷无条件清零 `x2/x3`，把 `ifElse` 与 `成功（array（…））` 分支刚算出的描述符覆盖掉。
4. 结果函数调用只把 `x2/x3` 当文本描述符转发，数组返回值在调用方被丢弃；`statementsUseRuntimeArray` 也不识别“数组结果函数调用”，导致 `_mmap/_munmap` 未导入，出现“系统导入槽超出范围：-1”。

## 决策

在受限范围内把整数数组实现为一等结果载荷，复用文本结果已有的四槽描述符布局：

- `resultSlot` 增加 `array`；数组载荷结果占 4 槽，`pointer` 为映射基址，`length` 为元素数，`value` 为映射字节容量。
- 调用帧 ABI：`x0=tag`、`x1=capacity`、`x2=data`、`x3=length`，与文本结果同形；整数载荷仍只用 `x0/x1`。
- 表达式体结果函数返回数组载荷时，在帧尾分配 32 字节临时描述符区，先把字面量写进该区再按寄存器返回；所有权转移给调用方。
- 结果声明处先清零 `pointer/length/value`，避免栈残留被当作旧映射释放；赋值时由 `emitRuntimeResultArrayPayload` 负责释放旧映射。
- `arrayLength（结果值（结果））` 与 `arrayGet（结果值（结果），索引）` 直接读描述符，`arrayGet` 带失败传播与边界检查。
- `statementsUseRuntimeArray` 识别数组载荷结果声明与数组结果函数调用，确保 `_mmap/_munmap` 被导入。
- 只在整数元素上生效；文本数组、嵌套容器、容器参数、通用容器结果载荷仍不支持。

## 验收

- `make test-p1b-runtime` 通过：281 个 arm64 整数形态产物、38 个函数结果边界产物（新增 7 例：直接字面量、长度、函数字面量、跨函数转发取索引、跨函数转发取长度、失败边界、失败边界的成功路径）、411 个编译诊断、125 个运行时拒绝样例。
- 最小复现输出 `2\n` 退出 0；失败路径 `代理（-1）` 退出 12 且无 stdout。
- 新增回归用例同时验证 `arrayLength` 与 `arrayGet` 两条读取路径。
- `python3 tools/check_seed_subset.py` 通过：11 个活动源码文件、13020/13200 掩码行、余量 180，C-1 5022/13048（38.5%）。

## 后果

这是一条受限 ABI，不是通用容器结果载荷：不支持文本数组载荷、容器参数、嵌套容器、结果逃逸或通用键值类型。P1b 仍未通过，需继续完成通用文本/容器结果载荷、完整效果函数 ABI 与跨函数恢复。
