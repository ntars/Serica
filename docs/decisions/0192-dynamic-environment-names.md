# D-0192 动态环境变量名称与文本描述符安全桥

状态：已定案

## 背景

D-0185 曾把 `readEnvironment` 的名称限制为编译期静态文本，以避免未经证明的 C 字符串桥。该限制阻断了参数驱动的环境查询，也阻断了 `textLength`、相等比较和成功载荷边界对这类结果的继续组合。后端复用 `_getenv` 时还必须保证名称以 NUL 结尾、拒绝空名称和非法字节，并在失败与成功路径上保持 ARM64 栈平衡。

## 决策

- `readEnvironment` 接受 `argumentText（整数下标）`，并接受由该表达式初始化或赋值的文本变量；任意文本拼接、静态运行时文本和未登记的文本表达式仍拒绝。
- 动态名称最多 4094 个 UTF-8 字节。原生后端把名称复制到 4 KiB、16 字节对齐的栈暂存区并以 NUL 终止；空名称、内嵌 NUL 和 `=` 在调用 `_getenv` 前失败。
- `_getenv` 缺失变量返回空文本。返回值按 NUL 扫描、执行完整 UTF-8 校验后，以缓冲区/长度描述符返回；成功、缺失和失败路径都恢复临时栈。
- 直接参数文本名称只导入 `_getenv`；先存入文本变量的名称额外使用 `_mmap`/`_munmap`，并在输出写调用前后保存描述符寄存器。
- 动态名称结果可进入直接输出、`textLength` 和 `equals` 等既有文本消费者；完整通用文本表达式、环境变量写入和其他进程 IO 不在本决定范围内。

## 验证

- `make test-p1b-runtime` 新增直接与存储参数文本名称的中文 UTF-8 输出、`textLength` 和相等比较四个成功产物。
- 非法参数下标继续以 `S-3069` 拒绝；缺少 `args`、未知能力、隐藏效果和任意文本名称仍由既有诊断覆盖。
- 存储名称产物额外验证 `_mmap`/`_munmap` 导入白名单，直接名称产物验证 `_getenv` 白名单。
- 全量 P0b/P1b 源码门、运行时门、doctor、许可、CI 前置检查和种子审计通过。
- 活动种子经逐行归因后为 12419 行；为容纳本次必要实现，机器预算由 12260 行调整为 12500 行。归因完整，C-1 为 4887/12235（39.9%）。Go 子集、依赖、许可、源码/产物独立性和 P3b 删除门不变。

## 后果

参数名字符串与存储参数文本变量都能安全调用 `readEnvironment`，并可在既有文本消费者中组合。P1b 仍未通过：通用文本/容器结果载荷、完整效果函数 ABI、跨函数错误恢复、通用 IO 和行简自编编译器仍待实现。
