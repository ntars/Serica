# D-0146 块体函数局部结果的观察与恢复

无效果块体函数可先用返回结果的函数调用初始化局部变量，再通过 `是否失败`、`错误码` 和 `结果值` 观察该局部，并把恢复后的整数、原失败状态或观察到的结果作为本函数结果返回。运行时函数还可把另一函数的调用结果作为直接实参接收：若调用实参本身是结果表达式，参数也被归入结果状态 ABI，调用帧同时保存标签与载荷，函数可在两条返回路径上原样转发，调用方再恢复为成功载荷或错误码。`examples/p1b-function-result-recovery.serica` 在真实 ARM64 产物上验证两条路径：输入 `5` 输出成功载荷 `6`，输入 `-1` 把错误码恢复为整数载荷，stdout 输出 `31` 并正常退出。

## 根因

原实现把无循环、无文本参数的块体函数一律送入表达式 lowering。该路径把局部引用替换为初始化表达式，导致 `中途` 丢失结果标签/值两槽语义，`是否失败（中途）` 与 `结果值（中途）` 被错误降级；随后结果参数分类又把 `成功（参数）`、`失败（参数）` 当作参数应当使用结果 ABI 的证据，使 `累计（数值，结果）` 的普通整数累积参数被误判。文本参数返回诊断先于语句验证执行，也掩盖了更接近根因的局部赋值诊断。

## 修复

- 含结果状态查询或返回运行时函数调用的无效果块体函数保留语句形态，不进入表达式 lowering。
- 局部类型预扫描只把实际被 `是否失败`、`错误码` 或 `结果值` 观察的局部登记为运行时结果；`成功（参数）`、`失败（参数）` 本身不再决定参数类型。
- 运行时结果参数仍以相邻标签/值槽传入调用帧；普通整数引用进入 `成功` 时按整数载荷构造，结果槽引用进入 `成功` 时直接转发标签和值。
- 句末 `若/否` 两分支均返回时视为完整返回路径；文本参数不可写，文本参数直接返回仍由 S-3068 拒绝。
- 文本参数返回诊断移到语句验证之后，使更具体的结果局部和赋值诊断优先出现。

## 续：结果跨函数返回

若块体函数需要把观察到的结果继续交给调用方，可在 `若/否` 的失败分支返回 `失败（错误码（局部））`，在成功路径直接返回该结果局部。运行时函数验证允许位于 `若/否` 分支中的结果返回，并按标签/载荷双寄存器发射；调用方再用 `结果值` 观察时，成功输出内层载荷，失败按原错误码无 stdout 退出。该边界只覆盖整数载荷结果，不改变静态/文本结果 ABI。

## 续：直接结果表达式作为函数实参

递归或运行时函数参数原先只在实参语法节点为 `引用` 时才被标为结果状态参数，因此 `转发（内层（输入））` 这类直接结果调用被按普通整数参数发射，调用方错误地观察到成功标签。修复让调用点先用常量/载荷类型判定实参的结果形态，再要求语法节点为结果引用或可识别的结果操作数形状；代码生成对这类操作数直接取标签/载荷寄存器。运行时门新增两条 macOS arm64 正例：输入 `5` 输出 `6`，输入 `-1` 输出错误码 `31` 并正常退出。文本载荷的直接调用实参仍由静态类型检查以 S-3023 拒绝，避免把四槽文本描述符误当整数状态转发。同一份 `内层/转发` 程序在不依赖测试脚本自动补能力时，也以 `程序=【能力=array（『stdout』，『stdin』），输出=...】` 显式声明能力并通过 `serica check`，证明它沿真实源码路径可验证。该路径仍限于整数载荷，文本/容器载荷和效果函数帧未加入 ABI。

## 边界

- 本决策只覆盖整数状态载荷、同函数内局部观察与恢复、既有递归结果参数转发，以及直接结果调用实参的状态转发。
- 通用文本/容器结果载荷、跨函数完整错误恢复、效果函数运行时 ABI、完整 IO 与通用容器仍未实现。
- `compiler/module-path.serica` 的 `返回 止+0` 与原生模块链夹具的 `变量 序=起+0` 仍是参数类型推断尚未完整的局部类型证据；尝试按比较运算符推断会把 `textByteAt` 的字节下标误判为文本，已撤回不安全改动。P1b 完整阶段仍须以显式参数类型或等价语义覆盖所有调用形态。
