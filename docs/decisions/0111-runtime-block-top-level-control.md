# D-0111 运行时块函数顶层条件与有序局部声明

状态：已验收（P1b 子门；不代表阶段门通过）

## 决定

无效果整数块体运行时函数的顶层语句列表现在可按执行顺序混合整数局部声明、赋值、`若`/`否`、`凡` 和最终整数返回。顶层 `若` 在原生代码中按当前参数和已初始化局部状态求值，分支返回与循环内返回共用函数收束点；未命中分支继续执行后续语句。

本子门同时放开局部整数的声明位置：

- 局部整数可在首个循环之后声明，初始化仅在该语句实际到达时执行一次。
- 局部整数可在顶层分支内声明，并按块作用域限制在该分支；分支结束后名称不可见，不能逃避到后续循环或函数返回。
- 函数内全部局部名称仍在入口预分配栈槽，名称不得与参数、常量或同函数内其他局部重名，函数参数与局部合计仍限 502 个 64 位槽。
- 顶层 `跳出`/`继续` 仍由 `S-3068` 拒绝；它们只能绑定 `凡` 循环。非布尔条件、非整数局部值、未知赋值、返回后不可达语句和隐藏 IO 效果继续拒绝。
- 顶层条件中的返回只结束当前函数；条件未命中时后续语句可达。函数顶层仍须以整数回落返回结束。
- 文本/容器局部、文本/容器返回值、运行时文本参数、效果函数帧、通用结果载荷和跨函数错误恢复仍不在该 ABI 内。

## 理由

守卫条件、循环后的汇总和按运行时条件选择循环起点是编译器与运行时常见形状。如果只有循环体内允许条件或局部声明，调用者必须拆分函数或复制状态准备逻辑。让顶层语句按源码顺序执行可缩小该缺口，同时复用现有条件补丁、块作用域验证和统一返回收束机制，不需要改变整数调用约定。

## 验收

- `examples/p1b-runtime-top-level-if.serica` 对输入 `-1` 执行顶层守卫并返回 `0`；对 `4` 跳过守卫，执行 `1+2+3+4` 并返回 `10`。
- 原生门新增顶层守卫命中、守卫未命中和循环后局部初始化 3 个基础场景；另以分支内局部选择循环起点，对输入 `5` 返回 `6`。
- `check`/`build` 新增非布尔顶层条件、顶层分支内 `跳出`、分支局部作用域逃逸和顶层条件隐藏输入 4 类反例，分别返回 `S-3068`、`S-3068`、`S-3022`、`S-4106`；旧“循环后局部尚不支持”限制被移除。
- `make test-p1b-runtime` 通过 152 个 arm64 整数形态，其中 19 个运行时整数块循环函数产物、258 个编译诊断和 116 个运行时拒绝样例。
- `python3 tools/check_seed_subset.py` 与 `make seed-audit` 通过 8937/12000 行及 C-1 5894/8562（68.8%）。
- P1b 阶段门仍未通过；运行时文本/容器参数与返回值、通用结果载荷、效果函数调用帧及更完整跨函数错误恢复留待后续子门。
