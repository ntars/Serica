# D-0231 语义规范与 101 例一致性语料

状态：已定案

## 背景

续开发手册 M4 要求 `docs/spec/semantics.md` 覆盖作用域、类型、效果和常量求值，一致性套件不少于 100 例，且 10 个坏程序符合四段诊断格式。此前只有 44 例一致性语料、21 条反例中的格式断言只校验 S-code，语义规范文件缺失。

## 决策

新建 `docs/spec/semantics.md`，用可测试规则描述类型、作用域、求值、效果、常量和运行时边界。把一致性语料扩充到 101 例（80 正例、21 反例），覆盖算术优先级、比较与短路逻辑、文本与数组内建、函数与控制流、结果载荷、运行时输入/参数能力，以及能力缺失、重复名称、未声明变量、越界、类型不匹配和非法错误码。`tools/check_conformance.py` 对每个反例同时校验非零退出、S-code 与 `file:line:col（显示第 N 格）/期望/实际/建议` 四段格式。

## 验收

- `make conformance` 通过并输出 `101 例（80 个正例、21 个反例）`。
- 全部 21 个反例满足诊断格式正则，不再只断言 S-code。
- 新增正例均由 `build/stage0/serica` 实际构建运行，精确 stdout 与退出码与语料一致；反例均由 `check` 实际诊断。
- `docs/spec/semantics.md` 中规则均标注可机器验证的对应用例或 Make 目标。

## 后果

M4 的数量门槛和诊断格式检查具备机器证据；语义规范仍是约束稿，未经人工签字冻结。新规则只增不减，未来改变规则必须同步更新本文、语料和决策索引。P1b–P6b 阶段门仍未完成。
