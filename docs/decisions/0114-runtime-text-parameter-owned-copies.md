# D-0114 运行时文本参数的函数帧内独立副本

状态：已验收（P1b 子门；不代表阶段门通过）

## 决定

无效果整数块体运行时函数可把只读 UTF-8 文本参数复制到函数顶层的文本局部变量。副本拥有独立的匿名映射、有效字节长度和容量槽；函数返回前统一解除仍存活的局部映射。函数仍只返回 `x0` 整数，文本局部只能通过 `textLength`、文本比较、拼接和切片进入整数控制流。

本子门接受两类 durable copy 来源：

- 直接引用另一个文本参数或已初始化文本局部变量。
- 受支持的 `textConcat` 或 `substring` 结果。

文本局部按源码到达顺序初始化。顶层局部可按同类型来源重新赋值；旧映射在扩容或替换时解除。参数本身仍是调用方拥有的借用指针，不得赋值、返回或写入容器。

## 边界

- 每个文本参数占指针和长度两个状态槽；每个文本局部另占指针、长度和容量三个状态槽，容量用于几何扩容。
- 文本局部先获得 64 字节初始映射，内容增长时扩容到足以容纳内容及行终止字节，硬上限为 16 MiB 内容预算。
- 循环和分支内部的文本局部、文本局部逃逸到容器、文本返回及运行时文本结果载荷仍拒绝。
- 清理使用系统 `_munmap`。统一收束点先保存整数返回值，再清理全部已初始化文本局部，最后恢复帧并执行 `ret`。
- 无效 UTF-8 在参数进入函数前保持非零退出且零 stdout、零 stderr。

## 验收

- 新增直接参数复制、局部再拼接、复制后比较、替换来源、`substring` 副本、补充平面文本及整数回归场景。
- 反汇编要求真实 `bl`/`ret`、动态文本参数装载和 `_munmap`；产物实际执行结果必须匹配。
- 文本返回、循环或分支内文本局部、读取隐藏输入和容器逃逸负例继续稳定拒绝。
- `make test-p1b-runtime` 已通过 174 个 ARM64 整数形态、22 个文本参数比较/长度/本地副本桥产物、144 个成功文本输入、286 个编译诊断和 117 个运行时拒绝样例。
- `make seed-audit` 已通过 9531/12000 行，C-1 为 6029/9131（66.0%）；完整硬门复跑结果同步记录于路线图和开发手册。

## 回滚

若清理、别名或扩容语义无法在同一子门内保持可验证的正确性，撤回文本局部分类和后端槽位，恢复 D-0113 仅借用文本参数的边界；保留测试作为后续决策证据。
