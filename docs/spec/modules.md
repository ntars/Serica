# 模块与导入（P1b）

模块规范决策见 [D-0023](../decisions/0023-p1b-module-import-semantics.md)。本文件定义文件模块语法和名称解析，不表示当前 stage0 已实现它。

## 文件结构

```serica
导入 『modules/text.serica』。
导入 『modules/greeting.serica』。

常量 标题=『模块示例』。
窗口=【标题=标题，文本=问候】。
```

零个或多个 `导入` 必须位于文件最前；其后可有零个或多个 `常量`，根文件以唯一 `窗口` 根绑定结束。模块文件遵守相同的导入与常量顺序，但不得包含窗口根绑定。导入声明和常量声明都以 `。` 结束。

导入路径必须是普通字符串中的静态路径字面量，不允许转义或表达式。路径使用 `/`，每段只允许 ASCII 字母、数字、点、下划线和连字符，并以 `.serica` 结尾；允许 `.` 和 `..` 片段，但解析后的目标必须位于入口文件所在目录树内。绝对路径、反斜杠、环境变量、波浪号展开、符号链接和越界路径均无效。路径按大小写敏感的字面名称解析。限制路径为 ASCII 是为避免不同文件系统的 Unicode 文件名规范化差异；源码标识符仍可用中文。

## 加载和名称解析

每个导入文件只导出其顶层常量。文件依赖图必须无环，依赖模块先于导入方求值；同一解析文件从多个依赖路径可达时只处理一次。每个文件内仍按声明顺序求值，因此常量只可引用同文件中更早声明的名称。

导入闭包和根文件共享一个平面名称空间。来自两个不同文件的同名常量是错误；根文件不能重定义导入闭包的名称。共享同一个传递依赖不会造成重复导出，因为文件身份只计一次。未导入文件中的常量不可见。

对每个文件的直接导入路径按规范化的 `/` 路径字节序排序后遍历。该顺序用于确定依赖诊断与冲突报告；每个文件内的声明顺序不变。编译器对相同源码树必须生成字节一致的产物，不受导入行排列影响。

## 诊断

| 诊断码 | 条件 |
|---|---|
| `S-4001` | 路径不合法、不是 `.serica`、包含符号链接或越出项目根 |
| `S-4002` | 文件缺失、不可读或不是 UTF-8 |
| `S-4003` | 发现导入环 |
| `S-4004` | 被导入模块含 `窗口` 根绑定 |
| `S-4005` | 不同模块导出同名常量，或根常量遮蔽导入名称 |

## 阶段限制

导入是编译期静态依赖；P1b 不包含动态加载、包管理、版本解析、模块别名、命名空间、私有可见性或函数导出。本文定义未来模块语义；当前 stage0 不支持导入语法，也没有活动实现。原 Go 模块实现已撤出，以遵守手册 §3.7/§4.6。未来行简实现须按 D-0023 与全阶段清单的验收门验证。
