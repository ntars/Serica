# 诊断格式规范（当前实现约束）

`serica lex/check/build` 的源码诊断必须稳定输出以下四段：

```text
<相对路径>:<行>:<列>（显示第 <显示列> 格）：错误 S-<四位编号>：
  期望：<受支持形态>
  实际：<遇到的形态>
  建议：<可执行修正>
```

行与列从 1 开始，按 Unicode 标量计数；显示列按终端显示宽度计数，因此全角标点后的列号与显示列号不同。词法诊断在组合字符等入口错误中可定位到 `0:0`，因为错误发生在文件字节规范化层而非某个 token；其余诊断须定位到具体 token。`conformance/` 的 21 个反例均由 `tools/check_conformance.py` 同时断言非零退出、`S-` 编号和完整四段格式；路径、行列、原因与建议缺失即为失败。

运行时错误必须在 stdout 之前以非零退出结束，不能输出半行结果。能力、类型、作用域、效果、模块路径、ABI 与所有权边界各有独立编号段；不复用编号表达不同原因。诊断文本可随版本改进，但 S-code 与判定边界在 1.0 后受兼容策略约束。

当前诊断规范由 `make conformance` 的 21 个反例和既有 `tools/test_p1b_*` 位置断言覆盖；这是实现快照，不表示 M4 已冻结规范。
