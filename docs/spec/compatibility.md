# 行简兼容策略（开发者预览）

本文件定义开发者预览期之后的兼容承诺。当前 `VERSION` 中的 `dev.N` 表示开发者预览包号，不是语义版本；在 1.0 发布前，语言、编译器与发布包都可以在没有弃用期的情况下变更，但每次破坏性变更必须写入 `CHANGELOG.md`，并至少新增一个正例和一个反例进入 `conformance/`。

## 版本层次

| 层 | 载体 | 含义 |
|---|---|---|
| 语言版本 | `VERSION` 的 `MAJOR.MINOR` | 用户程序依赖的语法、类型与运行时语义 |
| 编译器版本 | `VERSION` 全串 | 实现版本；同一语言版本可有多个编译器修订 |
| 种子预算版本 | `DECISIONS.json` 中的预算决策号 | `bootstrap/` 上限及计数口径 |

1.0 之后编译器版本遵循语义化版本；开发者预览期可调整全部字段，但必须说明兼容影响。

## 变更级别（1.0 起）

| 变更 | 版本位 | 要求 |
|---|---|---|
| 新增语法或标准库能力，既有合法程序行为不变 | MINOR | 新特征有正例、反例和决策记录 |
| 改变既有合法程序的行为（包括 bug 修复导致行为变化） | MAJOR | `CHANGELOG.md` 单列“行为变化”，给出迁移说明 |
| 删除语法、内建函数或能力 | MAJOR | 至少一个 MINOR 周期弃用警告，并提供迁移路径 |
| 诊断措辞、文档、内部实现且行为不变 | PATCH | 不改变程序输出与退出码 |

“修复 bug 导致行为变化”按 MAJOR 处理，因为用户可能已经依赖旧行为；如果必须作为 PATCH 发布，需要在发布说明中明确列出受影响形态并给出 conformance 反例。

## 弃用流程

1. 在 `docs/spec/compatibility.md` 增加条目：被弃用形态、替代形态、移除版本、迁移示例。
2. 编译器对该形态发出 warning；warning 不影响退出码，至少保留一个 MINOR。
3. 提供迁移说明或自动迁移工具；1.0 前不承诺自动迁移。
4. 移除时在 `CHANGELOG.md` 的 Removed 段写明，并把旧形态加入 `conformance/` 的反例。

### 当前登记条目

| 被弃用形态 | 替代形态 | 移除版本 | 迁移命令 | 状态 |
|---|---|---|---|---|
| `判等（…）`（历史文档拼写） | `equals（…）` | 1.0.0 | `tools/migrate --write legacy-equality <源码>` | 未移除；`tools/migrate --check` 可检查残留 |

迁移工具只替换作为调用名的 `判等`，不触碰字符串、注释或标识符。该条目证明 S6.1 的弃用登记与 S6.2 的一类自动迁移已落地；编译器 warning 与 1.0 后的正式移除仍属未来工作，不宣称 S6 全部完成。

## 平台与发布

当前唯一可运行、可验证的平台是 macOS arm64；其他平台见 `docs/spec/platform-matrix.md`，只描述事实，不承诺时间表。发布包的校验和、SBOM、ad-hoc 签名与安装脚本属于供应链证据，不代表 Apple 公证或跨机验证；相关限制见 `RELEASE.md` 与 `ACCEPTANCE.md`。

## 状态

该文件是 1.0 之前的策略草案，不表示 1.0 已发布，也不解除 P1b–P6b 的未完成项。
